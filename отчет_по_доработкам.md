# Отчёт по доработке проекта «Диантус» (dianthus-opt.ru)

## 1. Оценка проекта «как есть»

**Проект хороший — заметно выше типичного «самописного» магазина.** Это не учебная
поделка, а рабочая B2B-система с продуманной архитектурой:

**Сильные стороны (что уже было сделано правильно):**
- Чёткое разделение: роутеры / сервисы / модели / шаблоны. Конфигурация через `.env` с валидацией.
- Серверные сессии в Redis (а не в cookie) — корзина оптового клиента не «вылетает».
- Защита от фиксации сессии (новый id при входе/выходе).
- CSRF-токены + проверка Origin на всех POST-запросах.
- Пароли в bcrypt, прогрессивная блокировка входа после неудачных попыток.
- Оформление заказа атомарно: `SELECT … FOR UPDATE` с единым порядком блокировок (защита от deadlock и гонок), сверка цены с БД на момент покупки.
- Интеграция с 1С: Basic Auth со сравнением в постоянное время + HMAC-подпись webhook'ов.
- Docker-комплект с изолированной внутренней сетью, nginx с rate-limit зонами, авто-миграции, healthcheck, тесты (было 24).

**Что было слабо (и теперь исправлено):** XSS в подсказках поиска, слабый CSP,
выключенный TrustedHost, «мёртвая» настройка 2FA, пустой аудит-лог, open redirect
через Referer, формульные инъекции в Excel, гонка при переводе предзаказа в корзину.

**Почему у вас «ничего не изменилось» на сайте:** на VPS сейчас крутится **старая
версия кода** — репозиторий на GitHub заметно новее того, что развёрнуто
(проверено: `/health` отдаёт 404, `/register` отдаёт 405 — так ведёт себя старая
версия). Репозиторий обновлялся, а сервер — нет. Инструкция по обновлению — в разделе 4.

## 2. Что исправлено (по пунктам, с файлами)

### Безопасность

1. **Хранимый XSS в подсказках поиска** — `app/templates/catalog.html`.
   Подсказки строились через `innerHTML` из названий товаров: название со скриптом
   (из 1С или админки) исполнялось бы у каждого посетителя. Теперь подсказки
   строятся через `textContent`, а URL валидируется по шаблону `/product/<id>`.

2. **CSP с одноразовым nonce** — `app/middleware.py`, `app/templating.py`,
   `base.html`, `landing.html`, `supply_form.html`, `catalog.html`, `admin.html`.
   Раньше `script-src 'unsafe-inline'` позволял исполнить любой внедрённый скрипт.
   Теперь на каждый запрос генерируется nonce, и браузер выполняет только подписанные
   им скрипты. Добавлены заголовки `Cross-Origin-Opener-Policy` и
   `Cross-Origin-Resource-Policy`.

3. **TrustedHostMiddleware включён в prod** — `app/main.py`.
   Был импортирован, но не подключён: заголовок Host не проверялся. Теперь список
   разрешённых хостов строится из `APP_URL`.

4. **Open redirect через Referer** — `app/routers/cart.py`.
   Редирект «назад» брал Referer как есть: POST-запрос мог вернуть пользователя
   на фишинговый сайт. Теперь хост Referer сверяется с хостом сайта и `APP_URL`.

5. **Формульные инъекции в Excel** — `app/services/excel_service.py`.
   Ячейка, начинающаяся с `= + - @`, исполняется Excel как формула. Все экспорты
   (заказы, клиенты) теперь экранируют такие значения префиксом `'`.

6. **Rate limit на оформление заказа** — `app/routers/cart.py`: не более 10 заказов
   в минуту на пользователя (спам заказами/складом).

7. **2FA доведена до рабочего состояния** — `app/routers/profile.py`,
   `app/services/totp.py`, `app/templates/profile.html`, `app/auth.py`.
   Проверка кода при входе была, а включить 2FA было негде. Теперь в профиле админа —
   полный цикл: генерация секрета, QR-код, подтверждение первым кодом, отключение
   по паролю. Дополнительно: неудачные TOTP-коды теперь идут в прогрессивную
   блокировку входа (перебор 6-значного кода невозможен).

8. **Гонка при переводе предзаказа в корзину** — `app/services/preorder_service.py`.
   Остаток читался без блокировки: два одновременных перевода могли списать один
   остаток дважды. Добавлен `SELECT … FOR UPDATE` + откат с понятной ошибкой.

9. **Аудит действий админов заработал** — `app/routers/admin.py`.
   Таблица и функция `log_action` существовали, но нигде не вызывались. Теперь
   пишутся 13 действий: выдача/снятие админки, одобрение/отклонение заявок, смена
   скидки (старое→новое), смена статуса заказа, создание/правка/удаление товаров
   и поставок, разгрузка поставки.

### Мелкие баги и качество кода

10. Дубль `import time` — `app/security.py`.
11. Мёртвая функция `_back` — `app/routers/catalog.py`.
12. Опечатка в предупреждении конфига — `app/config.py`.
13. Лимит загрузки изображений вынесен в настройку `MAX_UPLOAD_SIZE` —
    `app/config.py`, `app/services/upload_service.py` (можно менять через `.env`).
14. В `requirements.txt` добавлен `qrcode` (QR для настройки 2FA).
15. **Админка**: списки клиентов и товаров ограничены 500 записями (раньше грузилась
    вся база — при тысячах товаров из 1С страница бы «умерла»), добавлен живой поиск
    по вкладкам «Клиенты» и «Товары» — `app/routers/admin.py`, `app/templates/admin.html`.
16. **README.md** переписан под реальный стек (старый описывал несуществующий
    React-фронтенд). **REVIEW.md** дополнен вторым раундом доработок.

### Тесты

17. Новый файл `tests/test_security_extras.py` — 6 тестов: CSP nonce в заголовке и
    шаблоне, security-заголовки, блокировка open redirect, санитизация Excel,
    полный цикл включения 2FA, запрет 2FA-эндпоинтов обычному пользователю.
    **Итог: 30 тестов, все проходят** (24 старых + 6 новых).

## 3. Как обновить сайт на сервере (пошагово)

Вариант А — через GitHub (рекомендую, у вас всё для этого есть):

```bash
# 1. На вашем компьютере: распакуйте архив поверх клонированного репозитория
#    (или замените файлы), затем:
git add -A
git commit -m "Security hardening round 2: XSS, CSP nonce, 2FA, audit, fixes"
git push origin main

# 2. На VPS:
ssh ваш_пользователь@ваш_сервер
cd /путь/к/dianthus
scripts/update.sh        # git pull + пересборка + перезапуск контейнеров
```

Вариант Б — без Git, напрямую архивом:

```bash
# 1. Залейте dianthus_improved.zip на сервер (scp/sftp)
scp dianthus_improved.zip ваш_пользователь@ваш_сервер:~

# 2. На VPS:
cd /путь/к/dianthus
docker compose down
cd .. && cp -r dianthus dianthus_backup_$(date +%F)   # бэкап старого кода
unzip -o ~/dianthus_improved.zip                       # распакуется папка dianthus/
cd dianthus
# 3. Убедитесь, что ваш .env на месте (в архиве его нет — он не публикуется):
ls -la .env
# 4. Пересборка и запуск:
docker compose up -d --build
```

Проверка после деплоя:

```bash
curl -I https://dianthus-opt.ru/health      # 200 OK (на старой версии было 404)
curl -sI https://dianthus-opt.ru/login | grep -i content-security-policy
# В заголовке CSP должно быть: script-src 'self' 'nonce-...'
```

База данных и загруженные картинки (`static/uploads`) не затрагиваются: миграции
выполняются автоматически при старте приложения, а Postgres и uploads живут
в docker-томах. На всякий случай перед обновлением сделайте `scripts/backup.sh`.

**Обязательно после обновления:** зайдите в профиль администратора → блок
«Двухфакторная аутентификация» → включите 2FA (приложение Яндекс.Ключ /
Google Authenticator). Это самая дешёвая и эффективная защита админки.

## 4. Что имеет смысл сделать дальше (по убыванию пользы)

1. **Alembic-миграции** вместо самописного `auto_migrate` — для переименований и
   смены типов колонок.
2. **Очередь для писем** (RQ/Celery поверх имеющегося Redis) — сейчас письма
   отправляются из процесса приложения.
3. **`pg_trgm`** для поиска по каталогу, когда товаров станут десятки тысяч.
4. **Внешний мониторинг доступности** (UptimeRobot/Better Stack) + Sentry-алерты.
5. **Атомарная корзина в Redis/БД** — сейчас два одновременных клика «в корзину»
   одного пользователя могут перезаписать друг друга.
