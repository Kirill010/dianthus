# Памятка программисту 1С: обмен 1С ↔ сайт «Диантус»

Сайт: **{{URL}}** · Адрес обмена: **{{URL}}/api/1c/** · Ключ доступа вам передаст владелец (отдельно от этой памятки).

Все форматы одним файлом JSON: **{{URL}}/1c-docs.json** — те же примеры, что ниже. Если что-то в памятке расходится с реальным поведением сайта, это ошибка памятки — напишите владельцу.

## 1. Какой подход: по поставкам (инвойсам)

Магазин оптовый, поэтому работаем **по поставкам** — это второй из двух вариантов, о которых вы спрашивали. У каждой партии цветов своя цена, свой рейс и своя дата, и клиент выбирает конкретную партию.

- 1С присылает **инвойсы** (`supplies/sync`): номер, дату, страну, статус и строки — товар, **цену** и **количество**. Пока инвойс в пути, клиенты видят его как «товары в пути» и делают предзаказ. Когда инвойс оприходован в 1С, его товар встаёт на полку.
- Сайт показывает каждую строку инвойса **отдельной карточкой** с пометкой «Поставка № 00000624 от 29.10.2026».
- Заказ возвращается в 1С **с привязкой к поставке**: у каждой строки заказа есть `supply` (id инвойса в 1С, номер, дата). По нему вы списываете товар из нужной партии.
- Режим «просто интернет-магазин» (список товаров без инвойсов) тоже есть: строки `products/sync` с `price` и `quantity` продаются «без поставки». Но основной путь — инвойсы.

Сайт сам **ничего не создаёт в 1С**. Документы «Заказ покупателя» создаёте вы.

## 2. Одинаковые названия во всём обмене

Одни и те же короткие названия везде — в поставках, товарах, заказах:

| Поле | Смысл |
|---|---|
| `id` | номер сущности. Когда его присылает **1С** — её собственный (код или GUID). Когда его отдаёт **сайт** — номер на сайте, а id из 1С лежит рядом в `external_id` (пусто, пока вы его не сообщили) |
| `external_id` | id сущности в 1С |
| `number` | номер документа: у инвойса — его номер в 1С; у заказа — `САЙТ-57` |
| `date` | дата документа |
| `sku`, `barcode`, `name` | артикул, штрихкод, наименование |
| `price` | цена за **одну штуку** (стебель), ₽ — не за упаковку |
| `quantity` | количество в **штуках** (стеблях) |
| `sum` | сумма: `price` × `quantity` (у заказа — до скидки) |
| `total` | итог заказа со скидкой |
| `package_size` | штук в упаковке; сайт продаёт только целыми упаковками |
| `min_quantity` | минимальный заказ, в штуках |

Контрагент везде одинаков: `id`, `external_id`, `name`, `inn`, `email`, `address`, `phone`. Товар: `id`, `external_id`, `sku`, `barcode`, `name`. Упаковок в обмене нет совсем: считайте в штуках, сайт сам переведёт в упаковки.

## 3. Что и когда передавать

| Поток | Направление | Как часто |
|---|---|---|
| **Инвойсы** `supplies/sync` | 1С → сайт | каждые 10–15 минут |
| **Заказы** `orders/export` + `orders/ack` | сайт → 1С | каждые 2–5 минут |
| **Статусы** `orders/status` | 1С → сайт | при смене состояния заказа в 1С |
| Контрагенты `clients/sync` | 1С → сайт | раз в сутки (необязательно) |
| Товары `products/sync` | 1С → сайт | по необходимости: карточки, виды и цвета, фото |
| Фото `products/photo` | 1С → сайт | при изменении фото (необязательно) |

Порядок в каждом обмене: **инвойсы → заказы → статусы**.

## 4. Доступ и проверка связи

Каждый запрос должен содержать ключ. Любой из способов:

```
X-API-Key: dnt_0123456789abcdef0123456789abcdef01234567
Authorization: Bearer dnt_0123456789abcdef0123456789abcdef01234567
Authorization: Basic base64("1c:dnt_0123…")      // логин любой, ПАРОЛЬ = ключ
```

Проверка связи (должен вернуться JSON со словом `ok`): `GET {{URL}}/api/1c/ping`

```
{{json:ping.response}}
```

Правила и ограничения:

- только **HTTPS**; нужен TLS 1.2 или новее (на старых Windows Server его надо включать отдельно);
- кодировка тела — **UTF-8** (допускается BOM); JSON — с кириллицей «как есть»;
- не чаще **120 запросов в минуту** с одного адреса (ответ 429 — подождите минуту);
- тело запроса — до **40 МБ**; ключ можно ограничить адресами вашего сервера (ответ 403 с других адресов); владелец может отключить ключ в любой момент (ответ 401).

**Сначала проверьте, потом загружайте.** К адресу любого приёма (`supplies/sync`, `products/sync`, `clients/sync`) можно добавить `?dry_run=1`: сайт посчитает всё так же, вернёт тот же ответ с `"dry_run": true`, но **ничего не сохранит**. Первую выгрузку всегда начинайте с проверки.

## 5. Инвойсы: 1С → сайт (основной путь)

`POST {{URL}}/api/1c/supplies/sync` · `Content-Type: application/json; charset=utf-8`

Инвойс в пути:

```
{{json:supplies_sync.request}}
```

Тот же инвойс после оприходования в 1С (в `quantity` — **остаток партии**, то есть сколько штук ещё не продано):

```
{{json:supplies_sync.request_received}}
```

Ответ:

```
{{json:supplies_sync.response}}
```

| Поле инвойса | Смысл |
|---|---|
| `id` | **идентификатор документа в 1С** (номер или GUID). По нему сайт находит поставку; повторная отправка ничего не дублирует |
| `number` | номер инвойса для людей (если нет — берётся `id`); клиенты и менеджеры видят «Поставка № 00000624» |
| `date` | дата поставки (прибытия), `2026-10-29` или `29.10.2026`; её видят клиенты |
| `country`, `supplier` | откуда летит; страна показывается клиентам, поставщик попадает в заметку |
| `status` | `in_transit` — ещё в пути (в 1С документ **не проведён**, в списке строка фиолетовая); `received` — **оприходован** (документ проведён, строка белая); `cancelled` — помечен на удаление |
| `items` | строки: `id`, `sku`, `barcode`, `name`, `package_size`, `price`, `quantity` (+ `kind`, `color`, `height`, `country`, если хотите описать новый товар) |

Правила:

- **`price`** — цена продажи за штуку (как в каталоге), а не закупочная цена из инвойса. **Владелец выбрал колонку «Цена продажи»** документа «Инвойс …» (не «Цена закупки» и не «Цена крупный опт»). Нет `price` — сайт возьмёт последнюю известную цену товара; если и её нет, строка вернётся в `errors`.
- **`quantity`** при `in_transit` — сколько штук едет (для предзаказа). При `received` — **остаток партии в штуках**: ушло 50 штук — в следующем обмене пришлите на 50 меньше. Остаток 0 снимает строку с полки. Неполная упаковка не продаётся (`quantity` 3010 при упаковке 25 → 120 упаковок).
- Присылайте инвойсы за последние 2–3 недели вместе с **текущим** состоянием (в пути или оприходован). Пустой список инвойсов ничего не закрывает.
- `items` можно не присылать совсем: тогда состав и количества не меняются, а оприходованный инвойс выкладывает на полку то, что в нём уже было. Пустой `items: []` означает «в партии ничего не осталось».
- **`"full": true`** — в списке **все** поставки, которые ещё в пути или имеют остаток; остальные поставки из 1С сайт закроет (снимет с полки). Используйте, только если отправляете полный список одним запросом.
- Когда инвойс получает `received`, сайт ставит его товар на полку, резервирует его клиентам с предзаказом и отправляет им уведомление и письмо. Если остатки доехали позже, предзаказ выполнится при следующем обмене.
- Позиция, на которую уже сослался заказ или предзаказ, не удаляется — только снимается с полки. Забытый «в пути» (1С 21 день не присылала) сайт закрывает сам.
- Товар, которого ещё нет на сайте, будет создан; вид, цвет, рост и страна берутся из строки (`kind`, `color`, `height`, `country`) или из названия («Роза Кения 40»). Страна, не найденная ни там ни там, берётся из страны инвойса.
- Один и тот же товар дважды в одном инвойсе — количества складываются. Новый инвойс, в котором не нашлось ни одной подходящей строки, не создаётся (причина — в `warnings` и `errors`).
- Битые строки не ломают обмен: остальное загрузится, список проблем придёт в `errors`; существующая позиция с ошибочной строкой не меняется.
- Если у владельца включён режим `ONEC_RESERVE_UNEXPORTED`, сайт вычитает из присланного остатка заказы, которые вы ещё не забрали (так остаток не завышается между обменами). По умолчанию режим выключен.

### Откуда брать поля в документе 1С «Инвойс …» (УТ 10.2)

Сверено по экрану документа «Инвойс срезка эквадор» (шапка и табличная часть «Товары»); цифры в примерах выше — только образец.

| Что в 1С | Куда в JSON |
|---|---|
| Номер документа (`00000606`) | `id` и `number` инвойса |
| Дата документа (`19.10.2026`) | `date`: у инвойса «в пути» — дата прибытия, которую увидят клиенты; у оприходованного — дата документа |
| Контрагент (`РоуаХилл АО`) | `supplier` |
| «Инвойс №» (`Азалия`) и Комментарий (`ОП-8005 от 19.10.2026`) | `comment` (попадает в заметку поставки в админке) |
| Название типа документа («Инвойс срезка эквадор») | `country`: `Эквадор` (поле «Страна» в шапке пустое) |
| Колонка «Код» | `id` строки |
| «Полное наименование» (`Роза Аква 50 см РХ РФ`) | `name` |
| «Вид товара» (`Роза`) | `kind` |
| «Приход кол.» (в штуках) | `quantity` |
| «В пачке» (`10`, а не 25) | `package_size` |
| **«Цена продажи»** за штуку | `price` (решение владельца) |
| Цвет: определяется названием цветка (сорта), берётся из 1С | `color` |
| Страна происхождения товара (если есть в карточке номенклатуры) | `country` строки |

- **Цена всегда в рублях.** Документ может быть в долларах (курс 88): в `price` идёт «Цена продажи» в рублях за штуку, а не цена по инвойсу в USD.
- **Цвет** присылайте в каждой строке (`color`): в документе его колонки нет, владелец сказал брать цвет из 1С по названию цветка («Аваланж» → «Белый»). Нет цвета в 1С — не шлите: владелец заполнит его на сайте.
- **Название** присылайте так, как оно в 1С, **вместе с «РХ РФ»**: клиенты видят его как есть (решение владельца).
- **Страна:** в журнале «Инвойс срезка эквадор» встречаются поставщики разных стран (ECUANROS, GW FLOWERS, ROSADEX, РоуаХилл…), поэтому берите `country` у товара, если страна происхождения заполнена, а не только по названию документа.
- **Номер** бывает с буквами (`д-000076`) — это нормально, `id` и `number` — строки.
- Рост сайт возьмёт из названия («50 см»). Колонка «Артикул» пустая — `sku` можно не слать.

## 6. Заказы: сайт → 1С

Алгоритм «забрал — подтвердил»: пока вы не подтвердили, заказ приходит снова, поэтому ни один не потеряется.

1. `GET {{URL}}/api/1c/orders/export?new=1` — заказы, которые 1С ещё не забирала (до 200 за раз; если `has_more` истина — повторите после подтверждения).
2. Для каждого заказа создайте в 1С документ «Заказ покупателя». **Номер заказа на сайте (`number`, например `САЙТ-57`) запишите в реквизит документа** — по нему вы отсеете дубль, если заказ придёт повторно.
3. `POST {{URL}}/api/1c/orders/ack` — подтвердите получение.

```
{{json:orders_export.response}}
```

Что важно:

- `id` — номер заказа **на сайте**; `number` — номер для документа (`САЙТ-` + `id`); `date` — время оформления (**время магазина, Москва, без смещения**).
- **`supply`** в каждой строке — поставка, из которой клиент взял товар: `id` на сайте, `external_id` — id инвойса в 1С, `number`, `date`. По ней списывайте товар из нужной партии. У товара «без поставки» (`products/sync`) `supply.external_id` пустой.
- `sum` — сумма товаров до скидки; `total` — итог со скидкой; в строке `sum` = `price` × `quantity`, округление до копеек.
- **Контрагента** (`counterparty`) ищите по `external_id`, затем по `inn`, затем по `email`; не нашли — создайте по этим реквизитам и сообщите его id обратно (`clients/sync`, раздел 8).
- **Товар в строке:** `external_id` — ваш идентификатор товара (тот самый `id` из инвойса); у товара, заведённого на сайте вручную, пустой. Ищите по `external_id`, затем по `barcode`, затем по `sku`.
- `delivery_method` — `pickup` (самовывоз) или `delivery` (доставка, адрес в `delivery_address`); `desired_date` — когда клиенту нужны цветы (пусто, если не указано).

Подтверждение:

```
{{json:orders_ack.request}}
```

Ответ: `{{json:orders_ack.response}}`. Повторное подтверждение безопасно. Другие способы выбрать заказы: `?since=2026-10-25T00:00:00+03:00`, `?status=Новый`, `?after_id=57`, `?limit=50`.

## 7. Статусы: 1С → сайт

`POST {{URL}}/api/1c/orders/status`

```
{{json:orders_status.request}}
```

Ответ: `{{json:orders_status.response}}`

Статусы сайта: `Новый`, `Подтверждён`, `В работе`, `Отправлен`, `Выполнен`, `Отменён`. Привычные названия понимаются: «Отгружен» = Отправлен, «Доставлен» = Выполнен, «В обработке» = В работе. Неизвестный статус вернётся в `errors`.

- `comment` (необязательно) попадает в заметку сотрудников к заказу; клиент его не видит.
- `onec_number` (необязательно) — номер вашего документа.
- Клиент получает уведомление на сайте и письмо. **Отмена возвращает товар в его поставку**, поэтому «Отменён» ставьте, только когда заказ действительно отменён.
- Без JSON (один заказ): `POST …/orders/status?number=САЙТ-57&status=Отгружен&onec_number=ЗК00000123`.

## 8. Контрагенты и скидки

Клиент сайта — это контрагент 1С. Список клиентов сайта (без сотрудников): `GET {{URL}}/api/1c/clients/export` (до 1000 за раз, `?after_id=` — продолжить с места):

```
{{json:clients_export.response}}
```

Чтобы сайт «узнавал» контрагента и применял его скидку, отправьте обратно запись с вашим `external_id` и `discount_percent` — `POST {{URL}}/api/1c/clients/sync` (можно отправить запись из выгрузки как есть, поля `count`, `has_more`, `last_id` игнорируются):

```
{{json:clients_sync.request}}
```

Ответ: `{{json:clients_sync.response}}`

- `id` — **число**: номер клиента на сайте. `id` строкой считается кодом контрагента в 1С (то же, что `external_id`).
- Клиент ищется по `id`, потом по `email`, потом по `external_id`, потом по `inn` (ИНН должен быть ровно у одного клиента). Если `id`, `email` и `inn` в строке указывают на разных клиентов, строка вернётся в `errors`.
- Меняются **только** `external_id`, `discount_percent` и адрес (если на сайте он пуст). Название, ИНН, email и телефон 1С не меняет, клиентов и права доступа не создаёт: регистрацию и одобрение делает менеджер на сайте. `discount_percent` можно не присылать, если присылаете `external_id`.

## 9. Товары: 1С → сайт (справочник, по необходимости)

`POST {{URL}}/api/1c/products/sync`

```
{{json:products_sync.request}}
```

Ответ:

```
{{json:products_sync.response}}
```

| Поле | Смысл |
|---|---|
| `id` | идентификатор товара в 1С (код или GUID). По нему сайт находит товар при следующих обменах; переименование в 1С дубля не создаёт |
| `sku`, `barcode`, `name` | артикул, штрихкод, наименование (**`name` обязательно**) |
| `kind`, `color`, `height`, `country` | вид, цвет, рост (число сантиметров), страна — значения справочников сайта; нового значения нет — оно создаётся само. Вместо названия можно `kind_id`, `color_id`, `height_id`, `country_id` (номер на сайте) |
| `unit`, `package_size`, `min_quantity` | единица (по умолчанию «упаковка»), штук в упаковке, минимальный заказ **в штуках** (округляется вверх до упаковок) |
| `description`, `photos` | описание и адреса фото |
| `price`, `quantity` | необязательно: товар **без поставки** (см. ниже) |

- Строка **без** `price` и `quantity` — просто карточка товара: цену и остаток она не трогает (они приходят в инвойсах).
- Строка **с** `price` и `quantity` продаёт товар «без поставки»: остаток попадает в служебную партию «остаток без поставки». Нужно, только если часть товара лежит без инвойса. `"full": true` в этом случае снимает с полки позиции «без поставки», которых нет в выгрузке; на инвойсы он не влияет.
- Товар ищется так: `id` → `barcode` → `sku` → точное название. Если одна и та же позиция приходит и в инвойсе, и «без поставки», сайт предупредит в `warnings`: присылайте остатки одним способом.
- Не присланное поле на сайте не меняется; присланное пустым (`""`, для роста `0`) — убирается.
- Старые названия `price_per_stem`, `stock_packs`, `stock_stems`, `quantity_packs`, `quantity_stems` не принимаются: строка вернётся в `errors` с подсказкой, как поле называется теперь.
- Список справочников сайта (только чтение): `GET {{URL}}/api/1c/dictionaries`. Какие значения появились в справочниках из вашей выгрузки, перечислено в `dictionaries_created` — по нему видно опечатки.
- Справочник сайта для сверки: `GET {{URL}}/api/1c/products/export` (`?format=csv` — таблицей): те же поля; `id` — номер на сайте, ваш id — в `external_id`; цен и остатков нет.

### Фото товаров (необязательно)

Картинки в каталоге не едут: сайт не может сам скачать файл из вашей внутренней сети. Поэтому 1С присылает **сам файл** отдельным запросом, тем же ключом. **Доступ на сервер для этого не нужен.**

```
POST {{URL}}/api/1c/products/photo?id=00000012345&n=1       (?dry_run=1 — проверка без сохранения)
Content-Type: application/octet-stream

<тело запроса — сама картинка, двоичные данные JPEG / PNG / WEBP / GIF>
```

- `id` — тот же идентификатор товара, что вы присылаете в инвойсах и товарах. Вместо него можно `barcode`, `sku` или `name`.
- `n` — номер фото по порядку (1 — главное). Номер занят — фото **заменяется**; следующий по порядку — **добавляется**; «дыра» — ошибка 400. До 10 фото у товара.
- Тело — **сама картинка**, не JSON и не base64; до **15 МБ**. Сайт смотрит на содержимое, перекодирует в WEBP не крупнее 1600×1600, прозрачный фон кладёт на белый.
- Товар должен **уже быть на сайте** (иначе 404): фото никогда не создаёт товар. Запрос идемпотентен: то же фото на том же месте — `"result": "unchanged"`.
- Не присылайте `photos` в товарах для тех же позиций: оно **заменит** загруженные файлы списком адресов.

Ответ:

```
{{json:products_photo.response}}
```

## 10. Если JSON недоступен

| У вас | Что использовать |
|---|---|
| 1С 8.3.6 и новее (есть `ЗаписьJSON`) | всё по этой памятке |
| 1С 8.2 / 8.3 старше 8.3.6, есть `HTTPСоединение` | заказы таблицей: `orders/export?new=1&format=csv`, подтверждение `POST …/orders/ack?numbers=САЙТ-57,САЙТ-58`; остатки — CSV-прайс (ниже) |
| 1С 7.7 | CSV через COM-объект `WinHttp.WinHttpRequest.5.1` |
| Из 1С нельзя ходить в интернет | файлы: выгрузка Excel/CSV из 1С → загрузка в админке сайта, заказы скачиваются из админки |

**CSV-прайс** (остаток «без поставки»): `POST {{URL}}/api/1c/products/sync?format=csv`, тело — текст с разделителем `;` (или запятой/табуляцией), первая строка — названия колонок:

```
Артикул;Наименование;Цена;Остаток;В пач.;Страна
ROSA-FREEDOM-60;Роза Freedom 60 см;42,5;3000;25;Эквадор
```

Колонки угадываются: «Артикул», «Код», «Штрихкод», «Наименование/Номенклатура», «Цена/Цена опт.» (`price`), «Остаток/Количество» (`quantity`), «В пач.», «Вид», «Цвет», «Рост», «Страна», «Мин. заказ». Колонка «Группа» не используется. Кодировка — UTF-8 или Windows-1251. Параметры адреса: `stock_unit=packs` (остаток в упаковках; по умолчанию — в штуках), `price_unit=pack` (цена за упаковку; по умолчанию — за штуку), `price_column=Цена опт` (какую колонку цены взять), `full=1`.

Заказы таблицей: каждая строка — одна **позиция** заказа, номер заказа и контрагент повторяются. Колонки: `order_number`, `order_id`, `date`, `desired_date`, `delivery_method`, `delivery_address`, `status`, `comment`, `order_sum`, `discount_percent`, `order_total`, `counterparty_id`, `counterparty_external_id`, `counterparty_name`, `counterparty_inn`, `counterparty_email`, `counterparty_address`, `counterparty_phone`, `supply_id`, `supply_external_id`, `supply_number`, `supply_date`, `product_id`, `external_id`, `sku`, `barcode`, `name`, `package_size`, `price`, `quantity`, `sum`. Добавьте `&encoding=cp1251`, если 1С читает Windows-1251.

## 11. Примеры кода (платформа 8.3.6+)

Служебная функция запроса. Адрес и ключ храните в константах/регистре сведений с ограниченным доступом, **не в тексте модуля**.


## 12. Приёмка: как проверить, что всё работает

1. `ping` возвращает `ok`.
2. Отправьте тестовый инвойс `in_transit` (с `?dry_run=1`, потом без него): в каталоге появились «товары в пути» с пометкой «Поставка № …», можно сделать предзаказ.
3. Отправьте тот же инвойс ещё раз — дублей нет, `created: 0`, `updated: 1`.
4. Отправьте его же со статусом `received` и остатком: товар на полке, цена за штуку и остаток сходятся; предзаказ выполнен.
5. Владелец оформляет на сайте тестовый заказ. Через `orders/export?new=1` он приходит, у строки заполнен `supply`; после `ack` — больше не приходит. Повторите `ack` — ошибки нет.
6. Смените статус заказа из 1С («Отгружен») — клиент видит новый статус и получает письмо; `comment` виден в заметке заказа.
7. Намеренно отправьте строку с ценой `abc` — остальные строки загрузились, эта вернулась в `errors`.
8. Отправьте товар с новым цветом («Малиновый») и ростом 65: в ответе они перечислены в `dictionaries_created`, в каталоге появились кнопки фильтра; повторная отправка ничего не создаёт.
9. Сообщите id контрагента через `clients/sync` — при следующей выгрузке заказа `counterparty.external_id` заполнен.
10. (Если есть фото.) Отправьте фото одного товара: `result: saved`; повторите — `unchanged`; отправьте вместо картинки текст — 400, на сайте ничего не изменилось.
11. Отключите ключ в админке — запросы получают 401.

Готовый скрипт проверки (нужен только Python): `python scripts/onec_smoke_test.py {{URL}} ВАШ_КЛЮЧ`. Страница «Интеграция» в админке показывает журнал обращений — там видно каждый запрос 1С и причину ошибки.

## 13. Надёжность и безопасность

- При сетевой ошибке или ответе 5xx повторите запрос через минуту (до 3–5 раз). При 4xx повтор бесполезен — исправьте данные.
- Все операции **идемпотентны**: инвойсы перезаписываются, `ack` и статусы можно повторять.
- Не отправляйте инвойсы чаще раза в минуту; раз в 10–15 минут достаточно.
- Не публикуйте ключ в письмах, мессенджерах и коде. Если ключ засветился — владелец отключает его в админке и создаёт новый.

| Код | Что значит | Что делать |
|---|---|---|
| 200 | принято (смотрите `errors` в ответе: строки с ошибками не загрузились, остальные — да) | — |
| 400 | неверный формат данных | исправить тело запроса; текст ошибки в `detail` |
| 401 | неверный или отключённый ключ | проверить ключ, попросить владельца создать новый |
| 403 | ключ нельзя использовать с этого адреса | сообщить владельцу адрес сервера 1С |
| 404 | (для фото) такого товара на сайте нет | сначала отправить товар или инвойс, передавать тот же `id` |
| 413 | слишком много данных | отправлять частями |
| 429 | слишком часто | подождать минуту |
| 500 | ошибка на сайте | повторить позже, сообщить владельцу |
| 503 | обмен не настроен | владелец не создал ключ |

## 14. Решения владельца и вопросы — выяснить до начала работы

**Уже решено** (по экрану документа «Инвойс срезка эквадор» и ответу владельца):

- в `price` идёт **«Цена продажи»** за штуку в рублях (не закупка и не «Цена крупный опт»);
- количество — в **штуках**; «штук в пачке» — колонка «В пачке» (`package_size`), вид — «Вид товара», код товара — «Код»;
- **«в пути» или «оприходован»** — по списку документов «Инвойс срезка эквадор»: строка **фиолетовая** (не привезли) — `in_transit`, **белая** (оприходован) — `received`. Вероятно, это признак «Проведён» (у «в пути» документ не проведён); проверьте, на каком реквизите построено оформление списка, и берите `status` из него;
- **название** — как в 1С, вместе с «РХ РФ» (не убирать);
- **цвет** — из 1С, по названию цветка.

**Ещё выяснить:**

- Ведётся ли в 1С остаток **по партиям** (по документам-инвойсам)? Откуда брать остаток партии для оприходованного инвойса?
- Какие склады учитывать? Вычитать ли резервы и заказы покупателей?
- Откуда брать штрихкод? Рост берётся из названия.
- Документы «Заказ покупателя» создавать автоматически или проверять вручную?
- Какие статусы и когда вы будете присылать на сайт?
- Нужна ли передача id контрагентов и скидок клиентов?
