# Обмен 1С и сайта: полное руководство

Книга для оператора 1С, менеджера и владельца: что делает файл «ОбменССайтом», как данные ходят в обе стороны, как проверить, что всё на месте и нет задвоений, и что делать, если что-то пошло не так. Редакция 12.11.2026.

# Часть 1. Главное

## Как это устроено в двух словах

* **1С главная.** Товары, цены, остатки и накладные ведутся в 1С. Сайт — витрина: он показывает то, что ему отправила 1С, и принимает заказы клиентов.
* **1С сама ходит на сайт.** Сайт к 1С не обращается, поэтому доступ к 1С из интернета не нужен. Вход на сайт по ключу (длинный пароль вида `dnt_…`), который владелец создаёт и в любой момент отключает в «Админка → Ещё → Интеграция с 1С».
* **Файл «ОбменССайтом.epf»** — маленькая программа внутри 1С (внешняя обработка). Через неё оператор отправляет поставки и фото, забирает заказы и сообщает статусы.
* **Ничего не уходит без вашего «Да».** Каждый шаг сначала показывает отчёт, потом спрашивает.
* **Сайт показывает снимок.** Остаток на сайте равен остатку в 1С **на момент последней отправки**. Если после неё в 1С продали товар, сайт об этом не знает, пока оператор не отправит поставки снова (или пока не включён автообмен). Это главное, что нужно помнить.

## Что куда ходит

| Данные | Где главные | Направление | Как |
|---|---|---|---|
| Поставки (инвойсы): товар, цена, остаток партии | 1С | 1С → сайт | «1. ПОСТАВКА» |
| Фото товаров | 1С (файлы на компьютере) | 1С → сайт | «3. ФОТО» |
| Заказы клиентов | сайт | сайт → 1С | «2. ЗАКАЗЫ С САЙТА» |
| Статусы заказов | менеджер на сайте или 1С | в обе стороны | на сайте или «3. Сменить статус заказа» |
| Регистрация и одобрение клиентов | менеджер на сайте | только на сайте | 1С клиентов не создаёт |
| Скидки клиентов | 1С или менеджер | через программиста | по необходимости |

## Файл «ОбменССайтом.epf»

**Где лежит.** На рабочем столе компьютера с 1С. Рядом может лежать старый файл «Проверка»: он не нужен.

**Как открыть.**

1. В 1С: «Файл» → «Открыть…» (или Ctrl+O).
2. Найдите «ОбменССайтом» и нажмите «Открыть». Если 1С спросит «Разрешить открывать данный файл?», нажмите «Да»: файл наш.
3. Появится меню из пяти пунктов. Выберите пункт и нажмите «OK». Закрыть меню: «Отмена».

**Как понять, что у вас новая версия.** В заголовке меню написано «сборка 2026-11-11, простое меню». Если вы видите длинный список из 21 пункта и первой строкой «Первая настройка», это старая версия, которая осталась в памяти 1С: нажмите «Отмена», закройте 1С и откройте её заново. Пункт «Первая настройка» **не нажимайте**.

**Меню.**

| Пункт | Для чего | Когда нажимать |
|---|---|---|
| **1. ПОСТАВКА** | загрузить товар, цены и остатки на сайт (3 шага: посмотреть, проверить, отправить) | пришла машина; изменились цены или остатки; утром и вечером, пока нет автообмена |
| **2. ЗАКАЗЫ С САЙТА** | посмотреть новые заказы, подтвердить перенос, сменить статус | несколько раз в день и каждый раз, когда на сайте новый заказ |
| **3. ФОТО** | загрузить фотографии товаров (2 шага: проверить, отправить) | когда положили новые снимки в папку |
| **4. ПРОВЕРКА** | работает ли связь с сайтом и ключ | утром; когда что-то не работает |
| **5. ДОПОЛНИТЕЛЬНО** | настройки, сверка, автозаказы | для программиста; оператору нужна только «Сверка» |

**Отчёты.** Окно отчёта закрывается кнопкой «OK» мышью: Enter в нём только добавляет пустую строку. Каждый отчёт сохраняется в файл `Документы\Dianthus1C\last_report.txt` на компьютере 1С, поэтому закрыть окно, не дочитав, не страшно.

## Что внутри «5. ДОПОЛНИТЕЛЬНО»

Первым стоит безопасный пункт «Показать настройки (только просмотр)». Дальше:

| Пункт | Безопасно? | Что делает |
|---|---|---|
| Сверка: все строки инвойсов | да, только чтение | показывает все строки, которые уйдут на сайт, со страной, пачкой, ценой |
| Поставка: только шаг «посмотреть» | да | как шаг 1 мастера |
| Поставка: только шаг «проверка на сайте» | да, на сайте ничего не сохраняется | как шаг 2 мастера |
| Фото: только проверка | да | как шаг 1 мастера «Фото» |
| Описание базы, сведения о базе | да, только чтение | для программиста |
| Автообмен по расписанию: включить или выключить | **только программисту** | 3 вопроса; про каталог и автозаказы отвечать «Нет» |
| **Первая настройка** | **нет: один раз при установке** | адрес сайта, ключ, склад |
| Поставка: только шаг «ОТПРАВИТЬ» | осторожно | отправляет без предварительного просмотра |
| Фото: только ОТПРАВИТЬ | осторожно | отправляет фото без проверки |
| Автозаказы: создать накладные | **только в копии базы** | создаёт документы 1С |
| **Каталог «без поставки»: ОТПРАВИТЬ** | **нет** | товар на сайте **задвоится** |

> **Важно.** Пункты «Каталог без поставки» и «Первая настройка» нажимать не нужно, пока вам не сказал это программист.

## Слова, которые встретятся

| Слово | Что это |
|---|---|
| **Инвойс** | документ 1С о приходе товара. В меню «Инвойсы» четыре списка: эквадор, голландия, горшечные, аксессуары. Для сайта инвойс — «поставка» |
| **Привоз** | партия: у каждого инвойса своя дата и своя цена, поэтому одна роза может быть на сайте несколькими карточками («привоз 6 ноября», «привоз 31 октября») |
| **Штука** | один стебель. Цена на сайте и в обмене всегда за **штуку** |
| **Пачка (упаковка)** | единица продажи на сайте: 10–25 штук. Клиент заказывает целые пачки |
| **В наличии** | инвойс проведён, товар на складе «Главный» |
| **В пути** | инвойс не проведён: машина едет, клиент может сделать предзаказ |
| **Полный список** | при каждой отправке сайт получает **все** актуальные поставки; чего в списке нет, то на сайте закрывается (остаток обнуляется) |
| **Проверка** | отправка с пометкой «только проверить»: сайт всё считает, но ничего не сохраняет |
| **Ключ** | пароль, по которому 1С входит на сайт |

# Часть 2. Поставки: из 1С на сайт

## Что читает обработка

Все документы «Инвойс» четырёх видов. На 12.11.2026 обработка прочитала **596 инвойсов**, из них на сайт идут только те, где ещё есть остаток: **78** (эквадор 34, голландия 26, аксессуары 12, горшечные 6). Остальные 518 распроданы и на сайт не уходят.

## Что получает каждая строка

| Что на сайте | Откуда берётся в 1С |
|---|---|
| Название | название номенклатуры |
| Идентификатор товара | код (GUID) номенклатуры: по нему сайт узнаёт товар, даже если его переименовали |
| Цена за штуку | «Цена продажи» в строке инвойса |
| Штук | Количество × Коэффициент строки |
| Размер пачки | «Кол-во в пачке» в строке; если пусто, число из поля «Упаковка»; если и его нет, обработка **угадывает** и пишет в отчёте «ПРОВЕРЬТЕ» (или знак «?» в сверке) |
| Длина стебля | «Высота» в строке; если пусто, из карточки товара |
| Вид (роза, хризантема, горшечное…) | по группе и названию номенклатуры; запасной источник: поле «Вид товара» в строке |
| Страна | по группе номенклатуры в 1С («Срезанные цветы → КЕНИЯ → …»), если группы нет, из карточки или строки |
| Номер и дата поставки | номер и дата инвойса |

> **Важно.** Если у товара пачка «угадана», проверьте её до отправки: от пачки зависит цена за пачку, которую увидит клиент.

## Остаток

* Для оприходованных (проведённых) инвойсов сайт показывает **остаток склада «Главный»**, а не количество по документу.
* Если один товар пришёл несколькими инвойсами, остаток склада **распределяется по ним от новых к старым**. Это расчёт, а не точный учёт по партиям.
* На сайте остаток считается **целыми пачками**: 7 штук при пачке 10 дают 0, и такой позиции на сайте нет.
* Если один товар встречается в инвойсе в двух строках, их количества суммируются.

## «В пути» и «в наличии»

* Инвойс не проведён: товар «в пути», клиенты видят его в разделе «Товары в пути» и могут сделать предзаказ.
* Когда инвойс проведён и отправлен на сайт, товар встаёт на полку, а клиентам с предзаказом резервируется товар и уходит уведомление.
* «В пути», о котором 1С не говорила 21 день, сайт закрывает сам.

## Полный список: как закрываются старые поставки

Обработка каждый раз отправляет **весь** актуальный список. Всё, чего в нём нет и что на сайте ещё лежало на полке, **закрывается**: остаток обнуляется, позиция снимается с полки. Товары и поставки при этом не удаляются.

Защита от ошибок. Обработка сама останавливается, если:

* прочитано **0 инвойсов** (пустой список закрыл бы весь каталог): «СТОП: 1С не прочитала ни одного инвойса»;
* к отправке **больше 200 инвойсов** (сайт принимает не больше 200 за раз): «СТОП: к отправке больше 200 инвойсов»;
* по документам оприходовано много, а на складе ноль: «ВНИМАНИЕ: … на складе … 0» (выбран не тот склад).

## Как сайт узнаёт товар

Для каждой строки сайт ищет товар в таком порядке: по идентификатору 1С; по штрихкоду; по артикулу; по точному названию. Штрихкод, артикул и название работают, только если найденный товар **не принадлежит другому коду 1С**: два разных товара с одинаковым названием не склеиваются. Поэтому:

* переименование товара в 1С **не создаёт дубль**: карточка та же, имя обновляется;
* повторная отправка того же инвойса ничего не дублирует: поставка узнаётся по номеру (`Инвойс-00000567`; бывают и номера вида `д-000085`).

## Защита свежих заказов

Пока 1С не подтвердила заказ с сайта, сайт **вычитает** такой заказ из остатка при загрузке: иначе отправка остатков «вернула бы на полку» только что проданное. Поэтому неперенесённые заказы нужно подтверждать вовремя (часть 3).

## Фото

Файл называется **точно как товар в 1С**: `Мондиал 60 Tessa.jpg`; второе фото: `Мондиал 60 Tessa #2.jpg` (до 10 на товар). Регистр, «ё» и лишние пробелы не важны. Формат JPG, PNG или WEBP; до 15 МБ через 1С; не больше 40 мегапикселей. Положите файлы в `Документы\Dianthus1C\photos` и выберите «3. ФОТО»: сначала проверка, потом отправка. Повторная отправка того же файла ничего не дублирует. Фото можно загружать только для товара, который уже есть на сайте: сначала поставка, потом фото.

# Часть 3. Заказы: с сайта в 1С

## Путь заказа

1. **Клиент нажимает «Подтвердить заказ».** Товар сразу резервируется: остаток на сайте уменьшается. Заказ получает номер (**САЙТ-5**) и статус «Новый», счёт PDF формируется сам. Двойное нажатие кнопки не создаёт два заказа.
2. **Оператор открывает «2. ЗАКАЗЫ С САЙТА» → «1. Показать новые заказы».** Отчёт показывает номер, клиента с ИНН, адрес получения, товары, штуки, цены и сумму со скидкой. Ничего не меняется. Пока заказ не подтверждён, он показывается снова и снова.
3. **Оператор оформляет документы в 1С:** «Счёт на оплату», затем «Расходная накладная» (Документы → Реализации товаров и услуг). В комментарии пишет **САЙТ-5**, чтобы не создать документ дважды, и резервирует товар.
4. **«2. Заказ оформлен в 1С… подтвердить на сайте».** Вопрос «Документ создан в 1С и товар зарезервирован?»: «Да» только если это так. Оператор вписывает номер документа (например, д-001812). Заказ перестаёт показываться как новый.
5. **Статус** ставит менеджер на сайте или оператор («3. Сменить статус заказа»): Новый → Подтверждён → В работе → Отправлен → Выполнен. Клиент получает уведомление на сайте и письмо (когда настроена почта).
6. **Отмена.** Статус «Отменён» возвращает товар на сайт.

## Что гарантирует сайт

* Заказ **не потеряется**: пока 1С его не подтвердила, он приходит снова.
* Повторное подтверждение **безопасно**: ничего не задвоится, номер документа обновится.
* Остаток не уходит ниже нуля: если два клиента заказывают последнюю пачку, второй получит сообщение, что осталось меньше.
* Смена статуса и отмена **сами пересчитывают остаток** той поставки, из которой взят товар.

## Автозаказы (когда будут включены)

Сейчас накладные создаёт оператор. Автозаказы (накладные создаются сами, непроведёнными) написаны, но включаются только после приёмки на копии базы «Цветы ТЕСТ» и по слову владельца. Пока они выключены.

# Часть 4. Как пользоваться: день оператора

## Распорядок

| Когда | Что делать |
|---|---|
| Утром | «4. ПРОВЕРКА» (первая строка «ВСЁ В ПОРЯДКЕ»). «1. ПОСТАВКА» (остатки за ночь). «2. ЗАКАЗЫ» → «Показать» |
| Пришла машина | оформить инвойс, провести → «1. ПОСТАВКА» → фото → «3. ФОТО» |
| В течение дня | «2. ЗАКАЗЫ» → «Показать» → оформить документы → «подтвердить на сайте» |
| После больших продаж и вечером | «1. ПОСТАВКА»: чтобы сайт не показывал уже проданное |

> **Важно.** Пока не включён автообмен, **частота отправки поставок = свежесть остатков на сайте.** Отправляйте минимум утром и вечером, а также после прихода машины и крупных отгрузок. Цель: автообмен каждые 30 минут.

## «1. ПОСТАВКА» по шагам

1. Выберите пункт, «OK». **Шаг 1 из 3 — посмотреть.** Прочитайте отчёт: сколько инвойсов, какие поставщики, строки со словом «ПРОВЕРЬТЕ». Закройте «OK».
2. Вопрос «проверить это на сайте?»: «Да».
3. **Шаг 2 из 3 — проверка на сайте.** Сайт считает и ничего не сохраняет. Первая строка: «ИТОГ: проверка прошла, ошибок нет. Можно отправлять.» Если «НЕ ГОТОВО», мастер остановится: читайте ошибки ниже и исправляйте данные в 1С.
4. **Шаг 3 из 3 — отправка.** Вопрос «Отправить на сайт N инвойсов ПО-НАСТОЯЩЕМУ?»: «Да», когда уверены.
5. Первая строка: «ИТОГ: поставка отправлена на сайт, ошибок нет». Откройте каталог и убедитесь, что товар появился.

В отчёте проверки есть цифры: «новых», «обновлено», «на полке», «закрыто». Например: «инвойсов: 78, новых: 1, обновлено: 76, на полке: 1, закрыто: 4». Если «новых» почти столько, сколько всего, а «обновлено» почти ноль, остановитесь: идентификаторы не совпали, и отправка завела бы дубли. Позовите программиста.

## Остальные пункты

«2. ЗАКАЗЫ С САЙТА», «3. ФОТО» и «4. ПРОВЕРКА» описаны в части 3 и в «Руководстве», карточки 1–5.

# Часть 5. Как проверить, что всё на месте и нет задвоений

## Быстрая проверка (2 минуты, оператор)

1. В 1С: «1. ПОСТАВКА» → шаг 1: запишите число «к отправке N инвойсов».
2. На сайте: «Админка» → «Поставки»: число поставок из 1С должно быть равно N плюс закрытые прежние.
3. Откройте каталог и найдите пару товаров, которые сегодня приходили: они на месте, цена и дата привоза верные.

## Полная сверка (10 минут, со мной)

Она сравнивает **каждую строку** 1С с каждой строкой сайта.

1. В 1С: «Файл → Открыть → ОбменССайтом → 5. ДОПОЛНИТЕЛЬНО → Сверка: все строки инвойсов». В окне отчёта щёлкните в текст, Ctrl+A, Ctrl+C, вставьте в файл `sverka.txt`.
2. Сразу перед этим (или после) отправьте поставки («1. ПОСТАВКА → Да»), чтобы сайт и 1С были «в один момент».
3. Мне: «сверь». Я выгружу строки сайта и запущу сверку: `python scripts/compare_1c_site.py sverka.txt rows.tsv`.

**Как читать итог:**

| Строка итога | Норма | Если не так |
|---|---|---|
| Есть в 1С, нет на сайте | 0 сразу после отправки | товар не дошёл: см. «Товара нет на сайте» |
| Есть на сайте, нет в 1С | 0 | товар продан или удалён в 1С после отправки: отправьте поставки |
| Остаток отличается | 0 сразу после отправки | после продаж без отправки это нормально |
| Цена, размер пачки, страна отличаются | 0 всегда | ошибка: позовите программиста |
| Названия разные (переименован) | 0, но допустимо | отправьте поставки, имя обновится |

## Проверка на задвоения (скрипт `data_check.py`)

* Сайт: 233 товара, 80 поставок (все из 1С), на полке 253 позиции, 4 882 пачки, 24 011 штук. **Задвоений нет, проблем 0.**
* Построчная сверка: **цены, размеры пачек и страны совпали у всех сопоставленных позиций (0 расхождений).**

## Г. Товара нет на сайте

Откройте «Сверку» (пункт 5) и найдите строку этого товара. Смотрите поле «штук к отправке» и «статус». По порядку:

1. **Остаток на складе «Главный» меньше одной пачки** (или 0): на сайт такой товар не попадает. Нормально.
2. **Инвойс не проведён:** товар «в пути», на полке его нет, он в разделе «Товары в пути».
3. **Нет цены** в строке: сайт строку не примет, мастер напишет «НЕ ГОТОВО».
4. **После прихода товара не отправляли поставки:** отправьте.
5. **Документ другого вида**, чем читает обработка: проверьте, что в названии есть слово «Инвойс» (настройка `invoice_words`).
6. **Документ с пометкой на удаление** или отменён: на сайт не идёт.
7. **Склад другой:** остаток считается только по складу «Главный».
8. **Строка с нулевым количеством:** пропускается.

## Д. Товар на сайте, а в 1С его уже нет

Сайт узнает об этом при следующей отправке: полный список закроет такие позиции. Пока не отправили, клиент **может заказать товар, которого нет**. Что делать менеджеру, если заказан отсутствующий товар: связаться с клиентом, предложить замену, при отказе отменить заказ (статус «Отменён»: товар вернётся на сайт, но фактически его нет, поэтому **сразу отправьте поставки**).

## Е. Остаток на сайте не совпадает с 1С

Самый частый вопрос. Причины по порядку вероятности:

1. **Давно не отправляли поставки**, а в 1С продавали. Отправьте.
2. **Расчётное распределение:** товар пришёл несколькими инвойсами, остаток склада разложен от новых к старым. Сумма по всем карточкам равна складу, а по каждой в отдельности может отличаться от «партии» в бумажном учёте. Это не ошибка.
3. **Округление до пачки:** 1С показывает 47 штук при пачке 10, сайт 4 пачки (40 штук).
4. **Заказы сайта, не подтверждённые в 1С:** сайт удерживает их из остатка. Перенесите и подтвердите заказы.
5. **Резервы в 1С:** при настройке «вычитать резервы» (`use_reserves`) остаток считается за вычетом резервов 1С.

# Приложения

## Что обмен не делает

* не создаёт клиентов и не одобряет заявки;
* не передаёт сайту платежи и накладные (только статусы);
* не создаёт документы 1С сам (их создаёт оператор; автозаказы пока выключены);
* **ничего не удаляет**: товары и поставки только закрываются (остаток 0, снятие с полки);
* не скачивает фото сам: файл присылает 1С.

## Настройки обработки (меняет только программист)

| Настройка | Значение по умолчанию | Что значит |
|---|---|---|
| Адрес сайта | https://dianthus-opt.ru | куда отправлять |
| Склад | «Главный» | по какому складу считается остаток |
| Слова в названии инвойса | «Инвойс» | какие документы читать |
| Период «в пути» и отмен | 21 день | сколько дней смотреть назад |
| «В пути» = | документ не проведён | правило предзаказов |
| Остаток ограничивается складом | да | остаток по документу не берётся |
| Вычитать резервы | да | остаток за вычетом резервов 1С |
| Размер пачки по умолчанию | 10 | если нигде не указан |
| Штучные товары | «аксессуар, горшеч» | товары без пачки |
| Страна по названию группы | роузхилл, ступино = Россия; ecuanros, gw flowers = Эквадор; porini, ultra flo = Кения; mh flowers = Голландия | подсказка по поставщику |
