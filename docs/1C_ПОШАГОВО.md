# Сайт и 1С: порядок работы для владельца и сотрудников

Эта инструкция — для уже настроенного обмена `https://dianthus-opt.ru` с вашей базой 1С.
Связь по ключу и предпросмотр инвойсов уже прошли. Повторно заводить сайт, ключ и склад не нужно.

## 1. Самое важное

1. **1С — главный источник товаров, цен, поставок и остатков.** Сайт не ходит в вашу 1С: обработка сама
   отправляет данные на сайт по защищённому HTTPS-соединению.
2. **Заказы идут в другую сторону:** клиент оформляет заказ на сайте → сотрудник переносит его в 1С →
   создаёт документ и резерв → подтверждает перенос на сайте → отправляет статусы выполнения.
3. Обработка **не создаёт, не проводит и не удаляет документы 1С**. Она читает остатки и документы,
   а пишет только свои настройки и отчёты на компьютере пользователя.
4. Цена в обмене — **за штуку (стебель)**, количество — **в штуках**. Размер пачки передаётся отдельно;
   клиент покупает целыми пачками.
5. Не ведите один и тот же остаток одновременно вручную на сайте, через «каталог без поставки» и через
   инвойсы. Иначе появятся повторные карточки и неверные остатки.
6. Надпись **«ПРОВЕРКА, ничего не сохранено»** означает только предпросмотр. После неё обязательно нужен
   пункт **«ОТПРАВИТЬ»**, если вы хотите применить данные.
7. Не очищайте сайт и не включайте автообмен, пока не завершена приёмка на нескольких реальных товарах
   и одном специально созданном тестовом заказе.

## 2. Кто что делает

| Сотрудник | Что делает |
|---|---|
| Оператор 1С / бухгалтер | Ведёт номенклатуру, цены, инвойсы, склад и резервы; запускает обмен; переносит заказы и отправляет статусы |
| Менеджер сайта | Одобряет регистрации покупателей, отвечает клиентам, следит за заказами и рекламациями, печатает листы сборки |
| Склад | Подтверждает фактический приход и наличие, собирает заказы; не меняет цифры на сайте в обход 1С |
| Владелец | Назначает ответственных, выдаёт права менеджеров, управляет ключами и настройками, контролирует журнал обмена и копии |

Один человек может совмещать роли, но действия должны оставаться в том же порядке.

## 3. Если справочник на сайте пустой: первая загрузка

Отдельно заполнять справочник вручную или начинать с пункта 5 **не нужно**. Инвойсы сами создадут товары
и значения фильтров: вид, цвет, рост и страну. Фотографии и описания, которых нет в инвойсе, добавляются
отдельно — это не мешает первой загрузке остатков.

1. Откройте привычную внешнюю обработку **«Обмен 1С с сайтом Диантус»** в рабочей 1С.
2. Выберите **«1. Проверить связь с сайтом»**. Должны быть два ответа `200`: для `/login` и `/api/1c/ping`.
   Ответ `ping` должен содержать `"status":"ok"` и `"auth":true`. Это только проверка связи.
3. Выберите **«6. Инвойсы (поставки): показать»**. Проверьте склад, виды документов, цену, количество,
   размер пачки и статусы. Сравните два-три инвойса с исходными документами в 1С. Этот пункт ничего не отправляет.
4. Выберите **«7. Инвойсы (поставки): проверка на сайте»**. Сайт рассчитает изменения и откатит их.
   Прочитайте весь отчёт, особенно `errors`, `warnings`, `products_created` и `closed`.
5. Если всё верно, выберите **«8. Инвойсы (поставки): ОТПРАВИТЬ на сайт»**, прочитайте предупреждение и
   подтвердите. В новом отчёте не должно быть слова «ПРОВЕРКА».
6. На сайте откройте админку → **«Интеграция с 1С»**. У последнего `POST supplies/sync` должен быть код `200`
   и отчёт настоящей загрузки. Затем проверьте **«Справочник»**, **«Поставки»**, каталог и «Товары в пути».
7. Сверьте с 1С не менее трёх позиций: код/название, цену за штуку, штук в пачке, количество и страну.
   Проверьте один оприходованный инвойс и один «в пути».
8. После этого сделайте отдельный тестовый заказ и пройдите раздел 5. Только затем разрешайте клиентам
   оформлять реальные заказы и включайте расписание.

**Почему не пункт 5?** Пункты 3–5 — другой режим, «каталог без поставки». Он нужен для товара, который
намеренно продаётся без привязки к инвойсу. Не отправляйте один остаток одновременно пунктами 5 и 8.

## 4. Ежедневная работа с товарами и остатками

1. В 1С корректно заполните номенклатуру: название, вид, упаковку/число штук в пачке, высоту, страну.
   Убедитесь, что «Цена продажи» — розничная оптовая цена сайта **за штуку**, а не закупка и не цена пачки.
2. Приход оформляйте инвойсом. Непроведённый документ при выбранном правиле означает `in_transit` —
   «в пути». Проведённый документ означает `received` — «оприходован».
3. После прихода, изменения цены, продажи или резерва откройте обработку и выполните **6 → 7 → 8**.
   При ручном режиме сайт не узнает об изменениях сам.
4. Прочитайте отчёт пункта 8: код HTTP 200 сам по себе не означает, что загрузилась каждая строка.
   Ошибки конкретных строк нужно исправить в 1С и повторить **6 → 7 → 8**.
5. Менеджер проверяет журнал «Интеграция», дату обновления каталога и новые значения фильтров.
   Опечатки в названиях товаров лучше исправлять в 1С, а не только на сайте.
6. Поставки, пришедшие из 1С, **не разгружайте вручную на сайте**. Их состояние меняется в 1С и при следующей
   отправке инвойсов. Ручные поставки нужны только для товара, которого действительно нет в 1С.

Если включён проверенный автообмен инвойсов, не запускайте параллельно ручную отправку того же списка без
необходимости. Ручная проверка после необычного изменения всё равно полезна.

### Полный список в новой обработке

При настройках `cap_stock=1` и пустом `invoice_kinds` обработка отправляет полный актуальный список:
для расчёта читаются все проведённые инвойсы, а «в пути» и отмены — за заданный период и будущие даты.
Распроданные старые поставки сайт закрывает и обнуляет их остаток. При отборе только части видов документов
полный режим не применяется, чтобы случайно не снять с продажи остальные товары.

Ограничения и защита:

- больше 200 инвойсов полный список не отправляется — его нельзя молча разбивать на части;
- пустой список, если 1С вообще не прочитала документы, блокируется;
- обычный пустой `full` на сайте ничего не удаляет;
- только явно подтверждённое полное отсутствие остатков отправляет `allow_empty=true` и закрывает старые позиции;
- складской остаток товара распределяется по инвойсам **расчётно от новых к старым**. Это не точный учёт
  по партиям. Для точного остатка каждой партии нужен отдельный обмен на основе партионного учёта 1С;
- настройки группы, склада и типа цены меняются через пункт 2. Не меняйте их только «чтобы попробовать»
  на рабочем обмене.

## 5. Заказ клиента: по шагам, без потерь и двойного резерва

1. **Менеджер видит новый заказ** на сайте: ⚙ → «Заказы» → номер заказа. Проверяет покупателя, состав,
   дату «Нужно к», способ получения, адрес и комментарий. При необходимости звонит клиенту.
2. **Оператор в 1С выбирает пункт 9.** Обработка показывает ещё не перенесённые заказы. Одна строка
   отчёта — одна позиция заказа. Цена — за штуку, количество — в штуках, размер пачки указан отдельно.
3. **Сотрудник создаёт документ в 1С вручную.** В вашей базе заказ клиента заводят как «Счёт на оплату» (журнал «Реализации товаров и услуг», дальше — «Ввести накладную на основании счёта»); если бухгалтер скажет иначе, делайте как принято у вас. Выберите контрагента,
   перенесите позиции и комментарий, сохраните номер сайта `САЙТ-N` в предусмотренном поле/комментарии.
   Товар ищите по идентификатору 1С, а не только по одинаковому названию. Проверьте сумму и скидку.
4. **Проверьте наличие и зарезервируйте товар в 1С один раз.** Если документ с этим `САЙТ-N` уже создан,
   не создавайте второй. Если товара не хватает, свяжитесь с клиентом и оформите изменение по вашим правилам —
   не подтверждайте несуществующий резерв.
5. **Только после документа и резерва выберите пункт 10.** Обработка спросит подтверждение по каждому
   заказу. Для неперенесённого отвечайте «Нет» — он останется новым и придёт снова. Для перенесённого
   введите номер документа 1С. Проверьте ответ: `Сайт подтвердил заказов: N из N`.
6. **Повторите пункт 9.** Перенесённые заказы должны исчезнуть из новых. Если заказ остался, читайте ошибку,
   а не создавайте ещё один документ.
7. **Отправьте «Подтверждён» пунктом 13**, введя `САЙТ-N` или просто `N`. Теперь клиент увидит подтверждение.
   Пункт 10 сам по себе не меняет видимый клиенту статус: он только отмечает перенос и сохраняет номер 1С.
8. По мере работы отправляйте пунктом 13: **«В работе» → «Отправлен» → «Выполнен»**. Внутренняя заметка
   необязательна и клиенту не показывается. Не отправляйте один и тот же статус из 1С и вручную из админки
   без согласования — выберите одного ответственного.
9. **Отмену сначала оформите в 1С**, снимите резерв по правилам учёта и только затем отправьте «Отменён»
   пунктом 13. Сайт вернёт товар в остаток своей поставки. Повторная отправка отмены не должна удваивать возврат.
   Если отмена ошибочна, согласуйте восстановление с оператором 1С и проверьте остаток после следующей синхронизации.
10. Лист сборки и PDF-счёт доступны в заказе на сайте. Юридически значимые документы и оплату ведёт 1С;
    сайт не принимает банковский платёж и не знает о нём автоматически.

**Важно:** пока новый заказ не подтверждён пунктом 10, безопасный режим сайта удерживает его количество из
следующей выгрузки остатков. Поэтому заказы нельзя надолго оставлять в пункте 9: остаток будет занижен.
Это намеренная защита от повторной продажи, а не автоматическое создание документа в 1С.

## 6. Все пункты меню: когда они нужны

| Пункт | Что делает | Меняет сайт? |
|---|---|---|
| 1. Проверить связь | Проверяет сайт и ключ | Нет |
| 2. Первая настройка | Адрес, ключ, группа, склад, тип цены и другие настройки | Нет |
| 3. Каталог без поставки: показать | Предпросмотр отдельного режима остатков без инвойсов | Нет |
| 4. Каталог: проверка | Расчёт отдельного режима, `dry_run` | Нет |
| 5. Каталог: ОТПРАВИТЬ | Настоящая загрузка остатков **без поставки** | Да |
| 6. Инвойсы: показать | Предпросмотр поставок, строк, цен и остатков | Нет |
| 7. Инвойсы: проверка | Расчёт загрузки поставок, `dry_run` | Нет |
| 8. Инвойсы: ОТПРАВИТЬ | Настоящая загрузка поставок и товаров | Да |
| 9. Заказы: показать новые | Получает ещё не подтверждённые заказы | Нет |
| 10. Подтвердить перенос | После документа и резерва отмечает заказы перенесёнными | Да |
| 11. Описание базы | Отчёт о метаданных для разработчика | Нет |
| 12. Настройки и автообмен | Показывает настройки, включает/выключает флаги автообмена | Нет |
| 13. Отправить статус | Вручную отправляет статус конкретного заказа | Да |

Пункты 3–7 и 9 безопасны для просмотра, но пункты 4 и 7 передают данные на сайт для расчёта. Они не сохраняют
их, но оставляют запись в техническом журнале обмена.

## 7. Настройки и ключ

Настройки лежат на компьютере 1С в `Документы\Dianthus1C\settings.ini` — в вашем случае профиль находится
на диске `E:` удалённого компьютера. Не переносите этот файл на другой компьютер без необходимости:
в нём открытым текстом хранится ключ. Не присылайте его в общий чат и не публикуйте скриншот полного ключа.

- `warehouse=Главный` — склад остатков; несколько складов указываются через `;`, если это согласовано;
- `invoice_words=Инвойс` — какие документы считаются поставками;
- `invoice_days=21` — период для «в пути», отмен и частичного режима;
- `invoice_kinds` пустой — все выбранные виды инвойсов, при `cap_stock=1` включается полный режим;
- `cap_stock=1` — ограничивать оприходованные инвойсы складским остатком;
- `use_reserves=1` — вычитать резервы при расчёте складского остатка;
- `price_type` — дополнительный источник цены, если цена берётся из регистра;
- `group=Срезанные цветы` и `price_type` в пункте 2 относятся к **каталогу без поставки**, а не заменяют
  цену и вид из строки инвойса;
- `auto_catalog=0`, `auto_invoices=0` — автоматическая отправка сейчас выключена.

Если ключ скомпрометирован: владелец → ⚙ → «Интеграция с 1С» → отключить старый ключ → создать новый.
Затем обновить ключ в пункте 2 на компьютере 1С. Ключ не нужно вставлять в исходный код обработки.

## 8. Автообмен: только после ручной приёмки

Сначала должны успешно пройти: реальная загрузка инвойсов, сверка товаров, тестовый заказ, его документ
и резерв в 1С, выборочное подтверждение, повторный пункт 9, смена статуса, отмена и повторная отмена.
Не проводите эти проверки на чужих реальных заказах.

Пункт 12 лишь разрешает автоматическую отправку **и не создаёт задание Windows**. Для расписания системный
администратор создаёт отдельную задачу в Планировщике заданий Windows на компьютере 1С:

1. Использовать отдельную учётную запись с нужными правами 1С и работающим исходящим HTTPS.
2. Запускать тот же установленный толстый клиент 1С, с которого прошла ручная проверка. Точный путь к `1cv8.exe`
   и рабочей базе берётся из ярлыка/настроек запуска этой базы, а не выдумывается.
3. В параметрах указать существующую базу, `/Execute` с полным путём к проверенному `ОбменССайтом.epf`
   и `/C "авто"`. Пример параметров — `ОбменССайтом.epf /C "авто"`; способ выбора базы и авторизации
   администратор берёт из существующего ярлыка 1С. Пароль в открытую командную строку не вписывать.
4. Установить запуск каждые 10–15 минут, независимо от открытого окна 1С. Учесть часовой пояс и работу сервера.
5. Сначала запустить задачу вручную и проверить отчёт в `Документы\Dianthus1C`, затем журнал сайта.
   После этого включить в пункте 12 **только инвойсы**. Не включать одновременно каталог без поставки
   для тех же товаров.
6. Первые несколько дней сверять дату последнего обмена и ошибки. Автообмен не заменяет пункты 9, 10 и 13:
   документы, резервы и статусы остаются ответственностью сотрудника, пока не написана отдельная интеграция документов.

## 9. Типичные ошибки

| Что видите | Что делать |
|---|---|
| `401` | Ключ неверный или отключён. Владелец создаёт новый; не переписывайте адрес сайта |
| `403` | Ключ ограничен другим IP. Проверьте разрешённый адрес у владельца |
| `503` | На сайте нет действующего ключа обмена |
| «ПРОВЕРКА, ничего не сохранено» | Это пункт 4 или 7. После проверки цифр выполнить 5 или 8 соответственно |
| Справочник пуст после `ping` | `ping` только проверяет связь. Нужны 6 → 7 → 8 |
| Новых товаров много при повторной загрузке | Возможны разные идентификаторы/дубли. Остановиться и проверить `id`, не отправлять вслепую |
| Цена в 10/25 раз отличается | Проверить «Цена продажи» за штуку, не цену упаковки и не закупку |
| Количество отличается в размер пачки | Проверить `Количество × Коэффициент`, единицу и штук в пачке |
| Нет цены или пачки | Заполнить карточку/строку 1С. Пачка по виду и высота из названия — запасные правила, не замена учёту |
| Товар появился дважды | Убрать двойной источник: ручная поставка, «без поставки» и инвойс одновременно |
| Старый товар не снялся с продажи | Проверить полный режим и повторить 6 → 7 → 8; посмотреть `closed` и ошибки |
| К отправке больше 200 инвойсов | Не разбивать полный список самостоятельно. Передать отчёт разработчику для безопасной пагинации |
| Пустой полный список заблокирован | Проверить названия документов и права 1С; не подтверждать очистку вслепую |
| Заказ снова пришёл в пункте 9 | Найти уже созданный документ по `САЙТ-N`; не создавать дубль; проверить ответ пункта 10 |
| Клиент не видит подтверждение после пункта 10 | Отправить статус «Подтверждён» пунктом 13 после проверки документа и резерва |
| Остаток стал меньше после заказа | Это ожидаемо: сайт удерживает неперенесённый заказ. Перенести его и подтвердить пунктом 10 |
| Сайт недоступен из 1С | Проверить исходящий HTTPS на `dianthus-opt.ru:443`, TLS и сертификат; не открывать 1С в интернет |

## 10. Обновление самой обработки

Файл `docs/1c_kit/ObmenSSaitom.bsl` — **исходный текст**, ещё не готовый `.epf`. Замена текста на компьютере
разработчика не обновляет обработку, которую сотрудник открывает в 1С.

Программисту с доступом к Конфигуратору нужно:

1. Сохранить прежний рабочий `.epf` отдельно, не перезаписывая его до проверки.
2. В отдельной пустой файловой базе открыть Конфигуратор → «Файл» → «Новый» → «Внешняя обработка».
3. Задать имя `ОбменССайтом`, открыть модуль объекта, вставить **весь** актуальный `ObmenSSaitom.bsl`.
4. Выполнить синтаксический контроль `Ctrl+F7`, сохранить как новый `ОбменССайтом.epf`.
5. Запустить его в рабочей базе только в режимах чтения/предпросмотра: 1, 6, 7 и 9. Не подтверждать реальные
   заказы и не отправлять изменения, пока не проверена новая версия сайта.
6. Пройти тестовый сценарий, сохранить старую версию для отката и только затем выдать файл сотрудникам.
   Настройки в `settings.ini` сохраняются отдельно от `.epf`.

**Состояние на 10.11.2026.** Версия 2 собрана и проверена: синтаксический контроль без ошибок, пункты 1, 6, 7 и 8 пройдены
в настоящей 1С (ответ сайта: ошибок 0). Файл лежит на рабочем столе компьютера 1С под именем **`ОбменССайтом_v2.epf`**,
прежний `ОбменССайтом.epf` не тронут (для отката). Настройки `settings.ini` общие, заново вводить ничего не нужно.
Сотрудникам открывать `ОбменССайтом_v2.epf`; когда привыкнете — прежний файл можно убрать с рабочего стола.
Пункты 9, 10 и 13 (заказы) в версии 2 ещё не проходились с настоящим заказом: сначала тестовый заказ (раздел 5).

## 11. Как потом очистить сайт и начать заново

**Сейчас ничего очищать не нужно.** Это необратимая отдельная операция. Сначала остановить автообмен,
чтобы 1С не загрузила данные повторно, и сделать свежую резервную копию. На сервере проекта:

```bash
sudo -i
cd /root/dianthus
bash scripts/backup.sh
```

Есть два разных варианта:

1. **Удалить только торговые данные:** заказы, предзаказы, рекламации клиентов, уведомления, клиентов,
   товары и поставки. Администраторы, справочники, ключи, настройки, юридические документы и журналы сохраняются.

   ```bash
   docker compose exec -e I_UNDERSTAND_THIS_DELETES_DATA=yes app python scripts/clear_all_safe.py
   ```

   Скрипт повторно спросит `YES`. Он не очищает 1С и не отключает задание Windows. Переменная
   `I_UNDERSTAND_THIS_DELETES_DATA=yes` нужна, потому что на боевом сервере такие скрипты по умолчанию
   заблокированы от случайного запуска: без неё скрипт просто напишет «заблокирован» и ничего не удалит.

2. **Полностью пересоздать базу сайта:** удаляются все данные, включая администраторов, ключи и настройки.
   До запуска администратор должен сохранить нужные параметры и решить, как будет создан новый доступ.

   ```bash
   docker compose exec -e I_UNDERSTAND_THIS_DELETES_DATA=yes app python scripts/reset_db.py
   docker compose restart app
   ```

   Скрипт требует отдельного подтверждения. После пересоздания проверьте создание администратора и смените
   стартовый пароль. Это не способ обновления сайта и не замена резервной копии.

Для возврата после ошибки: `bash scripts/restore-db.sh backups/db-ДАТА.sql.gz` (база) и `bash scripts/restore-uploads.sh backups/uploads-ДАТА.tar.gz` (фото); копии лежат в `/root/dianthus/backups`.
Не выполняйте `docker compose down -v`: он может удалить том с базой. Не очищайте таблицы вручную.
После любого сброса сначала выполните первый раздел этой инструкции на тестовых данных, затем включайте
клиентов и расписание.
