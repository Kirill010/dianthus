# Памятка программисту 1С: обмен 1С ↔ сайт «Диантус»

Сайт: **https://dianthus-opt.ru** · Адрес обмена: **https://dianthus-opt.ru/api/1c/** · Ключ доступа вам передаст владелец (отдельно от этой памятки).

Эта памятка самодостаточна: по ней можно настроить обмен, не заглядывая в код сайта. Если что-то в ней расходится с реальным поведением сайта — это ошибка памятки, напишите владельцу.

## 1. Что нужно сделать (коротко)

Обмен состоит из трёх потоков. Первый — обязателен, остальные — по желанию владельца.

| Поток | Направление | Что передаётся | Как часто |
|---|---|---|---|
| Каталог | 1С → сайт | товары, цены, остатки | каждые 10–15 минут (остатки) |
| Заказы | сайт → 1С | новые заказы клиентов | каждые 2–5 минут |
| Статусы | 1С → сайт | «Подтверждён», «Отправлен» … и номер документа в 1С | при смене статуса |
| Скидки | 1С → сайт | персональная скидка клиента, % | раз в сутки (необязательно) |

Сайт сам **ничего не создаёт в 1С** и ничего не знает о ваших складах: он только принимает данные и отдаёт заказы. Документы «Заказ покупателя» в 1С создаёте вы.

## 2. Доступ и проверка связи

Каждый запрос должен содержать ключ. Любой из способов:

```
X-API-Key: dnt_0123456789abcdef0123456789abcdef01234567
Authorization: Bearer dnt_0123456789abcdef0123456789abcdef01234567
Authorization: Basic base64("1c:dnt_0123…")      // логин любой, ПАРОЛЬ = ключ
```

Проверка связи (должен вернуться JSON со словом `ok`):

```
curl -H "X-API-Key: ВАШ_КЛЮЧ" https://dianthus-opt.ru/api/1c/ping
```

Правила и ограничения:

- только **HTTPS**; нужен TLS 1.2 или новее (на старых Windows Server его надо включать отдельно);
- кодировка тела — **UTF-8** (допускается BOM); JSON — с кириллицей «как есть»;
- не чаще **120 запросов в минуту** с одного адреса (ответ 429 — подождите минуту);
- тело запроса — до **40 МБ**, товаров в одном запросе — до **20 000**;
- ключ можно ограничить адресами вашего сервера — тогда с других адресов он не работает (ответ 403);
- ключ владелец может отключить в любой момент (ответ 401).

## 3. Какой вариант выбрать

| У вас | Вариант | Что использовать |
|---|---|---|
| 1С 8.3.6 и новее (есть `ЗаписьJSON`) | **A** | JSON, примеры в разделе 8 |
| 1С 8.2 / 8.3 старше 8.3.6 (JSON нет), есть `HTTPСоединение` | **B** | таблицы CSV: `?format=csv`, подтверждения через адрес |
| 1С 7.7 | **C** | CSV через COM-объект `WinHttp.WinHttpRequest.5.1` |
| Из 1С нельзя ходить в интернет (облако, запреты) | **D** | файлы: выгрузка Excel/CSV из 1С → загрузка в админке сайта; заказы скачиваются из админки |

Вариант D не требует программирования обмена вообще: владелец раз в день выгружает прайс-лист из 1С и загружает его на странице «Интеграция». Это «план Б» и запасной вариант на случай сбоев.

## 4. Каталог: 1С → сайт

```
POST https://dianthus-opt.ru/api/1c/products/sync
Content-Type: application/json; charset=utf-8
```

Тело:

```
{
  "full": false,
  "products": [
    {
      "id": "00000012345",
      "sku": "ROSA-FREEDOM-60",
      "name": "Роза Freedom 60 см",
      "country": "Эквадор",
      "category": "Роза Эквадор",
      "length_cm": 60,
      "package_size": 25,
      "min_quantity": 1,
      "price_per_stem": 42.5,
      "stock_packs": 120,
      "description": "Классическая красная роза",
      "photos": ["https://dianthus-opt.ru/static/uploads/abc.webp"]
    }
  ]
}
```

### Поля товара

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | желательно | **идентификатор товара в 1С** (код или GUID). По нему сайт находит товар при следующих обменах, поэтому переименование в 1С не создаёт дубль |
| `sku` | нет | артикул |
| `name` | **да** | название (до 200 символов) |
| `price_per_stem` | **да** | **цена за одну штуку (стебель)**, не за упаковку |
| `stock_packs` | да, одно из двух | остаток в **упаковках** (пачках) |
| `stock_stems` | да, одно из двух | остаток в **штуках**; сайт сам переведёт в упаковки: `stock_stems // package_size` (неполная упаковка не продаётся) |
| `package_size` | желательно | штук в упаковке (по умолчанию 1) |
| `min_quantity` | нет | минимальный заказ, упаковок |
| `country`, `category`, `length_cm`, `description`, `photos` | нет | если поле **не прислано** — на сайте остаётся прежнее значение |

Важные правила:

- **Цена и остаток — для оптового клиента.** Какую именно цену отправлять («Цена опт.», «Мелкий опт»…) и какие склады суммировать для остатка, решает владелец — спросите его до начала работы.
- Остаток отправляйте **свободный** (за вычетом ваших резервов, которые сайт не видит).
- Товар с остатком 0 на сайте скрывается с витрины; как только остаток снова больше 0 — появляется.
- Товары сопоставляются так: сначала по `id`, затем по `sku`, затем по точному названию.
- `full: true` («полный снимок») — все позиции каталога, которых **нет** в этой выгрузке, будут сняты с остатка. Используйте, только если отправляете **весь** каталог одним запросом. Пустой «полный снимок» сайт отклоняет (ответ 400), чтобы случайно не закрыть магазин.
- Большой каталог можно отправлять частями по 1000–5000 товаров без `full`; «полный снимок» не делится на части.
- Битые строки не ломают обмен: сайт загрузит остальные и вернёт список проблем в `errors`.
- **Сначала проверьте, потом загружайте.** Добавьте к адресу `?dry_run=1` (для «полного снимка» — `?dry_run=1&full=1`): сайт посчитает всё так же (сколько товаров будет создано, обновлено, снято с полки, какие строки с ошибками), вернёт тот же ответ с `"dry_run": true`, но **ничего не сохранит**. Первую выгрузку и любые изменения сопоставления полей всегда начинайте с такой проверки: если `created` равно числу товаров в каталоге, а `updated` нулю, значит, `id` или `sku` не совпали с уже имеющимися, и настоящая загрузка создала бы дубли.

Ответ (код 200):

```
{"status": "ok", "dry_run": false, "processed": 118, "created": 3, "updated": 115, "deactivated": 0,
 "errors": ["#7 (Роза Х): price_per_stem: «abc» — не число"], "errors_total": 1,
 "warnings": [], "supply_id": 1}
```

Ошибки в `errors` — это строки, которые не загрузились; их нужно исправить в 1С, обмен при этом считается успешным.

### Вариант B: каталог таблицей CSV

```
POST https://dianthus-opt.ru/api/1c/products/sync?format=csv
Content-Type: text/csv; charset=utf-8
```

Тело — текст с разделителем `;` (или запятой/табуляцией), первая строка — названия колонок, например:

```
Артикул;Наименование;Цена;Остаток;В пач.;Страна
ROSA-FREEDOM-60;Роза Freedom 60 см;42,5;3000;25;Эквадор
```

Названия колонок угадываются: «Артикул», «Код», «Наименование/Номенклатура», «Цена/Цена опт.», «Остаток/Количество», «В пач.», «Страна», «Категория», «Длина»… Кодировка — UTF-8 или Windows-1251 (определяется автоматически). Дополнительные параметры адреса: `stock_unit=packs` (остаток в упаковках; по умолчанию — в штуках), `price_unit=pack` (цена за упаковку; по умолчанию — за штуку), `price_column=Цена опт` (какую колонку цены взять), `full=1`.

## 5. Заказы: сайт → 1С

Алгоритм «забрал — подтвердил». Он надёжен: пока вы не подтвердили, заказ приходит снова, поэтому ни один не потеряется.

1. `GET https://dianthus-opt.ru/api/1c/orders/export?new=1` — заказы, которые 1С ещё не забирала (до 200 за раз; если `has_more` истина — повторите после подтверждения).
2. Для каждого заказа создайте в 1С документ «Заказ покупателя». **Номер заказа на сайте (`number`, например `САЙТ-57`) запишите в реквизит документа** — по нему вы отсеете дубли, если заказ придёт повторно.
3. `POST https://dianthus-opt.ru/api/1c/orders/ack` — подтвердите получение (и сообщите номер документа 1С).

Заказ в ответе:

```
{
  "id": 57, "number": "САЙТ-57",
  "created_at_local": "2026-10-25T12:31:00+03:00",
  "desired_date": "2026-11-04",
  "delivery_method": "delivery", "delivery_address": "Москва, ул. Цветочная, 5",
  "status": "Новый", "comment": "Позвоните за час до доставки",
  "subtotal": 31875.0, "discount_percent": 5.0, "total": 30281.25,
  "buyer": {"company": "ООО Ромашка", "inn": "7701234567", "contact": "Иван Иванов",
            "phone": "+79001234567", "email": "shop@romashka.ru", "city": "Москва"},
  "items": [
    {"sku": "ROSA-FREEDOM-60", "name": "Роза Freedom 60 см", "quantity_packs": 3,
     "package_size": 25, "stems": 75, "price_per_stem": 42.5, "sum": 3187.5}
  ]
}
```

Что важно:

- `desired_date` — дата, к которой клиент хочет получить цветы (может быть пустой).
- `delivery_method` — `pickup` (самовывоз) или `delivery` (доставка; адрес в `delivery_address`); может быть пустым.
- **Клиента ищите по ИНН** (`buyer.inn`), затем по email; если не нашли — создайте контрагента по реквизитам.
- Товар ищите по `sku`, затем по названию. `price_per_stem` — цена за штуку, `sum` — сумма строки с учётом упаковок; `total` — итог со скидкой.
- Сумма строки считается как цена × штук в упаковке × число упаковок, округление до копеек.

Подтверждение:

```
POST https://dianthus-opt.ru/api/1c/orders/ack
{"orders": [{"number": "САЙТ-57", "onec_number": "ЗК00000123"}, {"number": "САЙТ-58"}]}
```

Повторное подтверждение безопасно. Другие способы выбрать заказы: `?since=2026-10-25T00:00:00+03:00`, `?status=Новый`, `?after_id=57`, `?limit=50`.

### Вариант B: заказы таблицей

`GET https://dianthus-opt.ru/api/1c/orders/export?new=1&format=csv` (добавьте `&encoding=cp1251`, если 1С читает Windows-1251). Каждая строка — одна **позиция** заказа; номер заказа и данные клиента повторяются в каждой строке. Подтверждение без JSON: `POST https://dianthus-opt.ru/api/1c/orders/ack?numbers=САЙТ-57,САЙТ-58`.

## 6. Статусы: 1С → сайт

```
POST https://dianthus-opt.ru/api/1c/orders/status
{"orders": [{"number": "САЙТ-57", "status": "Подтверждён", "onec_number": "ЗК00000123"}]}
```

Допустимые статусы: `Новый`, `Подтверждён`, `В работе`, `Отправлен`, `Выполнен`, `Отменён`. Клиент получает уведомление на сайте и письмо. **Отмена возвращает товар на склад сайта**, поэтому статус «Отменён» ставьте, только когда заказ действительно отменён. Без JSON (один заказ): `POST …/orders/status?number=САЙТ-57&status=Подтверждён&onec_number=ЗК00000123`.

## 7. Скидки клиентов (необязательно)

```
POST https://dianthus-opt.ru/api/1c/clients/sync
{"clients": [{"inn": "7701234567", "discount_percent": 7.5}, {"email": "shop@romashka.ru", "discount_percent": 5}]}
```

Меняется **только** процент скидки. Клиентов и права доступа 1С не создаёт: регистрацию и одобрение делает менеджер на сайте. Список клиентов сайта: `GET …/api/1c/clients/export`. Как и у каталога, есть проверка без сохранения: `POST …/api/1c/clients/sync?dry_run=1`.

### Инвойсы поставщиков → «товары в пути» (необязательно)

Приход цветов от поставщика (инвойс, рейс) можно показывать клиентам как «Товары в пути»: клиент делает предзаказ, пока цветы летят.

```
POST https://dianthus-opt.ru/api/1c/supplies/sync            (?dry_run=1 — проверка без сохранения)
{"supplies": [
  {"id": "00000622", "number": "00000622", "date": "2026-10-29",
   "country": "Эквадор", "supplier": "ECUANROS S.A", "status": "in_transit",
   "items": [
     {"id": "00000012345", "name": "Роза Фридом 60", "package_size": 25,
      "price_per_stem": 42.5, "quantity_stems": 3000}
   ]}
]}
```

| Поле инвойса | Смысл |
|---|---|
| `id` | **идентификатор документа в 1С** (номер или GUID). По нему сайт находит поставку, повторная отправка ничего не дублирует |
| `date` | дата прибытия (`2026-10-29` или `29.10.2026`); её видят клиенты |
| `country`, `supplier` | откуда летит; страна показывается клиентам, поставщик попадает в заметку |
| `status` | `in_transit` — ещё в пути; `received` — **оприходован в 1С** (цветы приехали); `cancelled` — отменён или удалён |
| `items` | строки: те же поля, что у товара (`id`, `sku`, `name`, `package_size`, `price_per_stem`), количество — `quantity_stems` (штуки) или `quantity_packs` (упаковки) |

Что важно:

- В `price_per_stem` — **цена продажи** за штуку (как в каталоге), а не закупочная цена из инвойса. Если её нет, сайт возьмёт последнюю известную цену товара.
- Присылайте инвойсы за последние 2–3 недели вместе с **текущим** статусом (в пути или оприходован). Пустой список ничего не закрывает: статус всегда приходит явно.
- Порядок в каждом обмене: **сначала** `products/sync` (остатки на полке), **потом** `supplies/sync`. Когда инвойс получает `received`, сайт закрывает поставку, резервирует клиентам с предзаказом товар **с полки** (он уже в остатках 1С) и отправляет им уведомление и письмо. Если остатки доехали позже, предзаказ выполнится при следующем обмене.
- Поставка из 1С на полку сама не «разгружается» и вручную не разгружается: остатки ведёт 1С. Инвойс, который 1С 21 день не присылала, сайт закрывает сам.
- Товар, которого ещё нет на сайте, будет создан; страна и длина стебля берутся из названия («Роза Кения 40»), если их не прислали.

Ответ: `{"status": "ok", "dry_run": false, "processed": 3, "created": 1, "updated": 1, "received": 1, "cancelled": 0, "lines": 12, "products_created": 2, "preorders_fulfilled": 4, "errors": [], "warnings": []}`.

## 8. Примеры кода (платформа 8.3.6+, вариант A)

Служебная функция запроса. Адрес и ключ храните в константах/регистре сведений с ограниченным доступом, **не в тексте модуля**.

```
Функция ВыполнитьЗапросКСайту(Метод, Путь, ТелоТекст = Неопределено)

    Соединение = Новый HTTPСоединение("dianthus-opt.ru", , , , , 120,
        Новый ЗащищенноеСоединениеOpenSSL());

    Запрос = Новый HTTPЗапрос("/api/1c" + Путь);
    Запрос.Заголовки.Вставить("X-API-Key", КлючДоступаСайта());
    Запрос.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Если ТелоТекст <> Неопределено Тогда
        Запрос.УстановитьТелоИзСтроки(ТелоТекст, КодировкаТекста.UTF8,
            ИспользованиеByteOrderMark.НеИспользовать);
    КонецЕсли;

    Если Метод = "GET" Тогда
        Ответ = Соединение.Получить(Запрос);
    Иначе
        Ответ = Соединение.ОтправитьДляОбработки(Запрос);   // POST
    КонецЕсли;

    ТелоОтвета = Ответ.ПолучитьТелоКакСтроку("UTF-8");
    Если Ответ.КодСостояния >= 400 Тогда
        ВызватьИсключение "Сайт ответил " + Ответ.КодСостояния + ": " + ТелоОтвета;
    КонецЕсли;

    Чтение = Новый ЧтениеJSON;
    Чтение.УстановитьСтроку(ТелоОтвета);
    Результат = ПрочитатьJSON(Чтение, Ложь);   // Ложь — вернуть Структуру
    Чтение.Закрыть();
    Возврат Результат;

КонецФункции

Функция ВJSON(Значение)
    Запись = Новый ЗаписьJSON;
    Запись.УстановитьСтроку(Новый ПараметрыЗаписиJSON(ПереносСтрокJSON.Нет));
    ЗаписатьJSON(Запись, Значение);
    Возврат Запись.Закрыть();
КонецФункции
```

Отправка каталога (запрос к вашим регистрам цен и остатков — свой, он зависит от конфигурации):

```
Процедура ОтправитьКаталог()

    Товары = Новый Массив;
    // Выборка = ... ваш запрос: номенклатура, свободный остаток, оптовая цена
    Пока Выборка.Следующий() Цикл
        Т = Новый Структура;
        Т.Вставить("id", Строка(Выборка.Код));
        Т.Вставить("sku", Выборка.Артикул);
        Т.Вставить("name", Выборка.Наименование);
        Т.Вставить("price_per_stem", Выборка.Цена);
        Т.Вставить("stock_stems", Выборка.Остаток);       // остаток в ШТУКАХ
        Т.Вставить("package_size", Выборка.ШтукВПачке);
        Т.Вставить("country", Выборка.Страна);
        Товары.Добавить(Т);
    КонецЦикла;

    Тело = Новый Структура("products, full", Товары, Ложь);
    Результат = ВыполнитьЗапросКСайту("POST", "/products/sync", ВJSON(Тело));
    // Результат.errors — список строк, которые не загрузились: запишите в журнал 1С

КонецПроцедуры
```

Получение заказов и подтверждение:

```
Процедура ЗабратьЗаказыССайта()

    Данные = ВыполнитьЗапросКСайту("GET", "/orders/export?new=1");
    Подтверждения = Новый Массив;

    Для Каждого Заказ Из Данные.orders Цикл
        // 1. Если документ с номером Заказ.number уже есть — просто подтвердите его.
        // 2. Иначе: контрагент по Заказ.buyer.inn, документ «Заказ покупателя»,
        //    строки из Заказ.items (sku, name, stems, price_per_stem, sum).
        // 3. Номер сайта (Заказ.number) — в реквизит документа.
        Подтверждение = Новый Структура;
        Подтверждение.Вставить("number", Заказ.number);
        Подтверждение.Вставить("onec_number", НомерСозданногоДокумента);
```

## 9. Приёмка: как проверить, что всё работает

1. `ping` возвращает `ok`.
2. Отправьте 3 тестовых товара — они появились в каталоге сайта (владелец смотрит), цена за штуку и остаток сходятся.
3. Отправьте тот же каталог ещё раз — дублей нет, `created: 0`.
4. Владелец оформляет на сайте тестовый заказ. Через `orders/export?new=1` он приходит; после `ack` — больше не приходит.
5. Повторите `ack` — ошибки нет, дубликатов нет.
6. Смените статус заказа из 1С — клиент видит новый статус и получает письмо.
7. Намеренно отправьте строку с ценой `abc` — остальные товары загрузились, строка вернулась в `errors`.
8. Отключите ключ в админке — запросы получают 401.

Готовый скрипт проверки (нужен только Python): `python scripts/onec_smoke_test.py https://dianthus-opt.ru ВАШ_КЛЮЧ`. Страница «Интеграция» в админке показывает журнал обращений — там видно каждый запрос 1С и причину ошибки.

## 10. Надёжность и безопасность

- При сетевой ошибке или ответе 5xx повторите запрос через минуту (до 3–5 раз). При 4xx повтор бесполезен — исправьте данные.
- Все операции **идемпотентны**: каталог перезаписывается, `ack` и статусы можно повторять.
- Не отправляйте каталог чаще раза в минуту; остатки — раз в 10–15 минут достаточно.
- Не публикуйте ключ в письмах, мессенджерах и коде. Если ключ засветился — владелец отключает его в админке и создаёт новый.
- Сайт ограничивает частоту запросов (120 в минуту с одного адреса), а ключ — 160 бит случайности: перебор невозможен.

## 11. Справочник ответов

| Код | Что значит | Что делать |
|---|---|---|
| 200 | принято | — |
| 400 | неверный формат данных | исправить тело запроса; текст ошибки в `detail` |
| 401 | неверный или отключённый ключ | проверить ключ, попросить владельца создать новый |
| 403 | ключ нельзя использовать с этого адреса | сообщить владельцу адрес сервера 1С |
| 413 | слишком много данных | отправлять частями |
| 429 | слишком часто | подождать минуту |
| 500 | ошибка на сайте | повторить позже, сообщить владельцу |
| 503 | обмен не настроен | владелец не создал ключ |

## 12. Вопросы к владельцу — выяснить до начала работы

- Какую цену отправлять («Цена опт.», «Мелкий опт» или другую)?
- Остаток считать по каким складам? Вычитать ли резервы и заказы покупателей?
- Какие группы номенклатуры выгружать (только цветы или всё)?
- Остаток ведётся в штуках или в упаковках? Где в 1С хранится «штук в пачке»?
- Как в 1С различаются страны и категории товаров (реквизит или группа)?
- Документы «Заказ покупателя» создавать автоматически или проверять вручную?
- Какие статусы и когда вы будете присылать на сайт?
- Нужна ли передача скидок клиентов?
