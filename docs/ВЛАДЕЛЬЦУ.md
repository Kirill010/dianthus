# Памятка владельцу: как пользоваться сайтом «Диантус»

Это документ для вас, а не для программиста. Здесь простыми словами: что у вас есть, что делать каждый
день, как подключить 1С, что нужно по закону и что делать, если что-то сломалось.

Если вы только что получили сайт — прочитайте разделы 0–2 (10 минут), остальное — по мере надобности.

---

## 0. Главное за одну минуту

* **Сайт для клиентов** — каталог с оптовыми ценами, корзина, заказ, счёт PDF, предзаказы, сроки заказа,
  обращения по качеству. Цены видят только одобренные вами клиенты.
* **Админка** — шестерёнка ⚙ в правом верхнем углу (видна вам и менеджерам). Там заказы, клиенты, справочник
  товаров, поставки, «Интеграция с 1С», «Юридическое», «Настройки».
* **Главная админки** начинается с блока **«Что сделать сегодня»**: сколько новых заказов, срочных заказов
  (нужны сегодня–завтра), заявок клиентов, рекламаций. Красные/оранжевые плитки — то, что ждёт вас.

**Первая неделя — что обязательно сделать:**

1. ☐ Сменить пароль и включить двухфакторную защиту (раздел 1).
2. ☐ Заполнить реквизиты организации (раздел 8) — иначе в юридических текстах на сайте видно «[укажите: …]».
3. ☐ Показать тексты на сайте юристу и подать уведомление в Роскомнадзор (раздел 6, файл `docs/LEGAL_CHECKLIST.md`).
4. ☐ Подключить 1С: создать ключ и передать программисту (раздел 5).
5. ☐ Подключить почту (SMTP) — чтобы письма о заказах и «забыли пароль» доходили (раздел 8).
6. ☐ Выдать менеджерам роль «менеджер» (раздел 3).

## 1. Первые шаги

1. **Войдите** на сайт под своей почтой и паролем администратора (их показал `scripts/prepare.sh` при настройке
   сервера; они же в файле `.env` на сервере).
2. **Смените пароль:** значок человечка → «Профиль» → «Смена пароля».
3. **Включите 2FA** (второй замок): «Профиль» → «Двухфакторная защита» → «Включить». Понадобится приложение
   «Яндекс.Ключ» или Google Authenticator на телефоне: отсканируйте QR-код и введите шестизначный код. Теперь,
   даже если пароль украдут, без телефона в админку не войти.
4. **Удалите** `ADMIN_PASSWORD` из файла `.env` на сервере (порядок — в `docs/GUIDE_FROM_SCRATCH.md`, раздел 12).

## 2. Каждый день

### Заказы

1. Откройте ⚙ → вкладка **«Заказы»**. Сверху — кнопки-фильтры: «Срочные», «Новый (N)», «Подтверждён (N)» …
2. Нажмите на номер заказа. Вы увидите: клиента (с телефоном — на телефоне можно нажать и позвонить),
   **«Нужно к»** (дата, к которой клиенту нужны цветы), способ получения (самовывоз/доставка + адрес),
   комментарий, состав и сумму, историю статусов.
3. Позвоните клиенту, подтвердите. Смените статус на **«Подтверждён»** — клиент получит уведомление на сайте и
   письмо.
4. **«Лист сборки»** (кнопка в заказе) — печатная страница для склада: товар, сколько упаковок и штук, галочки.
   **⚙ → «Лист сборки»** на главной админки — сводный лист на все активные заказы (или на выбранную дату):
   сколько каких цветов достать со склада.
5. Собрали — «В работе», отправили — «Отправлен», клиент получил — «Выполнен».
6. **«Отменён»** возвращает товар на склад сайта. Включайте только когда заказ точно отменён.
7. **Заметка сотрудников** — внутренняя запись («позвонить за час»). Клиент её не видит.
8. **Счёт PDF** — можно скачать для любого заказа и отправить клиенту.

### Новые клиенты

Вкладка **«Клиенты»** → у новой заявки кнопка **«Одобрить»**. Перед одобрением проверьте компанию (например,
по ИНН на egrul.nalog.ru). Клиент получит письмо, что доступ открыт. Нажав на название компании, откроете
**карточку клиента**: контакты, сколько заказов и на какую сумму, средний чек, когда заходил, согласие на
обработку данных и на рекламу, ваша заметка, его рекламации.

* **Скидка** (только владелец) — число в строке клиента или в карточке.
* **Клиент забыл пароль.** На странице входа есть «Забыли пароль?» — клиент сам получит письмо со ссылкой
  (нужна настроенная почта). Если письма не ходят: в карточке клиента → **«Сбросить пароль»** (только владелец):
  сайт покажет новый временный пароль один раз — продиктуйте его клиенту по телефону.
* **Удалить данные клиента.** Если у клиента есть заказы, удаляются только его личные данные (имя, телефон, почта,
  ИНН), а заказы остаются для бухгалтерии как «Клиент №N (данные удалены)». Без заказов — запись удаляется совсем.

### Рекламации (жалобы на качество)

Клиент нажимает «Сообщить о проблеме» в своих заказах, описывает, что случилось, и прикладывает фото. Вам
приходит письмо, а в ⚙ → «Рекламации» — карточка. Правила, как у вас заведено (они напечатаны в карточке):

* клиенту **ничего не обещаем**, решение принимаете вы;
* не спорим и не обвиняем; предположения в комментарии помечаем словом «предположение»;
* если с момента получения прошло **больше суток** — карточка помечена красным: не отказывайте сами, а
  передайте вам.

Ответ клиенту пишется в поле «Ответ клиенту» — он увидит его на сайте и получит письмо.

## 3. Сотрудники и роли

Роль «менеджер» выдаёте вы: ⚙ → «Клиенты» → «Карточка» → **«Сделать менеджером»** (человек сначала регистрируется
как обычный клиент и одобряется вами).

| | Клиент | Менеджер | Владелец |
|---|:--:|:--:|:--:|
| Видеть каталог и оптовые цены, заказывать | ✔ | ✔ | ✔ |
| Заказы: смотреть, подтверждать, менять статус, листы сборки, счета | | ✔ | ✔ |
| Клиенты: смотреть карточки, одобрять заявки, писать заметки | | ✔ | ✔ |
| Рекламации: отвечать клиентам | | ✔ | ✔ |
| Выручка и суммы по дням | | | ✔ |
| Скидки клиентов, удаление клиентов, сброс пароля, назначение менеджеров | | | ✔ |
| Справочник товаров, поставки, склад | | | ✔ |
| Интеграция с 1С (ключи), юридические тексты, настройки | | | ✔ |
| Решение по рекламации («решение владельца») | | | ✔ |

Менеджер, который уволился: «Карточка» → «Забрать роль менеджера» (и при желании «Сбросить пароль»).

## 4. Поставки, предзаказы и сроки

* **Поставка** — машина с цветами. ⚙ → «Поставки» → «Новая поставка»: страна, дата прибытия, товары. Статус
  «В пути» — товары видны клиентам как **предзаказ**. Когда машина прибыла — кнопка **«Разгрузить»**: товары
  попадают в каталог, а клиенты, оформившие предзаказ, получают уведомление и письмо.
* **Сроки заказа.** Страница «Сроки заказа» (ссылка есть в подвале сайта) считает, до какого числа нужно
  заказать цветы к нужной дате: Эквадор/Голландия/Китай/Кения — за 10 дней, Колумбия — за 7, Россия — за 3
  (считается от даты, когда цветы нужны клиенту). Заказы принимаются каждый день, включая выходные. Если у вас
  сроки изменятся — ⚙ → **«Настройки»** → «За сколько дней заказывать (по странам)».
* **Условия оплаты** («Предоплата 100% по выставленному счёту») меняются там же, в «Настройках».

Пока 1С не подключена, остатки на сайте ведёте вы — через поставки. После подключения остатки ведёт 1С, а
поставки нужны только для предзаказов (см. `docs/1C_INTEGRATION.md`, раздел 8).

## 5. 1С: что делать вам (а не программисту)

**Что такое «ключ».** Это длинный пароль не для человека, а для программы. Он нужен, чтобы сайт понимал, что
к нему обращается именно ваша 1С. У ключа есть имя («Программист Иван»), и в любой момент вы можете его
**отключить** — программа сразу перестанет входить. Ключ показывается один раз; потерялся — создаёте новый.

**Порядок:**

1. ⚙ → **«Интеграция с 1С»** → поле «Название» → **«Создать ключ»**. (Поле «Адреса, с которых можно» можно
   оставить пустым.)
2. Появится зелёная карточка с ключом и **готовым сообщением для программиста**. Нажмите «Скопировать
   сообщение» и отправьте программисту личным сообщением (не в общий чат). В сообщении — адрес, ключ и ссылка
   на памятку, где всё описано.
3. Программист задаст вам вопросы. Ответы нужны от вас, не от него (это решения владельца):
   * **какую цену** отправлять на сайт: «Цена опт.» или «Мелкий опт»;
   * по каким складам считать остаток и вычитать ли резервы;
   * какие группы товаров выгружать;
   * остаток в 1С ведётся в штуках или в упаковках, где хранится «штук в пачке»;
   * заказы с сайта создавать в 1С автоматически или проверять вручную.
4. **Следите за плашкой** вверху страницы «Интеграция»: зелёная — всё работает; жёлтая — 1С давно не
   обращалась; красная — последнее обращение закончилось ошибкой (причина написана простыми словами);
   голубая — ключ создан, но 1С ещё не заходила.
5. **Приёмка работы.** Попросите программиста пройти список из раздела 9 памятки (`/1c-docs`): тестовые
   товары, тестовый заказ, смена статуса, неверные данные. Всё это вы увидите в журнале на этой же странице.
6. **Когда обмен заработал** — удалите старый общий пароль `INTEGRATION_PASSWORD` из `.env` (на странице будет
   жёлтое напоминание). Когда подрядчик закончил — отключите его ключ.

**Если из вашей 1С нельзя ходить в интернет** (облако, запреты) — не беда, есть запасной путь без
программирования: на той же странице блок **«Загрузка из файла»**.

* *Каталог:* в 1С выгрузите прайс-лист в Excel (или CSV) → загрузите файл на странице → прочитайте отчёт
  (что загрузилось, что нет и почему). Выберите, в чём указаны остаток и цена (штуки/упаковки). Кнопка
  «Загрузить как полный каталог» убирает с продажи всё, чего нет в файле — нажимайте её, только когда файл
  содержит **все** товары.
* *Заказы:* «Заказы для 1С вручную» → «Скачать (CSV)» → загрузить в 1С → нажать «Я загрузил их в 1С».

Не забывайте: пока остатки не обновляются, сайт показывает последние известные — клиент может заказать то, чего
уже нет. Поэтому обмен лучше настроить, а загрузка файлов — на время.

**Нет программиста 1С?** Тогда идите по `docs/1C_ПОШАГОВО.md`: там по шагам, как создать файл-«курьера» (внешнюю
обработку) и дальше работать с обменом через меню в самой 1С. Любая загрузка товаров на сайт сначала делается в режиме
**«Только проверить»** (галочка на странице «Интеграция с 1С»): сайт покажет, сколько товаров создастся и обновится,
и ничего не сохранит. Так не будет ни дублей, ни ошибок.

**Подробнее для программиста:** `docs/1C_PROGRAMMER_BRIEF.md` (то же самое открыто на сайте по адресу `/1c-docs`).

## 6. Юридическое: что нужно сделать вам

Все тексты (политика обработки персональных данных, согласия, условия работы) уже на сайте и подставляют ваши
реквизиты. Но это **качественные черновики, а не заключение юриста**. Список дел — ⚙ → **«Юридическое»**, там
же отмечаете выполненное. Подробно и с образцами — `docs/LEGAL_CHECKLIST.md` и папка `docs/legal/`.

Коротко:

1. Заполнить реквизиты (раздел 8).
2. Один раз показать тексты юристу (часовая консультация), поправить прямо в админке («Юридическое» → «Править»).
3. Подать уведомление об обработке персональных данных в Роскомнадзор (бесплатно, через сайт pd.rkn.gov.ru,
   `docs/legal/rkn_notification_guide.md` — готовые ответы на вопросы формы).
4. Назначить ответственного за персональные данные (приказ — образец в `docs/legal/`).
5. Убедиться, что сервер сайта и облако 1С находятся в России.
6. С 1 сентября 2026 года владелец домена `.ru` должен подтвердить личность через Госуслуги у регистратора домена — если ещё не сделали, сделайте (личный кабинет регистратора подскажет).

Что сайт делает за вас: берёт **отдельное** согласие на обработку данных при регистрации (галочка не стоит
заранее), отдельное необязательное согласие на рекламу, ведёт журнал согласий (кто, когда, на какую версию
текста), принимает запросы клиентов на удаление данных (вкладка в «Юридическом» — на ответ по закону даётся до
10 рабочих дней), даёт клиенту скачать свои данные, хранит историю версий текстов.

**Важно про рекламу:** звонить и писать клиентам с предложениями можно только тем, у кого в таблице клиентов
(⚙ → «Клиенты (Excel)») стоит «Да» в колонке «Согласие на рекламу». Сообщения по заказам — можно всем.

## 7. Деньги и счета

* Оплаты на сайте нет: клиент оформляет заказ → вы подтверждаете → выставляете **счёт** (кнопка «Счёт PDF» в
  заказе) → клиент платит по реквизитам. Онлайн-оплата — отдельная доработка (эквайринг), если понадобится.
* В счёте печатаются ваши ИНН/ОГРН, адрес и банковские реквизиты (`SHOP_REQUISITES`), условия оплаты,
  нужная дата получения, адрес доставки. Строка про НДС (`SHOP_VAT_NOTE`) — спросите бухгалтера, что писать
  («НДС не облагается (УСН)» и т. п.). Юридически значимый счёт и закрывающие документы по-прежнему делает 1С;
  PDF с сайта — удобная копия заказа.

## 8. Реквизиты и почта: как заполнить `.env` на сервере

Настройки сайта лежат в файле `.env` на сервере. Менять его нужно редко; делается так:

```bash
ssh deploy@ВАШ_СЕРВЕР          # подключиться к серверу (как в docs/GUIDE_FROM_SCRATCH.md, раздел 6)
cd /opt/dianthus
nano .env                       # открыть файл для правки
```

Найдите строки и впишите значения **после знака «=»** (без кавычек и пробелов вокруг «=»):

| Строка | Что вписать | Пример |
|---|---|---|
| `SHOP_NAME` | название организации, как в ЕГРЮЛ | `ООО «Диантус»` |
| `SHOP_INN` | ИНН | `7720965534` |
| `SHOP_OGRN` | ОГРН (для ИП — ОГРНИП) | `1257700000000` |
| `SHOP_LEGAL_ADDRESS` | юридический адрес | `г. Москва, ул. …` |
| `SHOP_ADDRESS` | адрес склада/магазина | `г. Москва, Вешняковская ул., 39Г` |
| `SHOP_EMAIL` | почта для обращений клиентов | `info@dianthus-opt.ru` |
| `SHOP_PD_RESPONSIBLE` | ответственный за персональные данные | `Иванов И. И., директор` |
| `SHOP_VAT_NOTE` | строка про НДС в счёте (спросите бухгалтера) | `НДС не облагается (УСН)` |
| `SHOP_REQUISITES` | банковские реквизиты через « \| » | `р/с 4070… \| БИК 0445… \| Банк «…»` |
| `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TO` | почта для писем с сайта (для Яндекса нужен **пароль приложения**) | см. `docs/GUIDE_FROM_SCRATCH.md`, раздел 13 |

Сохранить: `Ctrl+O`, `Enter`; выйти: `Ctrl+X`. Применить изменения:

```bash
docker compose up -d
```

Через минуту обновите страницу ⚙ → «Юридическое»: список «не заполнено» должен опустеть.

## 9. Если что-то не работает

| Что случилось | Что делать |
|---|---|
| Сайт не открывается | На сервере: `cd /opt/dianthus && docker compose ps` — все сервисы должны быть `healthy`. Если нет: `docker compose up -d`, затем `docker compose logs app --tail=50` и пришлите вывод программисту |
| Клиент не может войти | Проверьте, что он **одобрен** (⚙ → «Клиенты»). Забыл пароль — «Забыли пароль?» или «Сбросить пароль» в его карточке. Много неудачных попыток блокируют вход на время (10 минут и дольше) |
| Письма не приходят | Не настроена почта (`SMTP_*`, раздел 8) или для Яндекса не использован «пароль приложения». На сайте всё работает и без почты, но уведомления не уходят |
| Вы забыли пароль администратора | На сервере: `cd /opt/dianthus && docker compose exec app python scripts/set_password.py ВАША@ПОЧТА НОВЫЙ_ПАРОЛЬ` (пароль — от 8 символов, буква и цифра) |
| В каталоге нет товаров | Нет остатков: поставка не разгружена или 1С прислала нули (⚙ → «Интеграция» → журнал; вкладка «На складе») |
| Цены странные (в 25 раз больше/меньше) | Перепутаны «цена за штуку» и «цена за упаковку» в выгрузке из 1С — покажите программисту раздел 4 памятки |
| Плашка «Интеграция» красная | Прочтите причину в плашке и в журнале ниже; чаще всего это неверный/отключённый ключ или формат данных |
| Нужно срочно отключить доступ программисту | ⚙ → «Интеграция» → «Отключить» у его ключа |
| Заказ оформился дважды | Такого быть не должно (защита от двойного клика есть). Если вдруг — отмените лишний заказ статусом «Отменён», товар вернётся |

## 10. Резервные копии и обновления

* Копии базы и фото делаются скриптом `scripts/backup.sh` (по расписанию — настроено в `docs/GUIDE_FROM_SCRATCH.md`,
  раздел 15). Проверяйте раз в месяц, что свежая копия существует и **лежит не только на этом сервере**
  (`BACKUP_REMOTE`).
* Обновление сайта: `cd /opt/dianthus && bash scripts/update.sh` (раздел 16 руководства). Перед обновлением
  скрипт сам делает копию.

## 11. Решения, которые нужны от вас

1. **Какую цену показывать на сайте** — «Цена опт.» или «Мелкий опт». *Рекомендация:* «Цена опт.», а мелкому опту
   выдавать персональные скидки (1С может присылать их через `clients/sync`).
2. **Предзаказы: кому достанется, если приехало меньше, чем заказали.** Сейчас резерв делится между всеми, кто
   оформил предзаказ, а в корзину цветы забирает тот, кто нажал «В корзину» первым. Если нужен порядок «по очереди
   заявок» — это небольшая доработка.
3. **Страховка от перепродажи** (`ONEC_RESERVE_UNEXPORTED=1`): включать, только если 1С подтверждает получение
   заказов (`orders/ack`). Решите вместе с программистом.
4. **Онлайн-оплата.** Нужна ли? (Сейчас — счёт и оплата по реквизитам.)
5. **Юрист.** Выберите, кто проверит тексты и подскажет по Роскомнадзору (раздел 6).
6. **Внешние сервисы.** Если захотите мониторинг ошибок Sentry (`SENTRY_DSN`) — используйте российский/свой
   сервер: иначе данные уйдут за границу (см. `docs/LEGAL_CHECKLIST.md`).

## 12. Словарик

* **Админка** — часть сайта для сотрудников (⚙).
* **Ключ (API-ключ)** — пароль для программы 1С, отключается одним нажатием.
* **API** — «розетка», через которую 1С разговаривает с сайтом.
* **`.env`** — файл настроек на сервере (пароли, реквизиты). Никому не показывайте и не отправляйте.
* **Docker** — программа, в которой «упакован» сайт; команда `docker compose …` запускает и останавливает его.
* **2FA** — второй замок: код из приложения в телефоне при входе.
* **SMTP** — настройка отправки писем с сайта.
* **Персональные данные** — любые сведения о конкретном человеке (имя, телефон, почта): закон обязывает
  обращаться с ними аккуратно.
