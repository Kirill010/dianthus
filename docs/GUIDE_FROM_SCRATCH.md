# Руководство «с нуля»: от компьютера разработчика до работающего сайта

Для владельца сайта **dianthus-opt.ru**, который делает всё **впервые**: запускает
проект у себя, покупает домен и сервер, выкладывает сайт, подключает почту и 1С,
настраивает резервные копии. Каждый шаг устроен одинаково:

> **Что делаем → зачем → как проверить, что получилось → что делать, если нет.**

Если на каком-то шаге результат отличается от описанного — **остановитесь** и
разберитесь (раздел «Решение проблем» в конце), не идите дальше «на авось».

## 0. Как всё устроено

```
Покупатель (браузер)
      │  https://dianthus-opt.ru
      ▼
  ДОМЕН ── DNS ──►  IP-адрес вашего сервера (VPS)
                          │
        ┌─────────────────┴──────────────────────────────────┐
        │ Docker (на сервере; каждая часть — свой «контейнер») │
        │                                                     │
        │  nginx  ──►  app (FastAPI, Python)  ──►  PostgreSQL │
        │  (порты       │                           (база)    │
        │   80 и 443)   └──────────────────────►  Redis       │
        │                                  (сессии, корзины,  │
        │  certbot — продлевает HTTPS-сертификат   лимиты)    │
        └─────────────────────────────────────────────────────┘

  1С (у вас) ── HTTPS, /api/1c/... ──► тот же сайт
```

**Словарь (запомнить достаточно один раз):**

| Слово | Что это простыми словами |
|---|---|
| **Домен** | Адрес сайта словами (`dianthus-opt.ru`). Арендуется у регистратора на год |
| **DNS, A-запись** | «Телефонная книга» интернета: запись «домен → IP-адрес сервера» |
| **VPS** | Виртуальный сервер: компьютер в дата-центре, который вы арендуете помесячно и полностью контролируете (root-доступ) |
| **SSH** | Безопасный способ управлять сервером командами с вашего компьютера |
| **SSH-ключ** | Пара файлов: «замок» (публичный, лежит на сервере) и «ключ» (приватный, только у вас). Надёжнее пароля |
| **Docker, контейнер** | «Коробка» с программой и всем, что ей нужно. Сервер собирается из файлов-рецептов, а не из десятка ручных установок |
| **nginx** | Привратник: принимает запросы из интернета, отдаёт картинки, пересылает остальное приложению |
| **HTTPS, сертификат** | Шифрование (замок в браузере). Бесплатный сертификат даёт Let's Encrypt, продлевается автоматически |
| **`.env`** | Файл с настройками и паролями. **Секретный**: не отправляется в Git, права `600` |
| **Git, GitHub** | История версий кода и сайт, где она хранится. Через них код попадает с вашего компьютера на сервер |

**Три способа запуска — и зачем каждый:**

| Где | Для чего | Нужен ли Docker |
|---|---|---|
| **Ваш компьютер**, обычный Python | Разработка и проверка изменений | нет |
| Ваш компьютер, Docker (по желанию) | Проверить, что «образ» собирается и стартует | да |
| **Сервер (VPS)** | Настоящий сайт для клиентов | да (ставится скриптом) |

## 1. Что понадобится заранее

**Документы и доступы**

  идентификация через ЕСИА (закон от 29.12.2025 № 569-ФЗ). Подтвердить запись

* Почтовый ящик для сайта (например, на Яндексе) — через него сайт будет слать
  письма о заказах и заявках (раздел 13).
* Аккаунт на [GitHub](https://github.com) (в нём уже лежит код).

**Программы на компьютере (Windows 10/11)** — все бесплатные:

| Программа | Зачем | Откуда |
|---|---|---|
| **Git** | история версий, отправка кода | [git-scm.com](https://git-scm.com/download/win) |
| **Python 3.12 или новее** | запуск проекта и тестов | [python.org](https://www.python.org/downloads/) (при установке поставьте галочку **Add python.exe to PATH**) |
| **VS Code** | редактор кода | [code.visualstudio.com](https://code.visualstudio.com/) |
| **OpenSSH-клиент** | подключение к серверу | уже есть в Windows 10/11 (проверка: `ssh -V` в PowerShell) |

**Время:** первый раз закладывайте 3–5 часов, большая часть — ожидание регистрации

## 2. Проект на вашем компьютере

Цель: увидеть сайт у себя на `http://127.0.0.1:8000`, запустить тесты и
научиться вносить изменения. Это **безопасно**: боевой сайт не затрагивается.

### 2.1. Получить код

Если папка проекта уже есть (`D:\Down\21school\dianthus`) — пропустите.
Иначе (PowerShell):

```powershell
cd D:\
git clone https://github.com/Kirill010/dianthus.git
cd dianthus
```

### 2.2. Виртуальное окружение и зависимости

«Виртуальное окружение» — отдельная папка `.venv` с пакетами проекта, чтобы они
не смешивались с другими программами.

**Windows (PowerShell):**

```powershell
cd D:\Down\21school\dianthus
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
```

Если PowerShell отвечает, что «выполнение сценариев отключено», выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и повторите активацию.

**macOS / Linux:**

```bash
cd dianthus
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
```

✅ **Проверка:** в начале строки появился `(.venv)`, а `pip list` показывает
`fastapi`, `SQLAlchemy`, `pytest`.

### 2.3. Настройки

```powershell
# Копируем шаблон, только если .env ещё нет (Copy-Item перезаписывает файл молча!)
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

macOS/Linux: `[ -f .env ] || cp .env.example .env`.

Файл `.env.example` уже настроен для разработки (SQLite — файл-база, без
Redis и без HTTPS). Менять ничего не нужно. Вход админа:
`admin@example.ru` / `Admin12345`.

> ⚠️ **Если `.env` у вас уже есть** (например, с боевыми настройками: `ENV=prod`,
> пароли, SMTP), **не перезаписывайте его**. В режиме `ENV=prod` вход на
> `http://127.0.0.1` не работает (cookie только по HTTPS), а письма уходили бы
> настоящим адресам. Переименуйте его: `Rename-Item .env .env.server` (и храните
> как резервную копию — файл по-прежнему не должен попадать в Git), затем
> скопируйте шаблон командой выше.

### 2.4. Демо-данные

```powershell
python seed_demo.py
```

Создаются 12 товаров с картинками-заглушками, 3 товара «в пути» (для
предзаказов), клиент `client@example.ru` / `Client12345` и тестовый заказ.
На боевой базе (`ENV=prod`) скрипт откажется работать.

### 2.5. Запуск

```powershell

```

Откройте <http://127.0.0.1:8000>. Остановка — `Ctrl+C`.
Сервер сам перезапускается при сохранении файлов.

✅ **Проверка:** виден лендинг «Свежие цветы оптом»; вход админом открывает
каталог; в шапке есть шестерёнка «Админка».

### 2.6. Тесты

```powershell
pytest -q
```

Ожидается: все тесты `passed` (на момент написания — 128; число растёт по мере доработок). Тесты используют
временную базу в памяти — ваши данные не затрагиваются, письма не отправляются.

> **Правило:** перед каждой выкладкой на сервер — `pytest -q` без ошибок.

### 2.7. Устройство проекта: что где лежит

```
app/
├── main.py            точка входа: собирает приложение, обработчики ошибок, /health, /sitemap.xml
├── config.py          все настройки (из .env) с проверками
├── models.py          таблицы базы: User, Product, Supply, SupplyItem, Order…
├── database.py        подключение к базе (SQLite или PostgreSQL)
├── migrations.py      автоматически добавляет новые колонки/индексы при запуске
├── auth.py            регистрация, вход (2FA), выход
├── session.py         сессии в Redis (корзина лежит в сессии)
├── security.py        CSRF-защита, лимиты запросов, блокировка входа
├── middleware.py      заголовки безопасности и CSP
├── routers/
│   ├── catalog.py     каталог и карточка товара
│   ├── cart.py        корзина, оформление заказа, предзаказы, PDF-счёт
│   ├── profile.py     профиль, смена пароля, 2FA, уведомления, контакты
│   ├── admin.py       админка: заказы, клиенты, товары, поставки, журнал
│   └── integration_1c.py   обмен с 1С
├── services/          «бизнес-логика»: orders.py (статусы, склад), notifier.py (письма),
│                      pricing.py (деньги), excel_service.py, pdf_service.py…
├── templates/         HTML-страницы (Jinja2 + Bootstrap)
└── static/            стили, логотип, загруженные фото (uploads/)
tests/                 автотесты (pytest)
scripts/               служебные: подготовка сервера, бэкапы, обновление, проверка 1С
nginx/                 настройки nginx (HTTP и HTTPS)
docs/                  эта инструкция и описание обмена с 1С
```

**Как идёт запрос** (на примере «клиент добавил товар в корзину»): браузер →
nginx → `routers/cart.py::add_to_cart` → проверка CSRF-токена → чтение товара
из базы → запись в сессию (`security`/`session.py`) → редирект обратно.

### 2.8. Как внести изменение: пример «страница О компании»

1. **Создайте ветку** (так безопаснее — `main` остаётся рабочим):

   ```powershell
   git checkout -b about-page
   ```

2. **Маршрут.** В `app/routers/profile.py` (рядом с «Контактами») добавьте:

   ```python
   @router.get("/about", response_class=HTMLResponse)
   def about_page(request: Request, db: Session = Depends(get_db)):
       return render(request, "about.html", db)
   ```

3. **Шаблон** `app/templates/about.html`:

   ```html
   {% extends "base.html" %}
   {% block content %}
   <h1 class="catalog-title">О компании</h1>
   <p>{{ config.SHOP_NAME }} — оптовые поставки цветов.</p>
   {% endblock %}
   ```

4. **Тест** (в `tests/test_improvements.py` или новый файл):

   ```python
   def test_about_page(web):
       r = web.get("/about")
       assert r.status_code == 200 and "О компании" in r.text
   ```

5. Запустите `python run.py`, откройте `/about`, затем `pytest -q`.
6. **Сохраните и отправьте на GitHub:**

   ```powershell
   git add -A
   git status                       # убедитесь, что в списке НЕТ .env, *.db, backups
   git commit -m "Страница О компании"
   git push -u origin about-page
   ```

   Затем на GitHub нажмите «Compare & pull request» → «Merge». После слияния
   код в `main` готов к выкладке (раздел 16).

**Если добавляете колонку в таблицу:** допишите поле в класс в `models.py` **и**
строку в `EXPECTED_COLUMNS` в `migrations.py` — при следующем запуске колонка
добавится в существующую базу автоматически (данные не теряются).

### 2.9. Запуск образа Docker на своём компьютере (необязательно)

Если установлен Docker Desktop, можно проверить, что образ собирается и

### 2.10. Частые проблемы разработки

| Симптом | Решение |
|---|---|
| `python` не найден | Переустановите Python с галочкой «Add to PATH» или запускайте `py -m venv .venv` |
| `ModuleNotFoundError` | Не активировано окружение: `.\.venv\Scripts\Activate.ps1`, затем `pip install -r requirements-dev.txt` |
| Страница без стилей | Нет `app/static/vendor/…` — они лежат в Git; выполните `git status`, при необходимости `python scripts/download_vendor.py` |
| «Ошибка CSRF-токена» при входе | Откройте именно `http://127.0.0.1:8000` (а не по IP из сети) и обновите страницу |
| Забыли пароль админа локально | `python scripts/set_password.py admin@example.ru НовыйПароль1` |
| Хочу чистую базу | Остановите сервер, удалите `dianthus.db*`, снова `python seed_demo.py --force` |

## 3. Покупка домена

**Домен** — это аренда имени на год с автопродлением. Вы покупаете его **у
регистратора** (аккредитованной компании). Для зоны `.ru` это, например:
REG.RU, RU-CENTER (nic.ru), Timeweb, Beget, 2Domains и др. Цены у всех
сравнимы и небольшие — смотрите на сайтах регистраторов; продлевается домен
каждый год, поэтому **включите автопродление и следите за картой**.

> Ваш домен **dianthus-opt.ru** уже зарегистрирован. Этот раздел — для случая,
> когда вы начинаете полностью заново или берёте второй домен (например,
> тестовый).

**Пошагово (у любого регистратора порядок примерно одинаков):**

1. Зарегистрируйтесь в личном кабинете регистратора (email + телефон).
2. В поиске доменов введите имя (`dianthus-opt`), выберите зону `.ru`. Если имя
   занято — подберите другое. Хороший домен: короткий, читается с голоса,
   без дефисов и цифр (дефис в `dianthus-opt` — компромисс).
3. Добавьте в корзину. **Не покупайте лишнее**: «SSL-сертификат», «хостинг»,
   «конструктор сайтов», «защита от спама» — вам это не нужно (сертификат
   бесплатный, сервер вы берёте отдельно).
4. Выберите, на кого оформить домен: **физлицо / ИП / организация**. Для бизнеса
   — на ООО или ИП (так домен останется за компанией, а не за конкретным
   человеком). Данные должны быть настоящими: по ним проходит идентификация.
5. **Пройдите идентификацию через Госуслуги (ЕСИА)** — регистратор сам
   предложит войти через Госуслуги. Нужна **подтверждённая** учётная запись
   (разовое действие, см. раздел 1).
6. Включите **автопродление** и **скрытие данных владельца (WHOIS-приватность)**,
   если регистратор её предлагает (для физлиц данные скрыты по умолчанию).
7. Оплатите. Домен появится в личном кабинете обычно в течение нескольких
   минут. Придёт письмо — **сохраните** его (там реквизиты доступа).

✅ **Проверка:** в личном кабинете у домена статус «Делегирован»/«Активен», виден
раздел «Управление DNS» (понадобится в разделе 5).

⚠️ **Куда нельзя ошибаться:** почта, на которую оформлен личный кабинет
регистратора, должна быть вашей и надёжной — через неё восстанавливается доступ
к домену. Включите двухфакторную защиту входа в кабинет, если она есть.

## 4. Покупка сервера (VPS)

### 4.1. Что такое «подходящий» сервер

| Параметр | Минимум | Комфортно |
|---|---|---|
| Процессор | 2 ядра | 4 ядра |
| Память | **4 ГБ** | 6–8 ГБ |
| Диск | 40 ГБ SSD/NVMe | 80–100 ГБ |
| ОС | **Ubuntu 24.04 LTS** (проверенный вариант) или 26.04 LTS | — |
| Сеть | отдельный публичный IPv4, открыты порты 22, 80, 443 | — |
| Расположение | **дата-центр в России** | — |

* **Почему в России:** на сайте хранятся персональные данные (ФИО, телефоны,
  email) российских контактных лиц — по 152-ФЗ базы с ними хранят на территории
  РФ. Вопросы по закону уточните у юриста.
* **Нужен именно VPS/«облачный сервер» с root-доступом**, а не «виртуальный
  хостинг» (cPanel/ISPmanager) и не готовая панель управления: Docker на таких
  тарифах не работает.
* Лимиты памяти в `docker-compose.yml` рассчитаны на **4 ГБ**. На сервере с 2 ГБ
  поставьте в `.env` `WEB_CONCURRENCY=1` и уменьшите лимиты в compose (раздел 10);
  на 6 ГБ и больше — можно `WEB_CONCURRENCY=4`.
* Версия Ubuntu: берите **24.04 LTS** (поддержка до 2029 года, всё в этой
  инструкции проверено именно под неё). Версия 26.04 LTS (вышла в апреле 2026)
  тоже подходит — Docker её поддерживает, — но у неё меньше «наработанного опыта».
  Не берите 22.04 и промежуточные (25.x) версии.

### 4.2. Где брать

Крупные российские провайдеры облачных серверов: **REG.RU (облачные серверы)**,
**Timeweb Cloud**, **Selectel**, **Beget**, **Yandex Cloud**, **VK Cloud**,
**Cloud.ru** и др. Для проекта такого размера подойдёт любой. Что сравнивать:

* есть ли образ **Ubuntu 24.04** и возможность **добавить SSH-ключ при создании**;
* есть ли **снимки/резервные копии диска** (дополнительная страховка к нашим бэкапам);
* как платить (для организаций — счёт и закрывающие документы);
* поддержка отвечает на русском, есть консоль «как с монитором», если вы заперли
  себя на сервере.

Если вы уже арендовали сервер у REG.RU — используйте его; все шаги ниже одинаковы.

### 4.3. Как купить (порядок действий)

Интерфейсы провайдеров меняются, поэтому — общий порядок:

1. Зарегистрируйтесь у провайдера, пополните счёт или привяжите карту.
2. «Создать облачный сервер / VPS».
3. **Образ:** Ubuntu 24.04 LTS (чистая, **без** панелей и «приложений»).
4. **Тариф:** по таблице выше (4 ядра / 4 ГБ / 80 ГБ — хороший старт).
5. **Регион:** Москва или ближайший российский дата-центр.
6. **SSH-ключ:** если форма предлагает — вставьте **публичный** ключ (как его
   создать — раздел 6.1). Если не предлагает — будет пароль root.
7. Название — любое (`dianthus-prod`). Создать.
8. Через 1–5 минут сервер запустится. **Запишите:** публичный **IPv4-адрес** и
   пароль root (если выдан) — в менеджер паролей.

✅ **Проверка:** в панели у сервера статус «Работает/Active», виден IP вида
`203.0.113.25` (у вас будет другой).

⚠️ Не создавайте и не пользуйтесь IPv6-адресом для сайта: наш nginx слушает
только IPv4, а запись `AAAA` в DNS помешает выпуску сертификата (раздел 5).

## 5. Привязка домена к серверу (DNS)

**Зачем:** чтобы запрос на `dianthus-opt.ru` приходил на ваш сервер.

1. Откройте у регистратора **«Управление DNS»** вашего домена.
2. **Удалите** записи, которые регистратор создаёт по умолчанию («парковка»,
   чужие `A`, любые `AAAA`).
3. Добавьте две записи:

   | Тип | Имя (поддомен) | Значение | TTL |
   |---|---|---|---|
   | `A` | `@` (или пусто / `dianthus-opt.ru`) | **IP вашего сервера** | 300 |
   | `A` | `www` | **IP вашего сервера** | 300 |

   TTL 300 (5 минут) — запись быстрее обновится, если придётся менять IP.
4. Сохраните. Обновление занимает от нескольких минут до пары часов.

✅ **Проверка** (на вашем компьютере, PowerShell или любой терминал):

```powershell
nslookup dianthus-opt.ru
nslookup www.dianthus-opt.ru
```

В ответе в блоке «Address» должен быть **IP вашего сервера**. Пока там старый
IP или «не существует» — подождите и повторите (не чаще раза в несколько минут).

Если вы подключали домен к конструктору/парковке регистратора — отключите её,
иначе записи будут перезаписываться.

**Почту на этом домене** (если нужна адреса вида `shop@dianthus-opt.ru`)
настраивайте отдельным сервисом (Яндекс 360, Mail для бизнеса) — он потребует
добавить свои `MX`/`TXT`-записи в этот же раздел DNS. На сайт они не влияют.

## 6. Первое подключение к серверу (SSH)

### 6.1. Создайте SSH-ключ на своём компьютере

PowerShell (Windows 10/11; на macOS/Linux — то же в терминале):

```powershell
ssh-keygen -t ed25519 -C "dianthus-server"
```

На вопросы жмите Enter. Придумать **парольную фразу** для ключа — разумно: она
защитит ключ, если украдут компьютер (её придётся вводить при подключении).

Посмотрите публичный ключ (одна строка, начинается с `ssh-ed25519`):

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

macOS/Linux: `cat ~/.ssh/id_ed25519.pub`.

> **Приватный** ключ (`id_ed25519` без `.pub`) **никому не отправляйте** и не
> загружайте никуда. Резервную копию храните в защищённом месте.

Если форма создания сервера просила ключ — вставьте туда строку из этого файла.

### 6.2. Подключитесь

```powershell
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

Первый раз появится вопрос `Are you sure you want to continue connecting` —
ответьте `yes`. Если ключ не был добавлен при создании — введите пароль root из
письма/панели (при вводе символы не отображаются). Приглашение сменится на
`root@…:~#`.

Если ключ при создании **не** добавили, добавьте его сейчас (одной вставкой, на
сервере; подставьте вашу строку ключа целиком):

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAA...ВАШ_КЛЮЧ... dianthus-server' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

Затем `exit`, и снова `ssh root@IP` — теперь пароль не должен запрашиваться.

✅ **Проверка:** вход по ключу без пароля работает.

## 7. Настройка сервера

Скрипты делают всё за вас: обновляют систему, создают пользователя, ставят
Docker, включают файрвол и защиту от подбора паролей.

### 7.1. Скопируйте скрипты на сервер

На **вашем компьютере**, в папке проекта:

```powershell
scp scripts/server-setup.sh scripts/harden-ssh.sh root@IP_СЕРВЕРА:/root/
```

### 7.2. Запустите настройку

На **сервере** под `root`:

```bash
bash /root/server-setup.sh
```

Занимает 2–6 минут. Что делает:

1. обновляет систему и включает **автоматические обновления безопасности**;
2. ставит часовой пояс Москвы (логи и ночной бэкап — по местному времени);
3. создаёт пользователя **`deploy`** (работа от `root` в обычной жизни — плохая
   привычка), даёт ему sudo без пароля (пароля у него нет — вход только по
   ключу) и переносит ему ваши SSH-ключи;
4. ставит **Docker** (если официальный репозиторий недоступен — из репозитория
   Ubuntu);
5. включает **файрвол** `ufw`: открыты только порты 22 (SSH), 80, 443;
6. ставит **fail2ban** (банит IP, подбирающие пароль SSH) и **swap** 4 ГБ.

✅ **Проверка:** в конце видны версии `Docker` и `Docker Compose` и статус
файрвола `active`.

### 7.3. Проверьте вход под `deploy` — в НОВОМ окне терминала

```powershell
ssh deploy@IP_СЕРВЕРА
```

Должны войти **без пароля**. Не закрывайте окно с `root`, пока это не получилось.

### 7.4. Запретите вход по паролю и вход под root

В окне **deploy**:

```bash
sudo bash /root/harden-ssh.sh
```

Введите `yes`. Скрипт отключит вход по паролю и вход под `root`.

✅ **Проверка:** откройте ещё одно окно: `ssh deploy@IP` — работает;
`ssh root@IP` — **Permission denied** (так и должно быть).

> ⚠️ **Если не получилось войти под `deploy` — НЕ запускайте `harden-ssh.sh`**:
> вы заперли бы себя на сервере (у провайдера есть консоль для спасения, но лучше
> до этого не доводить).

### 7.5. Если Docker Hub недоступен с вашего сервера

Проверьте (под `deploy`):

```bash
docker pull hello-world
```

Если пишет `timeout`/`403 Forbidden` — Docker Hub (где лежат базовые образы)
недоступен с вашего хостинга. Решение — **зеркало**:

```bash
sudo nano /etc/docker/daemon.json
```

Приведите файл к такому виду (сохранив существующие настройки логов):

```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "5" },
  "registry-mirrors": ["https://dockerhub.timeweb.cloud"]
}
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`), затем `sudo systemctl restart docker` и
снова `docker pull hello-world`. Список рабочих зеркал меняется — проверьте
актуальные адреса в документации вашего провайдера. Если недоступен PyPI (при
сборке `pip` не может скачать пакеты) — в `.env` можно задать
`PIP_INDEX_URL=https://адрес-зеркала/simple`.

## 8. Проект на сервер

Код попадает на сервер через **GitHub**: вы отправляете изменения с компьютера
(`git push`), а на сервере делаете `git pull`.

### 8.1. Убедитесь, что на GitHub лежит актуальный код

На вашем компьютере (раздел 2.8, шаг 6):

```powershell
git status          # в списке НЕ должно быть .env, *.db, backups/
git add -A
git commit -m "Подготовка к выкладке"
git push
```

> Репозиторий лучше сделать **приватным** (GitHub → Settings → General → Danger
> Zone → Change visibility): в коде есть контакты, названия и порядок работы.
> Тогда серверу нужен «ключ развёртывания» (п. 8.3).

### 8.2. Публичный репозиторий

```bash
sudo mkdir -p /opt/dianthus && sudo chown deploy:deploy /opt/dianthus
git clone https://github.com/Kirill010/dianthus.git /opt/dianthus
cd /opt/dianthus && ls
```

### 8.3. Приватный репозиторий (ключ развёртывания, только чтение)

```bash
ssh-keygen -t ed25519 -f ~/.ssh/dianthus_deploy -N "" -C "dianthus-server"
cat ~/.ssh/dianthus_deploy.pub
```

Скопируйте выведенную строку → GitHub → репозиторий → **Settings → Deploy keys →
Add deploy key** (название `server`, **«Allow write access» не включать**) → Add.

Затем на сервере:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/dianthus_deploy
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config
sudo mkdir -p /opt/dianthus && sudo chown deploy:deploy /opt/dianthus
git clone git@github.com:Kirill010/dianthus.git /opt/dianthus
```

На вопрос про подлинность `github.com` ответьте `yes`.

✅ **Проверка:** `cd /opt/dianthus && ls` показывает `Dockerfile`,
`docker-compose.yml`, `app`, `nginx`, `scripts`, `docs`.

## 9. Настройки сайта (`.env`)

Все пароли и настройки — в одном файле `.env`, который скрипт создаёт сам со
**случайными** паролями:

```bash
cd /opt/dianthus
bash scripts/prepare.sh dianthus-opt.ru admin@dianthus-opt.ru
```

Вместо `admin@dianthus-opt.ru` укажите **реальный email** администратора сайта.
Скрипт **один раз покажет** пароль админа — **сразу запишите его в менеджер
паролей** (он же лежит в `.env`). Для 1С пароль не нужен: ключ доступа вы
создадите в админке сами (раздел 14).

Затем откройте файл и заполните остальное:

```bash
nano .env
```

| Что | Где | Комментарий |
|---|---|---|
| Контакты магазина | `SHOP_NAME`, `SHOP_PHONE`, `SHOP_ADDRESS`, `SHOP_EMAIL`, `SHOP_WORKING_HOURS`, `SHOP_MAX_LINK`, `SHOP_MAP_URL` | показываются на странице «Контакты», в письмах, в политике конфиденциальности. **По умолчанию подставлены данные из репозитория — замените на свои** |
| Реквизиты организации (для юридических текстов, подвала и счёта) | `SHOP_INN`, `SHOP_OGRN`, `SHOP_LEGAL_ADDRESS`, `SHOP_PD_RESPONSIBLE`, `SHOP_VAT_NOTE` | **заполните до запуска**, иначе в политике и согласии будет видно `[укажите: ИНН]`. `SHOP_PD_RESPONSIBLE` — кто отвечает за персональные данные («Иванов И. И., директор»). `SHOP_VAT_NOTE` — строка про НДС в счёте (спросите бухгалтера) |
| Условия оплаты и сроки | `SHOP_PAYMENT_TERMS`, `PREORDER_LEAD_DAYS` | значения по умолчанию; потом меняются в админке: ⚙ → «Настройки» |
| Реквизиты для счёта | `SHOP_REQUISITES` | строки через `\|`: `ИНН … \| КПП … \| р/с … \| БИК … \| Банк «…»` — печатаются в PDF-счёте |
| Почта | `SMTP_*` | раздел 13 |
| Часовой пояс | `SHOP_TZ=Europe/Moscow` | время заказов клиентам и менеджерам |
| Мощность | `WEB_CONCURRENCY` | число процессов; по умолчанию 2 (сервер 4 ГБ) |

Сохранить в `nano`: `Ctrl+O`, `Enter`, `Ctrl+X`.

✅ **Проверка:** `ls -l .env` показывает права `-rw-------` (600), а
`git status` **не** показывает `.env` (он в `.gitignore`).

> 🔐 **Правила обращения с `.env`:** не пересылайте его в мессенджерах и
> почте; не публикуйте в Git; храните копию в менеджере паролей. Если файл или
> пароли когда-либо попадали в публичное место — считайте их скомпрометированными
> и замените (удалите `.env`, запустите `prepare.sh` заново; для почты —
> перевыпустите «пароль приложения»).

## 10. Первый запуск

```bash
cd /opt/dianthus
docker compose build
```

Первая сборка занимает 3–8 минут (скачиваются образы и пакеты). В конце — без
слова `ERROR`. Если упало — смотрите «Решение проблем» (раздел 19), сборку можно
безопасно повторить.

```bash
docker compose up -d
docker compose ps
```

✅ **Проверка:** все пять сервисов `Up`, у `db`, `redis`, `app` статус `(healthy)`
(для `app` подождите 1–2 минуты). Если что-то `unhealthy` — `docker compose logs <имя> --tail=50`.

Журнал приложения:

```bash
docker compose logs app --tail=60
```

Ищите строки `Схема БД готова`, `Создан админ: …` и `🌸 Диантус готов (prod)` и
отсутствие `ERROR`/`Traceback`.

Проверка ответа сайта (с самого сервера):

```bash
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: dianthus-opt.ru" http://127.0.0.1/login
```

Ожидается `200`.

**Проверка поиска по русским названиям** (один раз):

```bash
docker compose logs app | grep -i "регистр кириллицы" || echo "ОК: поиск по кириллице работает"
```

Если вывелась ошибка про регистр — PostgreSQL создан с локалью, не различающей
регистр русских букв. На **только что созданной (пустой) установке** исправьте:
в `docker-compose.yml` замените `postgres:16-alpine` на `postgres:16`, затем
`docker compose down -v` (⚠️ удаляет данные — допустимо только пока их нет) и
`docker compose up -d --build`.

> Войти в админку по `http://IP` не получится — это защита: cookie сессии в
> боевом режиме работает только по HTTPS. Вход заработает после раздела 11.

**Если сервер слабее 4 ГБ:** в `.env` добавьте `WEB_CONCURRENCY=1`, в
`docker-compose.yml` уменьшите `mem_limit`: `db` → `512m`, `app` → `768m`, и в
`command` у `db` — `shared_buffers=128MB`. Затем `docker compose up -d`.

## 11. HTTPS

**Условие:** DNS уже указывает на сервер (раздел 5) — проверьте
`nslookup dianthus-opt.ru` (должен показать IP сервера).

```bash
cd /opt/dianthus
bash scripts/init-ssl.sh admin@dianthus-opt.ru
```

Скрипт сам: проверит DNS, получит бесплатный сертификат Let's Encrypt, включит
HTTPS-конфиг nginx (при ошибке в конфиге вернёт прежний). Email нужен
Let's Encrypt для уведомлений.

✅ **Ожидаемый финал:** `✅ HTTPS включён: https://dianthus-opt.ru`.
Откройте <https://dianthus-opt.ru> — замок в адресной строке; `http://` должен
перенаправлять на `https://`, а `www.` — на основной адрес.

**Продление автоматическое:** контейнер `certbot` проверяет сертификат дважды в
сутки и обновляет его заранее (Let's Encrypt постепенно сокращает срок
сертификатов до 64, а затем 45 дней — это учтено, ничего менять не нужно).
Проверить продление «вхолостую»:

```bash
docker compose run --rm --entrypoint certbot certbot renew --dry-run
```

| Если | То |
|---|---|
| `challenge failed` | DNS ещё не обновился, закрыт порт 80, либо у домена остались `AAAA`-записи. Исправьте и повторите (не чаще 5 раз в час) |
| В браузере «не защищено» | сертификат ещё не выпущен: повторите шаг; проверьте `docker compose logs nginx --tail=30` |

## 12. Первые шаги в админке

1. Откройте <https://dianthus-opt.ru/login>, войдите как админ (email и пароль из
   шага 9).
2. **Смените пароль:** шестерёнка → «Профиль» → «Смена пароля» (придумайте свой,
   длинный; сохраните в менеджере паролей).
3. **Включите 2FA** (двухфакторная защита) — «Профиль» → «Двухфакторная
   аутентификация» → «Включить»: отсканируйте QR в приложении
   (Яндекс Ключ, Google Authenticator), введите первый код. **Это самая
   дешёвая и эффективная защита админки.** Сохраните резервные способы
   восстановления кодов в приложении.
4. **Уберите пароль админа из `.env`** (он нужен был только для первого
   создания учётной записи):

   ```bash
   cd /opt/dianthus && nano .env      # удалите строку ADMIN_PASSWORD=...
   docker compose up -d
   ```

5. **Наполните каталог** (три способа, выбирайте один):
   * **вручную:** Админка → «Справочник» → «Добавить» (товар) → «Поставки» →
     «Новая поставка» → добавить позиции → **«Разгрузить»**: товары появляются в
     каталоге. («Разгрузка» заменяет прошлую партию: старые ручные партии
     снимаются с полок);
   * **из Excel:** «Справочник» → «Шаблон» → заполнить → «Импорт» (повторный
     импорт обновляет, а не дублирует), затем накладная в поставке;
   * **из 1С:** раздел 14.
6. **Проверьте сайт глазами клиента** (в другом браузере или режиме инкогнито):
   «Стать оптовиком» → заполните форму (нужна галочка согласия на обработку
   персональных данных) → в админке «Клиенты» → **«Одобрить»** → клиент получит
   письмо → войдите им → добавьте товар в корзину → оформите заказ.
7. Проверьте, что: заказ виден в админке; **PDF-счёт** скачивается и в нём русские
   буквы; приходят письма (раздел 13); смена статуса заказа оповещает клиента;
   **отмена заказа возвращает товар** на склад.
8. **Юридическая часть** — шестерёнка → **«Юридическое»**. Там тексты политики,
   согласия на данные, согласия на рекламу и условий работы (`/privacy`,
   `/consent`, `/marketing-consent`, `/terms`) и список дел с отметками. Тексты —
   **черновики**: впишите реквизиты (`SHOP_*` в `.env`), покажите юристу, поправьте
   через «Править» и отметьте «проверен юристом». Что ещё надо сделать (уведомление
   Роскомнадзора, приказ об ответственном, серверы в РФ…) — `docs/LEGAL_CHECKLIST.md`.
9. **Настройки магазина** — шестерёнка → **«Настройки»**: условия оплаты и сроки
   заказа по странам (правят страницу «Сроки заказа» для клиентов).
10. **Сотрудники.** Менеджеру не нужен пароль владельца: попросите его
    зарегистрироваться как клиента, откройте его в «Клиентах» → **«Сделать менеджером»**.
    Менеджер ведёт заказы, клиентов и рекламации, но не видит выручку, каталог,
    ключи 1С и юридические тексты. Памятка на каждый день — `docs/ВЛАДЕЛЬЦУ.md`.
11. **«Что сделать сегодня»** — на главной странице админки: новые и срочные заказы,
    заявки клиентов, рекламации, запросы на удаление данных. Заходите сюда первой.

Журнал действий администраторов — кнопка «Журнал действий» в админке
(`/admin/audit`): кто менял скидки, статусы, товары.

## 13. Почта

Сайт отправляет письма: администратору (новый заказ, новая заявка) и клиентам
(заявка одобрена, заказ принят, смена статуса).

Настройки в `.env`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USE_SSL=true
SMTP_USER=shop@yandex.ru            # полный адрес ящика-отправителя
SMTP_PASSWORD=пароль_приложения     # НЕ пароль от ящика
SMTP_FROM=shop@yandex.ru            # у Яндекса должен совпадать с SMTP_USER
SMTP_TO=boss@yandex.ru,manager@yandex.ru   # кому слать уведомления админам
```

**Пароль приложения (Яндекс):** Яндекс ID → «Безопасность» → «Пароли
приложений» → создать для «Почта» → скопировать в `SMTP_PASSWORD`. В настройках
почты должен быть разрешён доступ почтовых клиентов. После правки `.env`:
`docker compose up -d`.

✅ **Проверка:** оформите тестовый заказ — письмо приходит на адреса из
`SMTP_TO`; одобрите тестового клиента — письмо уходит ему. Ошибки отправки —
в `docker compose logs app | grep -i smtp`.

**Чтобы письма клиентам не попадали в «Спам»:**

* отправляйте с **ящика на вашем домене** (Яндекс 360 / Mail для бизнеса) и
  добавьте в DNS записи **SPF, DKIM, DMARC**, которые выдаст почтовый сервис;
* у бесплатных ящиков есть суточные лимиты на отправку — для десятков писем в
  день достаточно.

## 14. Обмен с 1С

Подробный справочник — **[docs/1C_INTEGRATION.md](1C_INTEGRATION.md)**; готовая
памятка для программиста — **[docs/1C_PROGRAMMER_BRIEF.md](1C_PROGRAMMER_BRIEF.md)**
(она же открыта на сайте по адресу `/1c-docs`).

**Пароль в `.env` больше не нужен.** 1С входит на сайт по **ключу доступа**:

1. Админка → кнопка **«Интеграция с 1С»**. В поле «Название (кому выдаёте)» впишите,
   например, «Программист Иван», нажмите **«Создать ключ»**. Ключ выглядит как
   `dnt_…` и **показывается один раз** — нажмите «Скопировать» и сохраните его в
   менеджер паролей. В базе хранится только «отпечаток» ключа: если потеряете,
   создайте новый, а старый отключите.
2. Сразу после создания появится «Готовое сообщение для программиста 1С (уже с
   ключом)». Нажмите **«Скопировать сообщение»** и отправьте программисту
   **личным сообщением** (не в общий чат и не на публичную почту). В сообщении уже
   есть адрес сайта, ключ и ссылка на памятку `https://ваш-домен/1c-docs`.
3. Если у сервера 1С постоянный адрес (IP), впишите его в поле «Адреса, с которых
   можно» — ключ заработает только оттуда. Не уверены — оставьте пустым.
4. Вверху той же страницы видно, **работает ли обмен**: «Обмен работает» / «1С давно
   не обращалась к сайту» / «Последнее обращение 1С завершилось ошибкой», а ниже —
   журнал последних обращений с причинами отказов (неверный ключ, не тот адрес,
   неверные данные). Кнопка «Отключить» у ключа мгновенно закрывает доступ.
5. Проверка связи с любого компьютера:

   ```bash
   python scripts/onec_smoke_test.py https://dianthus-opt.ru dnt_ВАШ_КЛЮЧ
   ```

6. **Нет программиста 1С?** Откройте **[docs/1C_ПОШАГОВО.md](1C_ПОШАГОВО.md)**: там, как самому
   создать файл-«курьера» для 1С и вести обмен (каталог, инвойсы «в пути», заказы) через его меню.
   Любую загрузку на сайт сначала делайте с галочкой **«Только проверить»** (или `?dry_run=1`
   в запросе): сайт покажет, что изменится, и ничего не сохранит.
7. Если 1С старая, обмен можно вести **файлами**: в админке
   «Интеграция» → загрузить прайс-лист из Excel/CSV и скачать новые заказы для
   загрузки в 1С.
8. 1С по расписанию (каждые 10–15 минут): **забирает новые заказы → подтверждает →
   присылает остатки → присылает статусы**. Раз в сутки — «полный снимок».
9. Прежде чем включать обмен остатками, снимите с полок ручные поставки
   (иначе товары будут видны дважды) — подробности в документе по 1С.
10. Облако 1С — это тоже «обработчик» данных ваших клиентов: убедитесь, что оно
   в России, и добавьте в договор условие о защите данных (образец —
   `docs/legal/processor_clause.md`).

## 15. Резервные копии

**База и фото живут отдельно от кода** — их надо копировать. Копия на том же
сервере не спасёт, если сервер потеряется или будет взломан: нужна ещё и копия
**на другом компьютере/сервере**.

```bash
cd /opt/dianthus
bash scripts/backup.sh
ls -lh backups/
```

Создаются `db-…sql.gz` (база) и `uploads-…tar.gz` (фото); хранятся 14 дней.

**Автоматически каждую ночь** (под пользователем `deploy`):

```bash
crontab -e
```

(выберите `nano`) и добавьте в конец строку:

```
15 3 * * * cd /opt/dianthus && bash scripts/backup.sh >> /opt/dianthus/backups/backup.log 2>&1
```

**Копия на другой сервер автоматически:** на втором сервере создайте
пользователя и папку, добавьте ваш SSH-ключ, затем в `.env` на основном:
`BACKUP_REMOTE=backup@другой-сервер:/srv/dianthus-backups` — скрипт сам
отправит свежие файлы после каждого бэкапа (нужен `rsync`, он ставится
`server-setup.sh`). Либо раз в неделю забирайте вручную:

```powershell
scp -r deploy@IP_СЕРВЕРА:/opt/dianthus/backups D:\dianthus-backups
```

**Проверьте, что бэкап восстанавливается** — хотя бы раз, на тестовом сервере:

```bash
bash scripts/restore-db.sh backups/db-ГГГГММДД-ЧЧММСС.sql.gz     # спросит yes; заменит данные!
docker compose up -d
bash scripts/restore-uploads.sh backups/uploads-ГГГГММДД-ЧЧММСС.tar.gz
```

Бэкап, который ни разу не восстанавливали, — это надежда, а не бэкап.

## 16. Обновление сайта и откат

**Обновление** (после того, как изменения слиты в `main` на GitHub):

```bash
cd /opt/dianthus
bash scripts/update.sh
```

Скрипт: делает бэкап → `git pull` → пересобирает и перезапускает контейнеры →
обновляет конфиг nginx (если он менялся; с проверкой и откатом) → ждёт, пока
приложение станет `healthy`. Простой сайта — несколько секунд. Схема базы
доводится **автоматически** (только добавляются колонки и индексы, данные не
затрагиваются).

**Откат на прошлую версию кода:**

```bash
cd /opt/dianthus
git log --oneline | head           # найдите хеш рабочей версии
git checkout ХЕШ
docker compose up -d --build
# вернуться на свежую:  git checkout main && bash scripts/update.sh
```

Поскольку миграции только добавляют колонки, старый код работает и на новой
схеме. Если сломались **данные** — восстановление из бэкапа (раздел 15).

**Регулярное обслуживание (раз в месяц):**

```bash
sudo apt update && sudo apt upgrade -y      # система
bash scripts/update.sh                      # свежие образы Docker и код
df -h && free -h                            # диск и память
```

После обновления ядра система может попросить перезагрузку: `sudo reboot`.
Контейнеры поднимутся сами (`restart: unless-stopped`); сессии клиентов и
корзины сохранятся (Redis пишет журнал на диск).

## 17. Мониторинг

* **Доступность снаружи:** заведите бесплатный монитор (UptimeRobot, Better
  Stack или свой Uptime Kuma) на `https://dianthus-opt.ru/login`, оповещение —
  на почту/телефон. (Адрес `/health` снаружи закрыт намеренно.)
* **Ошибки приложения:** по желанию подключите Sentry (`SENTRY_DSN` в `.env`).
* **Состояние сервера:**

  ```bash
  docker compose ps                    # все ли контейнеры живы
  docker stats --no-stream             # нагрузка по контейнерам
  free -h ; df -h                      # память и диск
  docker compose logs -f app           # журнал приложения «вживую»
  ```

  Если память стабильно > 85 % или активно растёт swap — уменьшите
  `WEB_CONCURRENCY` или возьмите сервер побольше. Диск: фото и бэкапы растут —
  следите за `df -h` и переносите старые бэкапы во внешнее хранилище.
* **Сертификат:** срок виден в браузере (замок → «Сертификат»); продлевается сам.
* **Домен:** срок продления — в кабинете регистратора. **Не допускайте
  истечения** (с 01.09.2026 для продления нужна идентификация через Госуслуги —
  пройдите её заранее).

## 19. Решение проблем

| Симптом | Что делать |
|---|---|
| `docker compose build` падает на скачивании образов (`timeout`, `403`) | Docker Hub недоступен: зеркало, п. 7.5; повторите сборку |
| сборка падает на `pip install` | недоступен PyPI: `PIP_INDEX_URL` в `.env` (п. 7.5), повторите |
| `app` в статусе `unhealthy` / перезапускается | `docker compose logs app --tail=80`. Частые причины: опечатка в `.env`; пароль в `DATABASE_URL` не совпал с `POSTGRES_PASSWORD`; база ещё не готова (подождите минуту) |
| «Ошибка CSRF-токена», вход «ничего не делает» | вы зашли по `http://` или по IP. Работает только `https://dianthus-opt.ru` (раздел 11) |
| Все получают `429 Слишком много запросов` | проверьте `docker compose logs nginx`: один IP шлёт слишком много запросов? Лимиты — в `nginx/nginx.conf` (`zone=auth` 10/мин на вход, `zone=posts` 120/мин на прочие POST) |
| `init-ssl.sh`: `challenge failed` | DNS не обновился / закрыт порт 80 / есть `AAAA`-записи. `nslookup dianthus-opt.ru` должен показать IP сервера |
| Фото товаров не видны | `docker compose exec app ls /app/app/static/uploads \| head`. После переноса — `bash scripts/restore-uploads.sh …` |
| PDF-счёт с квадратами вместо букв | `docker compose exec app ls /app/app/static/fonts` — должны быть 2 файла DejaVu; иначе `docker compose build --no-cache app && docker compose up -d` |
| Письма не приходят | `docker compose logs app \| grep -i smtp`; для Яндекса нужен **пароль приложения**; `SMTP_FROM` = `SMTP_USER` |
| Забыли пароль администратора | `docker compose exec app python -m scripts.set_password email@админа НовыйПароль1` |
| Админ заблокирован после неверных попыток | `docker compose exec app python -m scripts.reset_login_lock email@админа` |
| Нужно сделать пользователя админом | `docker compose exec app python -m scripts.make_admin email@клиента.ru` |
| Заканчивается диск | `docker system df`; `docker image prune -f`; удалите старые файлы в `backups/` |
| Сайт открывается, но стили/картинки «сломаны» | после обновления сделайте жёсткое обновление страницы `Ctrl+F5` |
| Заперли себя на сервере (SSH) | консоль «как с монитором» в панели провайдера → вход под `root`/`deploy` → правка `/etc/ssh/sshd_config.d/00-hardening.conf` |
| Нужен откат | раздел 16 |

Куда смотреть в первую очередь: `docker compose ps` → `docker compose logs app --tail=100`
→ `docker compose logs nginx --tail=50`.

## 20. Приложения

### А. Шпаргалка команд (на сервере, в `/opt/dianthus`)

| Действие | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Журнал приложения «вживую» | `docker compose logs -f app` |
| Перезапустить приложение | `docker compose restart app` |
| Обновить сайт (с бэкапом) | `bash scripts/update.sh` |
| Сделать бэкап | `bash scripts/backup.sh` |
| Зайти в базу | `docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'` |
| Нагрузка / память / диск | `docker stats --no-stream` · `free -h` · `df -h` |
| Применить изменения `.env` | `docker compose up -d` |
| Проверка 1С | `python scripts/onec_smoke_test.py https://… 1c_dianthus ПАРОЛЬ` |

### Б. Что проверено, а что нет

**Проверено (автоматически и вручную):** весь код — набором из 346 автотестов на
закреплённых версиях библиотек (`pytest`); `pip-audit` по `requirements.txt` —
«No known vulnerabilities found»; запуск приложения на пустой базе (создание
таблиц и администратора); обмен с 1С — реальными HTTP-запросами к запущенному
серверу; интерфейс — в браузере (подтверждения удаления, кнопки количества,
время по Москве, страница 404, возврат остатка при отмене заказа);
синтаксис shell-скриптов и `docker-compose.yml`.

**Не проверялось в среде автора** (там нет Docker и доступа к вашему серверу):
сборка Docker-образа, работа контейнеров вместе, конфигурация nginx «вживую»,
выпуск сертификата, подключение к вашей 1С, регистрация у конкретного
провайдера, юридическая сила текстов (они — черновики для проверки юристом). Поэтому **первая сборка на вашем сервере — настоящая проверка**; если
что-то упадёт, пришлите последние 30 строк вывода — обычно это правится в одну-две
правки.

### В. Где что лежит на сервере

| Что | Где |
|---|---|
| Код и настройки | `/opt/dianthus` (`.env` — секреты) |
| База данных | Docker-том `dianthus_postgres_data` |
| Фото товаров | Docker-том `dianthus_uploads` |
| Сессии/корзины | Docker-том `dianthus_redis_data` |
| Сертификаты | Docker-том `dianthus_letsencrypt` |
| Резервные копии | `/opt/dianthus/backups` |

> ⚠️ Команда `docker compose down -v` **удаляет все тома, то есть базу и фото**.
> Обычная остановка — `docker compose down` (без `-v`) или `docker compose stop`.
