# Обмен сайта с 1С

Руководство для владельца и для программиста 1С. Сайт предоставляет HTTP-API
(`/api/1c/...`), 1С по расписанию **сама ходит на сайт**: забирает заказы и
присылает каталог, цены, остатки и статусы. Сайт к 1С не обращается — поэтому
не нужно открывать доступ к серверу 1С из интернета.

> **Вход в обмен — по ключу.** Владелец сам создаёт ключ в админке («Интеграция»),
> отдаёт его программисту и в любой момент может отключить. Программисту подойдёт
> самодостаточная памятка `docs/1C_PROGRAMMER_BRIEF.md` (она же открыта по адресу
> `/1c-docs` на сайте). Этот документ — подробный справочник для разработчика.
> Старый вход по логину/паролю из `.env` (`INTEGRATION_PASSWORD`) продолжает работать.
>
> Всё описанное ниже проверено автотестами (`tests/test_1c_integration.py`,
> `tests/test_1c_exchange.py`) и запросами к работающему серверу. Примеры на
> языке 1С (BSL) написаны по документации платформы и **не запускались на вашей
> конфигурации** — относитесь к ним как к заготовкам.

---

## 1. Кто за что отвечает

| Данные | Главный источник | Направление |
|---|---|---|
| Номенклатура, цены, остатки | **1С** | 1С → сайт (`products/sync`) |
| Заказы клиентов | **сайт** | сайт → 1С (`orders/export`, потом `orders/ack`) |
| Статусы заказов («Подтверждён», «Отправлен»…) | **1С** (проводит документы) | 1С → сайт (`orders/status`) |
| Персональные скидки клиентов | **1С** (договоры/контрагенты) | 1С → сайт (`clients/sync`) |
| Регистрация клиентов и их одобрение | **менеджер на сайте** | 1С только читает (`clients/export`) |

Почему регистрация остаётся на сайте: клиент сам задаёт пароль, а допуск к
оптовым ценам решает менеджер. Через обмен 1С **не может** создать клиента или
выдать ему доступ — только поменять скидку.

## 2. Подготовка и проверка связи

1. Владелец: админка → **«Интеграция»** → «Создать ключ» (по желанию — список IP-адресов
   сервера 1С). Ключ выглядит как `dnt_…` и показывается один раз. Пока нет ни одного
   ключа (и не задан старый пароль) — обмен отключён, ответ `503`.
2. С любого компьютера (нужен только Python):

```bash
python scripts/onec_smoke_test.py https://dianthus-opt.ru dnt_ВАШ_КЛЮЧ
```

Скрипт проверяет ключ, связь, сертификат и показывает число товаров/заказов.
С ключом `--write` он отправляет служебный товар «ТЕСТ-ОБМЕН-1С» с нулевым
остатком (на витрине не виден, в справочнике админки — виден).

3. Запросы идут по **HTTPS**. Ключ можно передать тремя способами: заголовком
   `X-API-Key: dnt_…`, заголовком `Authorization: Bearer dnt_…` или паролем в HTTP Basic
   (логин — любой, пароль — ключ; удобно для `HTTPСоединение` 1С). Не используйте
   обмен по `http://` через интернет: ключ уйдёт открытым текстом.
4. Состояние обмена владелец видит в админке («Интеграция»): плашка «работает / не
   работает», время последней связи и загрузки каталога, журнал обращений 1С с
   объяснением ошибок на простом языке.

## 3. Рекомендуемый порядок обмена (задание по расписанию, каждые 10–15 минут)

```
1. GET  /api/1c/orders/export?new=1      забрать новые заказы
2. создать в 1С «Заказ клиента» по каждому (номер «САЙТ-<id>»), зарезервировать товар
3. POST /api/1c/orders/ack               подтвердить, что заказы получены
4. POST /api/1c/products/sync            отправить цены и остатки (уже с учётом шага 2!)
5. POST /api/1c/orders/status            сообщить новые статусы (проведён, отгружен, отменён)
```

**Почему именно в таком порядке.** Если сначала отправить остатки, а потом
забрать заказы, то заказ, оформленный клиентом между этими шагами, ещё не
вычтен из остатка 1С — выгрузка «вернёт на полку» проданные упаковки, и сайт
может продать их ещё раз. Когда заказы забираются **до** расчёта остатков и в
1С под них сделан резерв, отправляемые остатки уже честные.

Раз в сутки (ночью) полезно слать **полный снимок** (`full=1`, раздел 6), чтобы
исчезнувшие из 1С товары сняло с полок.

Скидки клиентов (`clients/sync`) — по необходимости, например, раз в сутки.

### Страховка от перепродажи (необязательная)

Если в `.env` задать `ONEC_RESERVE_UNEXPORTED=1`, то при загрузке остатков сайт
сам **вычитает** заказы, которые 1С ещё не подтвердила через `orders/ack`.
Это закрывает «окно» между шагами 1 и 4 даже тогда, когда 1С его не учитывает.
Включайте, **только если 1С действительно вызывает `orders/ack`** — иначе
подтверждения не придут, и остатки будут занижены.

## 4. Методы API

Базовый адрес: `https://ВАШ-ДОМЕН/api/1c`. Везде ключ (раздел 2, п. 3), тело — JSON в
**UTF-8** (`Content-Type: application/json; charset=utf-8`; BOM в начале допускается).
Лимит: 120 запросов в минуту с одного IP, тело запроса — до 40 МБ.

Для старых версий 1С без JSON есть таблицы **CSV**: каталог принимается как
`POST /products/sync?format=csv` (`Content-Type: text/csv`), заказы и каталог
выгружаются как `?format=csv[&encoding=cp1251]`, а подтверждения и статусы можно
слать в адресе, без тела — подробности в `docs/1C_PROGRAMMER_BRIEF.md`.

### `GET /ping` — проверка связи

```json
{"status": "ok", "service": "dianthus-1c", "env": "prod", "auth": true,
 "auth_name": "Программист Иван", "formats": ["json", "csv"],
 "server_time_utc": "2026-10-21T21:02:21+00:00", "reserve_unexported": false}
```

### `POST /products/sync` — каталог, цены, остатки (1С → сайт)

```json
{"products": [
  {"id": "00000012345", "sku": "ROSA-FREEDOM-60", "barcode": "4600000000001",
   "name": "Роза Freedom 60 см", "description": "Классическая красная роза",
   "kind": "Роза", "color": "Красный", "height": 60, "country": "Эквадор",
   "unit": "упаковка", "package_size": 25, "min_quantity": 1,
   "price_per_stem": 42.5, "stock_packs": 120, "photos": []}
 ],
 "full": false}
```

| Поле | Обязательно | Значение |
|---|---|---|
| `id` (или `external_id`, `guid`, `code`) | нет, но **очень желательно** | идентификатор товара **в 1С** (код/GUID). По нему товар сопоставляется |
| `sku` | нет | артикул |
| `barcode` | нет | штрихкод, до 64 символов; по нему товар тоже находится |
| `name` | **да** | наименование, до 200 символов (длиннее — обрезается) |
| `kind`, `color`, `height`, `country` | нет | вид, цвет, рост (число см, 10…300), страна — значения справочников (ниже) |
| `unit` | нет | единица, до 30 символов (по умолчанию «упаковка») |
| `price_per_stem` | **да** | цена за **штуку (стебель)**, ₽, 0…10 000 000 |
| `stock_packs` | одно из двух | остаток в **упаковках** |
| `stock_stems` | одно из двух | остаток в **штуках** — сайт переведёт: `stock_stems // package_size` (неполную упаковку не продаёт) |
| `package_size` | нет | штук в упаковке, 1…10 000 (0/пусто = 1) |
| `min_quantity` | нет | минимальный заказ в упаковках, 1…10 000 |
| `description` | нет | описание, до 5000 символов |
| `photos` | нет | до 20 ссылок `https://…` или `/static/…`. Ссылки на `localhost`, внутренние IP, с логином:паролем и схемами `javascript:`/`data:` отбрасываются |

**Вид, цвет, рост и страна — отдельные таблицы-справочники** (`kinds`, `colors`,
`heights`, `countries`), у каждой записи свой `id` на сайте и `external_id` из 1С.
Значение можно прислать названием (`"color": "Красный"`, `"height": 60` или `"60 см"`),
`id` на сайте (`"kind_id": 3`) или `id` в 1С (`"kind_external_id": "…"`, вместе с названием,
пока справочники не сверены). Нового значения ещё нет — оно **создаётся само** (регистр и
пробелы не важны: «красный» и «Красный » — одна запись). Прислали пустым (`""`, для роста `0`) —
значение у товара убирается; не прислали ключ — остаётся прежним. Старые имена полей
`category` (вид) и `length_cm` / `height_cm` (рост) понимаются. Справочники для чтения:
`GET /dictionaries` (ниже).

Что **не** нужно путать (иначе цены «разъедутся» в 25 раз): цена — за **штуку**,
остаток — в **упаковках** (или `stock_stems` в штуках).

Необязательные поля, которых нет в запросе, у существующего товара **не
меняются** (например, если не прислать `photos`, фото останутся).

Ответ:

```json
{"status": "ok", "processed": 2, "created": 1, "updated": 1, "deactivated": 0,
 "errors": [], "errors_total": 0, "warnings": [], "supply_id": 3,
 "dictionaries_created": {"color": ["Малиновый"], "height": ["65 см"]}}
```

`dictionaries_created` — какие значения справочников появились из этой выгрузки.

* Плохие строки **не роняют** обмен: они попадают в `errors` (первые 50;
  всего — `errors_total`), остальные загружаются.
* `warnings` — предупреждения (например, о дублях, см. раздел 8).
* Повторная отправка тех же данных безопасна (идемпотентно).
* Одновременно выполняется один обмен каталогом: параллельный запрос подождёт.

### `POST /supplies/sync` — инвойсы «в пути» (1С → сайт)

Приходные инвойсы поставщиков показываются клиентам как «Товары в пути» с предзаказом.
Формат, статусы (`in_transit` / `received` / `cancelled`) и правила описаны в
памятке программисту ([1C_PROGRAMMER_BRIEF.md](1C_PROGRAMMER_BRIEF.md), раздел 7).
Коротко:

```
POST /api/1c/supplies/sync?dry_run=1
{"supplies": [{"id": "00000622", "date": "2026-10-29", "country": "Эквадор",
               "supplier": "ECUANROS S.A", "status": "in_transit",
               "items": [{"id": "00012345", "name": "Роза Фридом 60", "package_size": 25,
                          "price_per_stem": 42.5, "quantity_stems": 3000}]}]}
```

* поставка ищется по `id` инвойса: повторная отправка обновляет, а не дублирует;
* `received` закрывает поставку и выполняет предзаказы за счёт остатков с полки
  (поэтому в каждом обмене сначала `products/sync`, потом `supplies/sync`);
* такая поставка не разгружается ни автоматически, ни вручную (в админке у неё
  значок «из 1С»); забытая 21 день — закрывается сама.

### `POST /products/photo` — фото товара (1С → сайт)

База 1С во внутренней сети, поэтому сайт сам картинку скачать не может: 1С присылает
**файл** тем же ключом. Доступ на сервер для этого не нужен. Формат, правила и пример
кода — в памятке программисту ([1C_PROGRAMMER_BRIEF.md](1C_PROGRAMMER_BRIEF.md), раздел 7).
Коротко:

```
POST /api/1c/products/photo?id=00000012345&n=1        (?dry_run=1 — проверка)
Content-Type: application/octet-stream
<тело — сама картинка: JPEG / PNG / WEBP / GIF, до 15 МБ>
```

* товар ищется как в каталоге (`id` → `barcode` → `sku` → название; можно передать `?barcode=…`) и должен
  уже быть на сайте, иначе 404;
* `n` — номер фото по порядку (1 — главное, до 10): занятый номер заменяется, следующий добавляется,
  «дыры» — ошибка 400;
* картинка проверяется по содержимому и перекодируется в WEBP не крупнее 1600×1600; прозрачный фон
  становится белым; то же фото на том же месте повторно не пишется (`unchanged`);
* не присылайте поле `photos` в каталоге для тех же товаров: оно заменит загруженные файлы.

### `POST /orders/status` — статусы заказов (1С → сайт)

```json
{"orders": [
  {"number": "САЙТ-57", "status": "Подтверждён", "onec_number": "00000000123"},
  {"number": "САЙТ-58", "status": "Отменён"}
]}
```

Допустимые статусы: `Новый`, `Подтверждён`, `В работе`, `Отправлен`, `Выполнен`,
`Отменён`. Можно присылать `"id": 57` вместо `"number"`.

* Клиент получает уведомление в кабинете и письмо — как при смене статуса
  менеджером.
* **`Отменён` возвращает товар на склад сайта**, а возврат заказа из отмены
  снова списывает (если товара хватает; иначе — ошибка по этому заказу).
* `onec_number` — номер документа в 1С (сохраняется и виден в выгрузке заказов).

Ответ: `{"status":"ok","updated":1,"unchanged":1,"errors":[]}`. Ошибки — по
каждому заказу отдельно, остальные применяются.

### `GET /orders/export` — заказы сайта (сайт → 1С)

```
GET /api/1c/orders/export?new=1         только не подтверждённые через ack (рекомендуется)
GET /api/1c/orders/export?after_id=57   заказы с id больше 57
GET /api/1c/orders/export?since=2026-10-01T00:00:00Z&status=Новый&limit=200
```

```json
{"count": 1, "has_more": false, "last_id": 57,
 "orders": [{
   "id": 57, "number": "САЙТ-57", "date": "2026-10-27T09:31:00", "status": "Новый",
   "comment": "Позвонить за час", "desired_date": "2026-10-30T00:00:00",
   "delivery_method": "delivery", "delivery_address": "Москва, ул. Цветочная, 1",
   "subtotal": 2125.0, "discount_percent": 0, "total": 2125.0,
   "counterparty": {"id": 8, "external_id": "000001234", "name": "ООО Ромашка",
                    "inn": "7701234567", "email": "shop@test.ru",
                    "address": "Москва, ул. Цветочная, 1", "phone": "+79001234567"},
   "items": [{"product_id": 15, "external_id": "00000012345", "sku": "ROSA-FREEDOM-60",
              "barcode": "4600000000001", "name": "Роза Freedom 60 см",
              "quantity_packs": 2, "package_size": 25, "stems": 50,
              "price_per_stem": 42.5, "sum": 2125.0}]
 }]}
```

`id` — номер заказа на сайте, `number` — его номер для документа 1С. `desired_date` —
дата, к которой клиент хочет получить цветы; `delivery_method` — `pickup` (самовывоз)
или `delivery` (доставка, адрес — в `delivery_address`); у этих полей может быть пустое
значение, если клиент их не указал. `counterparty` — клиент: `id` на сайте,
`external_id` (его id в 1С, пусто, пока 1С не сообщила через `clients/sync`), название, ИНН,
email, адрес, телефон. В строке заказа `product_id` — товар на сайте, `external_id` —
его id в 1С (пусто у товара, заведённого на сайте вручную).

**Время.** `date` — когда заказ оформлен, **время магазина (Москва) без смещения**: 1С
читает его как местное. Параметр `since` принимает `…Z`, `…+03:00` или время без пояса
(тогда это UTC).

Максимум 200 заказов за запрос; `has_more=true` — есть ещё, повторите запрос
(после `ack` они пропадут из `new=1`, либо передайте `after_id=<last_id>`).

### `POST /orders/ack` — «заказы получены»

```json
{"orders": [{"number": "САЙТ-57", "onec_number": "00000000123"}]}
```

или просто `{"numbers": ["САЙТ-57", "САЙТ-58"]}`. Повтор безопасен. Заказ,
которому прислали статус через `orders/status`, считается полученным сам.
Ответ: `{"status":"ok","acked":2,"errors":[]}`.

### `GET /products/export` — каталог сайта (сайт → 1С)

`/products/export` — то, что сейчас на полке; `?all=1` — весь справочник.
Формат записи совпадает с форматом `products/sync`, но `id` — это id **на сайте**, а
id из 1С лежит в `external_id`; кроме того есть `kind_id`, `color_id`, `height_id`,
`country_id` (id записей справочников) и `reserved_packs`, `available_packs`. Так
что выгрузку можно поправить и отправить обратно.

### `GET /dictionaries` — виды, цвета, рост, страны (сайт → 1С)

```json
{"kinds": [{"id": 1, "external_id": "", "name": "Роза"}],
 "colors": [{"id": 3, "external_id": "", "name": "Жёлтый", "hex": "#f4d03f"}],
 "heights": [{"id": 3, "external_id": "", "name": "60 см", "cm": 60}],
 "countries": [{"id": 1, "external_id": "", "name": "Эквадор"}]}
```

Только чтение: новые значения создаются сами, когда приходят в товарах; править список
может владелец на странице «Фильтры каталога» в админке.

### `POST /clients/sync` — контрагенты и скидки (1С → сайт)

```json
{"clients": [
  {"email": "shop@test.ru", "external_id": "000001234", "discount_percent": 5},
  {"inn": "7701234567", "discount_percent": 7.5}
]}
```

Клиент ищется по `email`; не нашёлся — по `external_id`; не нашёлся и так — по `inn`
(должен найтись ровно один). Меняются **только** `external_id` (id контрагента в 1С) и
скидка (0…100; можно не присылать, если присылается `external_id`). Администраторам
данные не меняются. Каждое изменение записывается в «Журнал действий» админки.

### `GET /clients/export?after_id=0&limit=500`

Клиенты сайта без сотрудников — контрагенты: `id, external_id, name, inn, email, address,
phone, discount_percent` (те же реквизиты, что в `counterparty` заказа). Постранично:
`count`, `has_more`, `last_id`.

## 5. Как сопоставляются товары

Порядок поиска товара на сайте для строки из 1С:

1. по `id` (идентификатор из 1С) — точное совпадение;
2. по `barcode` (штрихкод);
3. по `sku`;
4. по точному названию.

Шаги 2–4 применяются, только если найденный товар **не принадлежит другому
идентификатору 1С**: два разных товара 1С с одинаковым названием не
склеиваются. Товар, заведённый на сайте вручную (без id из 1С), при первой
выгрузке «усыновляется» по названию, и ему проставляется id.

Поэтому: **задавайте `id` всегда** (код или GUID номенклатуры) — тогда
переименование товара в 1С не создаст дубль.

## 6. Полный снимок остатков

Без `full` сайт только добавляет и обновляет то, что вы прислали. Товар,
удалённый или распроданный в 1С и **не присланный** в очередной раз, остался
бы на сайте со старым остатком. Для этого есть полный снимок:

```
POST /api/1c/products/sync?full=1       (или "full": true в теле)
```

Все позиции каталога 1С, которых **нет** в этой выгрузке, получают остаток 0 и
снимаются с полки. Правила безопасности:

* присылайте **весь** каталог **одним** запросом (до 20 000 товаров). Если
  делите на части, `full` не используйте — каждая часть «обнулила» бы остальные;
* пустой полный снимок отклоняется (`400`): он снял бы с продажи весь каталог;
* товар, чья строка в этой выгрузке оказалась «битой», **не** обнуляется.

### Сначала проверка без сохранения (`dry_run`)

Любую выгрузку каталога можно сначала отправить с `?dry_run=1`
(`POST /api/1c/products/sync?dry_run=1`, для полного снимка `?dry_run=1&full=1`).
Сайт выполнит все те же расчёты и вернёт обычный ответ с `"dry_run": true`, но
**ничего не запишет**: ни товары, ни цены, ни остатки. Так видно заранее:

* сколько товаров будет **создано** и сколько **обновлено** — если создаётся почти
  всё, а обновляется почти ничего, то `id`/`sku` из 1С не совпали с товарами на
  сайте, и настоящая загрузка завела бы дубли;
* сколько позиций снимет с полки полный снимок (`deactivated`);
* какие строки с ошибками (`errors`) и предупреждения.

То же есть у скидок (`POST /api/1c/clients/sync?dry_run=1`) и в админке: на странице
«Интеграция с 1С» у загрузки файла есть галочка «Только проверить». Правило для
первого запуска: проверка → смотрим цифры → настоящая загрузка.

## 7. Статусы: как сопоставить с документами 1С

Пример соответствия (подберите под ваши бизнес-процессы):

| В 1С | Статус на сайте |
|---|---|
| «Заказ клиента» создан, не проведён | `Новый` |
| Проведён, товар зарезервирован | `Подтверждён` |
| Идёт сборка | `В работе` |
| «Реализация товаров» проведена, отгружено | `Отправлен` |
| Оплачено и закрыто | `Выполнен` |
| Заказ закрыт без отгрузки | `Отменён` |

Отмена и возобновление отменённого заказа автоматически пересчитывают остаток
на сайте, но 1С остаётся главной по остаткам: при следующей выгрузке остатков
сайт получит верные цифры.

## 8. Переход на 1С: ручные поставки и дубли

До подключения 1С остатки на сайте ведутся вручную через «Поставки». Если после
подключения один и тот же товар одновременно лежит на полке и из ручной
партии, и из 1С, в каталоге он виден **дважды** (а цены могут отличаться).
Ответ `products/sync` сообщит об этом в `warnings`.

Порядок перехода:

1. В админке → «Поставки» → **«Снять с полок»** для всех ручных партий, которые
   на самом деле уже учтены в 1С. (Машины «в пути» для предзаказов оставьте —
   они на полки не попадают.)
2. Отправьте **полный снимок** из 1С.
3. Дальше остатки ведёт только 1С; поставки в админке нужны для предзаказов.

Разгрузка ручной поставки **не снимает** с полки остатки 1С (раньше снимала —
клиенты видели пустой каталог до следующей выгрузки), но и не заменяет их:
по одному и тому же товару выбирайте один источник.

## 10. Безопасность

* Только HTTPS. Если 1С не принимает сертификат Let's Encrypt, установите на
  сервере 1С корневой сертификат **ISRG Root X1** в «Доверенные корневые».
* Ключ — 160 бит случайности; на сайте хранится только его хэш, поэтому показать
  ключ повторно нельзя. Утёк или потерян — отключите в админке («Интеграция») и
  создайте новый: это занимает секунды и не требует доступа к серверу.
* Ключ можно привязать к IP-адресам сервера 1С (при создании) — с других адресов он
  не сработает (ответ `403`). Дополнительно можно ограничить доступ в nginx: в
  `nginx/site_https.conf`, в блоке `location /api/1c/`, раскомментируйте
  `allow <IP>; deny all;`, затем `bash scripts/update.sh`.
* Старый общий пароль (`INTEGRATION_PASSWORD` в `.env`) лучше убрать, когда обмен по
  ключу заработал: ключей может быть несколько (по одному на подрядчика), и каждый
  отключается отдельно.
* Каждое обращение 1С записывается в журнал обмена (админка → «Интеграция»; хранится
  60 дней). Неверные ключи с одного адреса схлопываются в одну строку со счётчиком;
  с одного IP не более 120 запросов в минуту.
* Смены скидок и статусов через обмен попадают в «Журнал действий»
  (`/admin/audit`, автор — «1С / система»).

## 11. Диагностика

| Симптом | Причина и что делать |
|---|---|
| `401` | неверный или отключённый ключ (в журнале админки — «неверный ключ или пароль»). Создайте новый ключ |
| `403` | ключ привязан к другим IP-адресам. Сообщите владельцу адрес, с которого работает 1С |
| `503` «не настроен» | в админке («Интеграция») нет ни одного ключа и не задан старый пароль |
| `422` «There was an error parsing the body» | тело — не JSON или не UTF-8 (например, Windows-1251). Отправляйте UTF-8 |
| `413` | больше 20 000 товаров за раз — разбейте выгрузку (без `full`) |
| `400` «Полный снимок без товаров» | выгрузка вернулась пустой — проверьте запрос к номенклатуре в 1С |
| `errors` в ответе sync | смотрите текст: «price_per_stem … не число», «вне диапазона» и т. д. |
| в каталоге товары дважды | раздел 8: ручные партии ещё на полке |
| сайт продал больше, чем есть | раздел 3: порядок «заказы → остатки», либо `ONEC_RESERVE_UNEXPORTED=1` |
| таймаут на больших выгрузках | у nginx для `/api/1c/` таймаут 5 минут; увеличьте таймаут в 1С |
| ошибка сертификата в 1С | раздел 10: корневой сертификат ISRG Root X1 |

Логи сервера: `docker compose logs -f app` (строки «1С sync: …»).

## 12. Чего обмен не делает (осознанно)

* не создаёт клиентов и не одобряет заявки;
* не передаёт сайту банковские платежи и накладные (только статусы);
* не управляет фото на сервере — присылает ссылки; загрузка файлов — через
  админку сайта.

## 13. Если из 1С нельзя ходить в интернет: файлы

Обмен по сети не обязателен. Запасной путь без программирования:

* **Каталог.** Выгрузите из 1С прайс-лист в Excel (`.xlsx`/`.xls`) или CSV (колонки вроде
  «Артикул, Штрихкод, Наименование, Вид, Цвет, Рост, Цена опт., Остаток, В пач., Страна») и загрузите в админке:
  «Интеграция» → «Загрузка из файла». Правила те же, что у обмена по сети: плохие строки
  пропускаются с понятным описанием, пустые ячейки не затирают прежние данные, цену
  можно выбрать из нескольких колонок («Цена опт.», «Мелкий опт»), остаток и цену можно
  считать «в штуках» или «в упаковках». Кнопка «Загрузить как полный каталог» снимает с
  полки всё, чего в файле нет.
* **Заказы.** Там же: «Заказы для 1С вручную» — скачать CSV (одна строка = одна позиция),
  загрузить в 1С, затем нажать «Я загрузил их в 1С», чтобы заказы не выгружались повторно.
* Загрузка файла попадает в тот же журнал обмена («файл из админки»).
