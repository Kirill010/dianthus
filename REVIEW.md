# Ревью проекта «Диантус»

## Общая оценка

**Крепкий проект для своей задачи — заметно выше уровня «домашнего».** Чёткая
структура (роутеры / сервисы / модели), конфигурация через `.env`, серьёзная
безопасность «из коробки» (CSRF, CSP, bcrypt, лимиты, блокировки), атомарное
оформление заказа, обмен с 1С, авто-миграции, тесты.

Но «работает у автора» и «ставится с нуля и работает у всех» — разные вещи. Третий
проход (раздел «Раунд 3» ниже) шёл именно оттуда: запуск на **пустой** базе, запуск на **старой**
базе, тесты на каждую подозрительную ветку, реальный браузер, реальные
HTTP-запросы к обмену. Он нашёл ошибки, которые чтение кода пропускало.

Четвёртый раунд (первый раздел ниже) добавил то, чего проекту не хватало для живой работы: юридический
блок, ключи доступа для 1С, роли сотрудников, «что сделать сегодня», рекламации, «забыли пароль» — и
нашёл ещё 16 ошибок, в том числе такие, которые проявились бы только на боевой PostgreSQL.

Как проверялось в этом проходе:
* автотесты: **40 → 128 → 314 → 364 → 445** (после шестого раунда); все проходят и на локальном окружении, и на наборе
  версий из `requirements.txt`, поставленном «с чистого листа»;
* `pip-audit`: старые версии — **82 известные уязвимости в 6 пакетах**
  (Pillow 10.4 — 44, Starlette 0.38 — 14, python-multipart 0.0.12 — 14, Jinja2 3.1.4 — 6,
  xhtml2pdf 0.2.16, python-dotenv 1.0.1); новые — «No known vulnerabilities found»;
* запуск приложения на пустой базе и на базе, созданной **исходным коммитом**
  (обновление боевой базы: колонки добавились, данные целы, вход/каталог/админка/заказ работают);
* браузер: подтверждения, кнопки «+/−», время, страница 404, возврат остатка, новые страницы;
* обмен с 1С — реальные HTTP-запросы к запущенному серверу.

**Не проверялось** (в среде ревью нет Docker): сборка образа, совместная работа
контейнеров, nginx «вживую», выпуск сертификата, ваша 1С.

## Раунд 6: справочники-фильтры, формат обмена по образцам владельца, откат неудачного обновления

Задача владельца: у каждой сущности есть `id`; **контрагент** — название, ИНН, id, email, адрес, телефон; **товар** — наименование, артикул, штрихкод, id;
**заказ** — дата, номер, id на сайте; у цветов три направления — **вид**, **цвет**, **рост**; все фильтры — **отдельные таблицы**. Образцы форматов
(товар, заказ, контрагенты) владелец прислал сам — они стали главными.

**Что пошло не так по дороге (урок).** Привычка `git add . && git commit && git push` плюс обновление сервера унесла на боевой сайт недоделанную работу:
весь `/api/1c/*` отвечал 404 (роутер не импортировался), ночная задача падала, а миграций для новых колонок ещё не было. Сайт откатили на последнюю рабочую версию
(коммит-откат, копия базы, обновление), а дальше работа шла в **отдельной рабочей копии** (ветка), чтобы папка владельца с `main` всегда была готова к выкладке.

| Что | Как устроено |
|---|---|
| Справочники | четыре таблицы `kinds`, `colors` (+цвет кружка), `heights` (см), `countries`: у каждой записи `id`, `external_id` (id в 1С) и порядок показа; товар хранит ссылки. Значения создаются сами и **без дублей** (регистр, «ё», пробелы), владелец правит их на странице «Фильтры каталога» (`/admin/filters`) |
| Перенос старых данных | один раз (отметка `taxonomy_v1`): текстовые `country / category / length_cm` → справочники («Роза Эквадор» → вид «Роза» + страна «Эквадор»); повтор безопасен, ручные правки не затираются |
| Формат обмена | три образца владельца вставлены в тесты **дословно**; ответ заказов сравнивается с образцом целиком. Заказ: `counterparty{id, external_id, name, inn, email, address, phone}`, дата — время магазина без смещения; товар: `barcode`, `kind`, `color`, `height`, `country`, `unit`; контрагенты: поиск email → id 1С → ИНН; `GET /api/1c/dictionaries`; фото и по штрихкоду |
| Каталог | панель «Вид · Цвет · Рост · Страна»: несколько значений, число товаров у каждого, «Сбросить фильтры», кружок цвета; на телефоне сворачивается; поиск по артикулу и штрихкоду; прайс-лист — группы по видам |
| Админка | страница «Фильтры каталога», форма товара с выпадающими списками, артикул и штрихкод, адрес клиента (регистрация, профиль, карточка, выгрузка, удаление данных) |
| Убрано лишнее | прежняя «совместимая прослойка» (`Product.country/category/length_cm`, `PRODUCT_CATEGORIES`, `buyer`, `created_at_local`) |

* реальные HTTP-запросы к запущенному сайту: каталог, повторная отправка, выгрузка, заказ, справочники, контрагенты, ошибка строки;
* браузер, компьютер и телефон 375 px: панель фильтров (несколько значений, сброс), прайс-лист по видам, страница «Фильтры каталога» (добавить), форма товара;
* `pip-audit` — «No known vulnerabilities found».

**Не проверялось:** сама 1С (ни обмен, ни комплект `docs/1c_kit`), настоящий телефон.

## Раунд 5: сравнение с конкурентами, прайс-лист, обход всех страниц

Посмотрели двух конкурентов и взяли идеи (код и тексты не копировались, всё написано заново): у «Golden Flowers / Oasis Flowers» — мобильный

и установкой на экран телефона. Сделано своё:

| Что | Как устроено |
|---|---|
| Вид **«Прайс»** | `/catalog?view=list`: строка на товар (фото, название, страна и длина, остаток, цена, «−/+» и корзина), группы по категориям, 50 строк на страницу; выбор запоминается в cookie `catalog_view` (в ней только слово `cards` или `list`) |

## Раунд 4: «до совершенства» — удобство, юридическая часть, ключи для 1С

Задача раунда: сделать сайт удобным клиентам и сотрудникам, закрыть юридическую сторону (152-ФЗ, реклама),
дать владельцу ключ для программиста 1С и найти оставшиеся ошибки. Автотестов стало **314** (в прошлом раунде было 128);
все проходят. Главное изменение в тестах: SQLite теперь запускается с **включёнными внешними ключами**, как
PostgreSQL в проде, — раньше удаление записей «работало» в тестах и падало бы на боевой базе.

### Найденные и исправленные ошибки

| # | Проблема | Чем грозила | Исправление |
|---|---|---|---|
| 1 | Ссылки из блока «Товары в пути» вели на **404** (карточка открывалась только для товаров «на полке») | клиент не мог открыть товар из предзаказа | карточка товара «в пути» с формой предзаказа; для неподходящих позиций — по-прежнему 404 |
| 2 | Количество предзаказа не ограничено | переполнение `INTEGER` на PostgreSQL → ошибка 500, абсурдные резервы и значки | потолок 2000 упаковок (на сервере и в форме), в сумме тоже |
| 3 | Корзина удаляла позицию по **номеру в списке** | в двух вкладках удалялась не та позиция | удаление по ключу «товар:из предзаказа»; номер оставлен только для старых форм |
| 4 | Количество в корзине нельзя было изменить | лишние клики: удалить и добавить заново | +/− и ввод числа в строке, автообновление, проверка остатка и минимального заказа |
| 5 | Ссылки «Все»/«сбросить поиск» в каталоге без URL-кодирования | поиск «Роза & Пион» ломал ссылку | `\|urlencode` |
| 6 | Пустая выдача при поиске писала «товаров в наличии нет» | клиент думал, что склад пуст | разные сообщения для «ничего не найдено» и «нет в наличии» |
| 7 | Удаление клиента на PostgreSQL упало бы на внешних ключах (журнал, рекламации, предзаказы, согласия, запросы) | «Не удалось удалить пользователя», зависшие заявки | `purge_user_refs`; клиента с заказами **обезличивают**, а не удаляют, чтобы не терять учёт |
| 8 | Скрипты очистки (`scripts/clear_*.py`) не знали про предзаказы/рекламации | падали бы на PostgreSQL | общие помощники в `cleanup_utils.py` |
| 9 | «Повторить заказ» брал «любую» партию товара | мог взять старую партию с другой ценой | берётся самая свежая |
| 10 | Год «2026» в подвале зашит | через два месяца неверный год | текущий год |
| 11 | Выгрузка «Клиенты» — только с заказами, без согласий | нельзя отобрать тех, кому можно звонить с рекламой | все клиенты + «Согласие на рекламу», последний вход, ИНН, город |
| 12 | Не было «Забыли пароль» | каждый сброс — звонок и ручная работа | ссылка на почту (одноразовая, 60 минут, не раскрывает, есть ли адрес) + временный пароль в карточке клиента |
| 13 | Все сотрудники имели полный доступ | менеджер видел выручку, ключи, мог менять цены | роль «менеджер» |
| 14 | Счёт PDF без ИНН/ОГРН, условий оплаты, даты и адреса | неполный документ | добавлены; строка про НДС — из `SHOP_VAT_NOTE` |
| 15 | `scripts/onec_smoke_test.py` падал на консоли Windows (значки) | программист не видел результата | вывод в UTF-8 без падения |
| 16 | Фото рекламаций с телефона > 5 МБ молча отбрасывались; nginx резал 30 МБ | клиент думал, что фото ушли | лимит 15 МБ на фото, понятное сообщение, nginx 128 МБ для `/claims` |

### Новое

* **Юридический блок:** политика, отдельное согласие, отдельное рекламное согласие, условия работы — в БД, правятся в
  админке, версионируются; журнал согласий; выгрузка данных клиента; запросы на удаление с обезличиванием;
  страница «Юридическое» со списком дел; образцы документов в `docs/legal/`.
* **1С:** ключи доступа (хэш в базе, показ один раз, IP-ограничение), страница «Интеграция» (плашка состояния,
  журнал обращений, готовое сообщение программисту), CSV-вариант обмена для старых версий 1С, загрузка прайс-листа
  из Excel/CSV и ручная выгрузка заказов, памятка программисту (`/1c-docs`).
* **Клиентам:** «Сроки заказа», дата получения и способ получения в заказе, этапы заказа, рекламации с фото.
* **Сотрудникам:** «Что сделать сегодня», роль менеджера, карточка клиента, листы сборки, заметки, история статусов.

### Что НЕ проверено

* Тексты политики/согласий/условий — **черновики**; юридическую силу даст только проверка юристом.
* Образцы документов и ответы для Роскомнадзора составлены по открытым источникам (октябрь 2026); форма портала
  может отличаться.
* Реальная 1С: примеры на встроенном языке и варианты для старых версий не запускались на вашей конфигурации.
* Docker/nginx «вживую», выпуск сертификата, отправка писем через ваш SMTP.
* Кириллица в PDF на машине без шрифта DejaVu (в Docker-образе шрифт ставится сам).

### Дополнение от 27.10.2026: подключение 1С без программиста

Выяснилось, что 1С владельца стоит во внутренней сети (сервер `192.168.201.2`, база «Цветы», обычные формы, меню
«Инвойсы»), то есть сайт сам к ней не подключится, а программиста нет. Что сделано:

* **«Проверка без сохранения» (`dry_run`).** Любую загрузку каталога (`POST /api/1c/products/sync?dry_run=1`,
  в том числе «полный снимок»), скидок (`clients/sync?dry_run=1`) и файла в админке (галочка «Только проверить»)
  можно сначала прогнать вхолостую: ответ тот же (создано / обновлено / снято с полки / ошибки), но транзакция
  откатывается и в базе ничего не меняется. Так видно заранее, не создаст ли загрузка дубли. Тесты: `tests/test_dry_run.py` (6).
* **Инвойсы поставщиков → «товары в пути»** (`POST /api/1c/supplies/sync`, `app/services/supply_sync.py`). По экранам владельца
  «Инвойс срезка эквадор» — приход от поставщика с валютой и курсом. 1С присылает инвойсы за последние недели с текущим статусом
  (`in_transit` / `received` / `cancelled`); сайт создаёт или обновляет «поставку» по идентификатору инвойса (повтор ничего не
  дублирует), клиенты видят «Товары в пути» и делают предзаказ. Когда инвойс оприходован (`received`), поставка закрывается, а
  предзаказам резервируется товар **с полки** (остатки ведёт 1С) с уведомлением и письмом. Поставка из 1С не разгружается ни
  автоматически, ни вручную (иначе товар был бы виден дважды); забытая 21 день закрывается сама. Новые колонки
  `supplies.external_id`, `supplies.external_synced_at` добавляются авто-миграцией. Раньше предзаказы при остатках из 1С не
  выполнялись вообще (разгружались только ручные поставки): это был пробел.
* **Подсказки по названию** (`app/services/product_guess.py`): «Роза Кения 40с» → страна Кения, длина 40 см, категория «Роза»; у новых
  товаров и только в пустые поля (то, что прислала 1С или поправил менеджер, не трогается). Тесты: `tests/test_supply_sync.py` (38).
* **Пробный файл** (`docs/1c_kit/Proverka.bsl`, ~270 строк, 10 минут, только чтение): создаётся ли файл, запускается ли он при открытии, виден ли
  сайт из 1С (средствами 1С и через Windows), как в базе называются нужные справочники, регистры, инвойсы и где искать скидки. Нужен, чтобы
  первый шаг был дешёвым и безопасным и чтобы сверить имена объектов **до** большого файла.
* **Файл для 1С** (`docs/1c_kit/ObmenSSaitom.bsl`, внешняя обработка для «Управление торговлей 10.2»): меню в самой 1С — связь,
  каталог (показать / проверка / отправка), инвойсы «в пути» (так же), новые заказы с сайта (показать / подтвердить),
  описание базы (названия справочников и полей, поиск «скидки»). 1С читается только запросами, ничего не создаётся. Защиты:
  «проверка без сохранения» перед отправкой, подтверждение «Да», стоп, если товаров внезапно вдвое меньше. Написан без возможностей
  новых версий платформы (JSON, `СтрСоединить` и т. п.), потому что режим совместимости базы неизвестен; запрос на сайт идёт
  средствами 1С, при сбое — через Windows (`WinHttp`), JSON передаётся в чистом ASCII.
  Пошаговая инструкция: `docs/1C_ПОШАГОВО.md`.
* **Не проверено:** ни одной строки встроенного языка 1С в живой 1С запустить было нельзя (платформы нет на машине разработки).
  Файл проверен двумя скриптами: парность блоков/скобок/кавычек и поиск необъявленных имён, неверного числа аргументов и неверных
  `Возврат`. Имена методов платформы и **стандартные имена объектов УТ 10.2** (`ЦеныНоменклатуры`, `ТоварыНаСкладах` и т. д.)
  взяты по памяти; если в базе они иные, меню само скажет, что нашло (и перечислит найденные поля). Первый запуск у владельца
  и есть настоящая проверка. Скидки клиентов и создание документов в 1С намеренно не сделаны: нужны экраны базы и тест на копии.

## Что осталось на будущее (по убыванию пользы)

1. **Предзаказы: очерёдность.** При разгрузке поставки все клиенты с предзаказом
   на товар получают «Предзаказ поступил», даже если упаковок хватает не всем;
   достаётся тому, кто первым нажал «в корзину». Честнее — распределять остаток
   по порядку создания предзаказов (потребует поле «выделено упаковок»).
2. **Alembic вместо самописной авто-миграции** — нужен для переименований и смены
   типов (например, перевод денег из `Float` в `Numeric`). Сейчас авто-миграция
   только добавляет колонки/индексы — для текущих задач достаточно.
3. **Очередь для писем** (RQ/Celery поверх Redis). Сейчас письма уходят из
   процесса приложения; при росте нагрузки — вынести.
4. **Атомарная корзина.** Два одновременных клика «в корзину» одного пользователя
   могут перезаписать друг друга в сессии (последняя запись побеждает).
5. **Серверный поиск в админке** для вкладок «Клиенты» и «Справочник» при более
   чем 500 строках (сейчас живой поиск работает по показанным).
6. **«Выйти на всех устройствах»** (сейчас смена пароля обновляет только текущую сессию).
7. **Контрольная сумма ИНН** в валидации регистрации.
8. **Внешний мониторинг доступности и алерты** (Sentry подключается через `SENTRY_DSN`).
9. **Онлайн-оплата** (эквайринг) — сейчас счёт и оплата по реквизитам.
10. **Поиск по артикулу** в каталоге и «быстрый заказ списком» для постоянных клиентов.
11. **Сбор согласий у уже зарегистрированных** — сейчас плашка-напоминание в кабинете; при желании можно
    запретить оформление заказа до подтверждения.
12. **Прайс-лист в Excel** для скачивания одобренными клиентами (у конкурентов есть) — не делали, чтобы не плодить лишнее;
    добавляется за полдня, если клиенты попросят.
